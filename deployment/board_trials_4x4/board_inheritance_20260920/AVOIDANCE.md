# 当前避障逻辑与障碍前停滞

## 正常链路

MID360 driver2 → FAST-LIO定位和配准点云 → FreeDOM静态障碍筛选 → Fast-Planner占据/距离场 → 动力学A* → B样条优化与碰撞检查 → traj_server → 控制器 → 数值转换到MAVROS map设定点。

任务层给出目标点，不预先硬编码从树左侧还是右侧绕行。局部规划器在地图、动力学和边界约束内找路。水平避障柱用于避免靠升高飞过树；它与实际三维点占据共同生效。看到一条直连航点线不代表飞机会沿这条线穿过障碍。

轨迹变得不安全时先停止旧轨迹推进，尝试重规划；成功后才发新Bspline恢复。显示同一个pos_cmd可能是在保持，也可能没有新轨迹，不能仅凭这一现象断言traj_server算法故障。

## 三套当前实际参数

- 巡航速度上限0.5m/s，加速度0.35m/s²；它们不是飞控一定能达到的实测速率。
- 水平占据膨胀0.30m，向上0.10m、向下0.30m；规划栅格0.10m；最小额外净空0.025m。
- 高位额外tracking_margin=0.10m，低位重访恢复0；三套地图范围10×6×3.8m，局部更新范围4.5/3/3m。最终值由generated overrides覆盖公共旧配置，不应只看horizontal_planner.yaml中的旧整场尺寸。
- 目标附近调整通常半径0.15m；失败规划间隔至少0.75s，搜索预算0.25s。搜索预算是一次A*尝试的预算，不是整个任务超时。
- 本次板端运动动作期限30s，目标事务60s，总任务300s。SEARCH/RESUME另有12s首次轨迹保护；这不是所有阶段的统一恢复机制。历史seed31走廊90s是整场配置，不能照搬成三套的期限。

## 为什么障碍前会停

1. **几何无解**：机体中心或终点处在膨胀障碍内；目标附近15cm没有可用替代点；通道或合法高度层太窄。80cm通道减去两侧30cm只剩20cm中心通道，再加栅格取整、额外净空与点云噪声，可能变成无路。不能再额外重复扣一次机体宽度来解释同一膨胀。
2. **地图造成的假阻塞**：点云噪声、定位漂移或遮挡下的清除不足，可能保留障碍残影。是否发生须看本轮点云/距离场，当前不能定案。FAST-LIO的/Laser_map显示补丁不自动修复FreeDOM规划地图。
3. **动力学/搜索预算失败**：几何上看似有路，不代表在当前速度、加速度、起点速度和单次搜索预算内一定找到可验证轨迹。提速不会修复此类问题；0.5m/s按0.35m/s²理想制动距离约0.36m，尚未计入通信、规划和控制延迟。
4. **有轨迹但没有实际进展**：旧曲线保持、跟踪位置异常、控制器模式不匹配或输入不新鲜等，要分别查看。已有物理进展监控依赖goal_has_trajectory以及新鲜地图/位姿和有效控制模式；没有生成第一条曲线时不会按相同口径累计跟踪停滞。
5. **反复求同一个无解问题**：失败后保留目标并重试。如果没有地图变化或合法替代目标，每次重试仍可能失败。缩短超时只会提前终止，不等于恢复成功。

## 现场区分顺序（只读观察）

先确认`/planning/goal_status`对应的当前目标：是否反复PLANNING/FAILED_ATTEMPT、有没有TRAJECTORY_READY；再看`/planning/bspline`是否有该目标的新曲线。然后比较`/planning/pos_cmd`、`/navigation/local_odom`和任务状态，区分保持、执行、到达与无解。核对`camera_init↔map`及输入时间戳，最后看起点/终点周围膨胀占据、净空及高度层。

首次失败最有用的数据是：请求/有效目标、当前位置与速度、失败原因、当前高度/边界参数、局部占据或距离场。没有这些信息，不宜反复改速度、缩膨胀或直接关闭约束。下一步应针对首轨迹无解补齐诊断及有限恢复，而不是无限尝试或盲目向障碍前进；此次部署未新增该恢复算法。
