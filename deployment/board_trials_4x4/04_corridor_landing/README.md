# 走廊导航点＋自主避障＋H降落专项

本入口沿用4×4总场地和固定起飞坐标系：机头初始向前为+X、左侧为+Y。先按测量航点顺序飞行，航点间由实时雷达地图与Fast-Planner自主避障；到H附近后定点升高识别、视觉对齐、自动降落。没有目标投递或模拟舵机服务。

**现场几何未知，默认不能运行任务。** `settings.yaml`中`corridor_waypoints: []`及`landing_xy: null`均刻意留空，没有隐藏默认走廊路线。入口在创建ROS节点、启动定位/控制之前检查这些字段；空配置会报错退出，preview也不会绕过检查。

## 待现场填写

- `corridor_waypoints`：至少两个按飞行顺序排列的对象，每个填写`x`、`y`，可选`agl`（飞控中心离地高度；省略沿用1.4m）。不要把障碍内部的位置当作必须到达的点；门前、门后是否各需一点，要按实际净空测量决定。
- `landing_xy`：实测H中心的两个坐标。没有默认“前方2米”，也不会自动把最后一个走廊航点当成H。
- 可用中心范围继承当前配置：X∈[0.35,3.4]、Y∈[−1.4,1.4]；走廊点AGL允许0.5–1.8m。超出范围会拒绝配置。此范围不同于整个4×4边界，保留已有机体余量。

填写完成后，生成链将按顺序保留每一个走廊点，再追加用户给定H中心处的低位接近点和同XY升高观测点。每一点仍需任务/规划到达判定，不会把目标修正当作任意跳过航点。没有真实门洞地图或实测净空时，本配置不能证明能过某扇门。

## 继承配置

巡航上限0.5m/s、加速度0.35m/s²；默认走廊航高1.4m，H接近1.4m、捕获1.8m。这里是专项默认值，**不是正式赛道限高验收配置**；布设走廊前须核对门洞与升高点空间。虚拟顶棚已按现场要求关闭（−0.1），控制指令上限仍为地面+2.9m，保留水平障碍柱和现有膨胀。

相机/IMU已知外参、实测map↔camera_init数值转换、未解锁静置自动地面基准、RKNN视觉链、原始/标注相机录像全部复用公共入口。地面MAVROS Z≈0无需手填ground_z。投递链关闭，只检验导航/避障及H视觉降落；H识别失败不伪报成功。

## 使用

从独立工程根目录执行；下列命令在空配置时会明确拒绝：

```bash
bash deployment/board_trials_4x4/04_corridor_landing/start.sh preview --check-config
bash deployment/board_trials_4x4/04_corridor_landing/start.sh preview
# 退出preview后，现场按原流程选择flight：
bash deployment/board_trials_4x4/04_corridor_landing/start.sh flight
```

`--check-config`仅校验已填写配置，不创建ROS节点、不启动飞行。flight不会自动解锁或调用任务启动服务；设备准备与人工起飞/启动步骤见[总说明](../README.md)。日志目录前缀为`logs/board_corridor_landing_*`，包含相机原图/视觉标注视频和结果。只有任务完成且确认落地的运行才记为PASS。
