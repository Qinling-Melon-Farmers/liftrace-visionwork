# 实装相机与安装外参测量标准

更新时间：2026-09-04

本文冻结当前飞机下视相机的已知运行口径，并回答安装外参“从哪里量到哪里”。内参文件按
用户要求直接采用，不在本文复核棋盘格或重投影正确性。

## 1. 当前实装相机的已确认信息

| 项目 | 当前口径 | 证据边界 |
| --- | --- | --- |
| 模组 | KS2A543，AR0234 全局快门彩色模组 | 板端盘点记录；USB 描述本身不能唯一证明镜头型号 |
| USB 设备 | Sonix Technology，Microdia `0c45:636b` | OrangePi 实测 |
| 稳定设备路径 | `/dev/v4l/by-id/usb-Sonix_Technology_Co.__Ltd._USB_2.0_Camera_SN0001-video-index0` | OrangePi 实测 |
| V4L2 输入 | `MJPG 1280x720 @ 30 FPS` | 正式 600 s 运行实际协商值；不用模组宣传的最高帧率代替 |
| ROS 图像 | `/camera/image_raw`，`1280x720 bgr8` | 板端正式入口 |
| CameraInfo | `/camera/camera_info` | 板端正式入口 |
| optical frame | `downward_camera_optical_frame` | Image 与 CameraInfo 已验证一致 |
| 板端吞吐 | raw `29.164 Hz`；RKNN `13.705 Hz` | 无人触碰 600 s 复跑 |
| 板端时延 | inference P95 `63.894 ms`；processing P95 `73.478 ms` | 同一 600 s 复跑 |

厂家同型号页面给出的通用信息是 38 mm × 38 mm 模组、AR0234 全局快门、默认 3.6 mm/
约 100° 镜头且可换 40°～170° 镜头。它只能说明产品族能力，不能覆盖本机实际镜头、裁剪和
USB 带宽。当前项目应以实测 `1280x720@30` 和标定参数为准。厂家页面：
<https://www.camera-module.com/product/globalshuttercameramodule/2mp-global-shutter-camera-module-color-images.html>。

当前接受的内参位于
`vision_ws/src/camera_sdk/param/calibration_1280x720.yaml`：

```text
fx = 725.3510059644 px    fy = 723.3403562845 px
cx = 631.6718631370 px    cy = 397.5663813312 px
D  = [0.0058668601, 0.0179105495, -0.0010064116,
      0.0014715594, -0.0264851009]
标定推导水平视场约 82.85°
```

仓库和现有实验资料中没有当前机架的可核验六自由度安装尺寸，也没有能确定镜头朝向、线缆
方向和机体基准点的实装照片。2025 代码中的 `[0, 0, -0.15] m` 只是一代旧机架的候选值，
而且其多个历史四元数彼此冲突，禁止直接写入当前实机配置。

## 2. 唯一应交付的静态外参

当前定位链由 FAST-LIO 发布：

```text
camera_init -> body
```

其中 `camera_init` 是启动后建立的世界/任务坐标，不是可用卡尺测量的机身固定基准；`body`
是 FAST-LIO 状态使用的 IMU body frame，里程计源码也明确把它作为 child frame。因此实装应
测量并只发布：

```text
body -> downward_camera_optical_frame
```

测量端点定义如下：

- 起点：飞控中被 `/mavros/imu/data` 和 FAST-LIO 当作 `body` 原点的 IMU 感测中心。不能用
  桨盘中心、机架几何中心、OrangePi 外壳、起落架或 MID360 外壳中心代替。
- 终点：相机针孔模型的投影中心。机械测量无法接触该点时，以镜头光轴中心及镜头座参考面
  建立相机 link，再用相机 link 到 optical frame 的固定旋转组合；不要量到 USB 插座或 PCB
  边缘后直接称为 optical center。
- 表达坐标：平移向量必须用 `body` 轴表达，单位米；旋转四元数按 ROS `xyzw` 顺序。
- 轴约定：项目应核对 `body` 是否已按 ROS 右手系 `+X` 前、`+Y` 左、`+Z` 上；相机 optical
  frame 按 `+X` 图像右、`+Y` 图像下、`+Z` 光轴前。名义下视安装中 optical `+Z` 指向地面。

ROS REP-103 给出了上述 body/optical 轴约定，REP-105 说明 `base_link`/机体固定 frame 可选在
平台上的明确固定参考点；本工程进一步收紧为定位器实际使用的 IMU `body` 原点，避免测量值与
状态估计平移一个未知杠杆臂。

## 3. 现场测量步骤

1. 固定最终相机支架、镜头、USB 线和应力释放；冻结 `1280x720`、不旋转像素、同一焦距/
   对焦。支架或镜头重装后外参作废。
2. 断桨并让机架水平放置，只做静态测量。根据飞控 PCB/手册找到实际 IMU 感测中心；若无法
   直接触达，建立三个互相垂直且可复现的机架基准面，分别量出“基准面到 IMU”和“基准面到
   镜头投影中心”，再作差。
3. 测 `body` 原点到相机投影中心的 `x/y/z` 杠杆臂。每个方向至少独立装夹/读数三次，记录
   原始读数，不把机架 CAD 名义尺寸冒充装配后实测值。
4. 测相机光轴相对 body 的 roll/pitch/yaw。先用水平仪/方尺测镜头座法向，再在实时图像中让
   标记分别沿机头前方和机体左方移动，确认图像 `+X/+Y` 与机体轴的实际对应，消除 90°/
   180° 安装歧义。
5. 将机械测得的 camera link 姿态与标准 link-to-optical 旋转相乘，导出
   `translation_xyz_m` 和 `quaternion_xyzw`；不要同时发布两条相同 child frame 的 TF。
6. 静态发布 `body -> downward_camera_optical_frame`，由现有动态
   `camera_init -> body` 自动组成完整投影链。Image、CameraInfo 和 TF 必须使用同一图像源
   时间戳进行查询。

若飞控板没有可确认的 IMU 原点标记，先向飞控/结构负责人冻结一个可测机架 datum，并测出
`datum -> IMU body`；不能把 datum 直接重命名为 `body`。更高精度时可在机械初值之后做相机—
IMU hand-eye 优化，但不应再增加第二套运行时外参选择逻辑。

## 4. 建议验收口径

以下是本项目工程目标，不是竞赛规则原文：

- 三次拆装/复测的平移极差不大于 5 mm；roll/pitch 极差不大于 0.5°，yaw 极差不大于 1°。
- 在 3 m 高度，0.5° 姿态误差约产生 2.6 cm 横向误差，1° 约产生 5.2 cm，因此角度不能只凭
  “看起来朝下”填写。
- 用地面固定点在 1.2/2.4/3.6 m 三高度验证，不改变已接受内参；目标地图误差 P95 建议
  `<=0.10 m`，现有 V-SIM 硬上限 `0.25 m` 只能作为兜底。
- 检查视场不被起落架、桨保护、投递盒和 USB 线遮挡；USB 线必须有应力释放。此前人工碰线
  已真实造成过一次 UVC 断连。
- 外参未验收时继续保持 `map_valid=false/tf_unavailable`，不得为了联调伪造当前实机 TF。

## 5. 仿真与实机仍不等价的部分

V-SIM-04 已可使用单彩色 KS2A543 几何夹具，分辨率、帧率上限、标定视场、D、话题和 frame
与实机口径对齐。Gazebo Classic 相机插件只有一个 `focalLength`，所以仿真 CameraInfo 使用
`fx=fy=725.351 px`；实机标定的 `fy=723.340 px` 与之相差约 0.28%。为了这点差异另加一条
CameraInfo relay 会增加不必要接口，故仿真报告必须明示该近似，实机仍发布原 YAML 的完整 K。
Gazebo 的瞬时帧与全局快门方向一致，但它不模拟真实 MJPG USB 解码、自动曝光、镜头眩光、
振动、运动模糊、线缆断连和 OrangePi/NPU 调度；板端 600 s 数据仍是实机性能的权威来源，
Gazebo 数据用于几何/业务回归。
