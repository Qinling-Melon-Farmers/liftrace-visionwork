# OrangePi 5 Plus 板端视觉性能报告（2026-09-02）

## 1. 结论摘要

本轮已经在 OrangePi 5 Plus 上跑通新相机、标定参数、ROS Noetic、统一六分类 FP32 RKNN、
视频回放、实时 USB 相机和板载 GUI 显示。当前可确认的是：

- USB 相机能够稳定协商 `MJPG 1280×720@30`，ROS 原始图像和 `CameraInfo` 使用同一
  `downward_camera_optical_frame`，新内参已实际发布。
- `merged_standard_fp32.rknn` 在板端 NPU 上可用，不再存在“模型路径没传入却持续发布
  空检测”的伪健康模式；正式入口的模型缺失策略为 fail-fast。
- 同一冻结 revision 的无人触碰 600 秒复跑已经 PASS：实时相机发布 `29.164 Hz`，RKNN
  完整处理 `13.705 Hz`，处理 P95 `73.478 ms`；新增 USB/UVC 内核日志、节点退出、禁用
  飞控/控制节点和 probe error 均为 0。
- 新内参去畸变会增加约 `7.6 ms` 的板载查看器单帧总耗时；已生成并拉回两段严格
  20 秒、600 帧的无去畸变/去畸变对照视频。
- 首次 600 秒运行不能记为“无扰动稳定性 PASS”：用户确认运行中碰过相机线，内核同时
  记录一次 `USB disconnect`。该次结果证明了自动恢复能力，但清洁稳定性 Gate 必须以
  无人触碰的 `rerun1` 为准；rerun1 已用同一 revision 排除该外力干扰并通过。
- rerun1 后 213 秒资源旁路显示，统一模型的 NPU devfreq 持续报告 `100%@1 GHz`，视觉
  10 个节点合计约占 `3.66` 个逻辑核；当前不能再叠加第二套全图 RKNN，导航/LIO 并发余量
  仍须在整机仿真中复测。

本报告只评价链路、时延、吞吐、资源和失效行为。实拍视频没有人工实例/类别/中心真值，
现场相机朝向顶棚，且尚未安装相机到机体/地图的有效外参。因此下文的检测数量不是精度、
召回率或中心误差；顶棚上的框不代表识别正确；`map_valid=0` 是无外参时正确的安全退化，
不代表地图定位通过。

## 2. 测试边界与安全约束

本轮启用范围：

- OrangePi、USB/V4L2、相机采集、`CameraInfo`；
- RKNN/NPU 粗检测及现有视觉 ROS 链；
- 本地视频回放、板载显示、性能和系统资源采样；
- 无外参条件下的地图输出 fail-closed 行为。

本轮明确未启用：

- PX4、MAVROS、解锁、起飞、遥控接管；
- `patrol_control`、舵机、PWM、真实投递机构；
- FAST-LIO、实机导航和整机运动；
- 相机安装外参及真实地图坐标验收。

600 秒探针列出的节点只有相机和视觉节点，`forbidden_nodes=[]`。这只能证明本轮测试没有
误启动飞行/执行机构节点，不能替代后续整机联调。

## 5. “订阅 JPEG”是什么，为什么需要或不需要

这里有两层容易混淆的压缩：

1. 相机到 OrangePi 的 USB 传输协商为 `MJPG`。这是相机硬件/驱动侧的传输格式，OpenCV
   读取后得到普通 BGR 图像。
2. ROS 相机节点发布 `/camera/image_raw` 后，还可以把 BGR 图再次编码成 JPEG，发布为
   `/camera/image_raw/compressed`。所谓“订阅 JPEG”，特指有 ROS 节点订阅第二个
   `CompressedImage` 话题，不是订阅传感器 RAW，也不是要求 YOLO 读取 JPEG 文件。

统一 RKNN 检测器直接消费 `/camera/image_raw`，正式机载推理本身不需要订阅 JPEG。
JPEG 压缩话题主要适合：

- 通过网络远程看图，降低 ROS 网络带宽；
- `rqt_image_view`/网页监看明确选择 compressed transport；
- 需要压缩图的轻量记录器或调试工具。

JPEG 编码需要 CPU。如果无人订阅却每帧照常编码，会白白消耗板端计算资源并与图像预处理、
RKNN 调度争用。当前实现通过 `compressed_pub.get_num_connections()` 按需编码：有人订阅
才生成 JPEG，无订阅时只发布原始图和 `CameraInfo`。

### 5.1 30 秒 JPEG 订阅 A/B

| 指标 | 有 JPEG 订阅 | 无 JPEG 订阅 | 观察 |
|---|---:|---:|---|
| 原始图/CameraInfo | 648 帧，约 21.59 Hz | 876 帧，约 29.16 Hz | 无订阅恢复到接近相机 30 FPS |
| JPEG 压缩图 | 648 帧 | 0 帧 | 无订阅时确认没有无效编码/发布 |
| 三话题同 stamp | 647 组 | 不适用 | 有订阅时 raw/info/compressed 对齐 |
| RKNN perf | 333，约 11.10 Hz | 401，约 13.37 Hz | 无 JPEG 后吞吐增加约 20% |
| processing P95 | 90.316 ms | 75.939 ms | 降低 14.377 ms |
| inference P95 | 79.089 ms | 64.936 ms | 同机资源争用减轻 |
| processing P50 | 70.238 ms | 63.373 ms | 无订阅轮次较低 |
| inference P50 | 61.656 ms | 55.688 ms | 无订阅轮次较低 |

两轮是顺序实测而非严格同时对照，温度、CPU 频率和系统调度会影响绝对差值。冻结 revision
随后又完成一次 15 秒 compressed 回归：raw/CameraInfo/JPEG 分别为 438/439/439 条，频率均
约 `29.17 Hz`，438 组 raw/info/JPEG 时间戳一致，RKNN 199 条、处理 P95 `75.709 ms`，
`errors=[]`、新增 USB 日志为空。这证明按需发布没有破坏 JPEG 话题，也说明早期 21.6 Hz
不是固定上限。因此这里能下的确定结论是：无人订阅时不应白做编码；有远程显示需求时可
正常订阅，但其资源代价必须在当时的整机负载下测量，不能把顺序短测差值当固定折损率。

### 10.3 人工碰线、USB 断连与自动恢复

用户已确认首次运行期间碰过相机线。内核在约运行中段记录：

```text
usb 1-1.4: USB disconnect
uvcvideo ... Failed to resubmit video URB (-19)
usb 1-1.4: new high-speed USB device
Found UVC 1.00 device USB 2.0 Camera (0c45:636b)
```

设备在内核层约 0.55 秒后重新枚举。相机节点随后连续读帧失败，在从首条 ROS 读帧警告计时
约 2.8 秒后触发重开，并记录：

```text
摄像头连接超时，尝试重新连接...
成功打开摄像头 ... 协商=1280x720@30.00 MJPG
摄像头重新连接成功
```

断连期间 roslaunch、rosmaster 和其余视觉节点没有退出，恢复后图像和 RKNN 继续发布到
600 秒结束。这说明当前相机节点具备实际的热拔插/接触不良自恢复能力。

但是首次 Gate 脚本把任何新增 USB disconnect 都定义为硬失败，所以该轮最终状态应记为：

```text
链路连续运行与断连自恢复：PASS
无扰动 USB 稳定性 Gate：FAIL（人工碰线造成一次真实断连）
```

不能因为已自动恢复，就把第一次运行改写成清洁 600 秒 PASS。

## 14. 遗留风险与下一步

1. **固定相机线缆。** 本轮已经实证轻微物理操作可触发 USB 断连。实机部署前应使用可靠
   线缆、应力释放和机械固定；软件自动恢复只能作为兜底。
2. **安装相机外参。** 外参完成后再验证 TF 年龄、地图点、stable ID 和投递中心；当前
   任何地图定位结论都不成立。
3. **补真实场景观察。** 将相机对准标准靶、红十字、H 和负样本，人工观察框与中心；若要
   报精度，必须建立人工真值或可复核实例清单。
4. **统一 RKNN 软件栈。** 在最终镜像冻结时对齐 RKNNLite/runtime/driver 版本并复跑本报告
   的离线、回放和 600 秒 Gate。
5. **不叠加第二全图 RKNN。** NPU 已在当前统一模型下持续报告 100%；应优先复用统一输出、
   用 ROI/阶段门控减少 CPU 几何开销，并在导航/LIO 联跑后再决定是否优化频率。
6. **默认关闭 compressed 订阅。** 正式飞行链只消费 raw；远程看图时按需启用 JPEG。冻结
   revision 已证明话题功能正常，但其成本随系统负载变化，整机调试时仍应复测。
7. **封闭机舱热测试。** rerun1 开放实验室环境最高观察到 69.307 °C；装机后还需在真实供电、
   风道和环境温度下复测，不能直接外推。
8. **最后再做整机联调。** 本报告没有授权或执行起飞、舵机、投递，后续必须继续遵守实机
   动作人工确认边界。
