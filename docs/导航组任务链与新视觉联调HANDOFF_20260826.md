## 3. 候选与权重的真实语义

当前逻辑**不是全局记忆目标按权重排队**，而是“当前新鲜候选局部按权重选择 + 发现时序
驱动立即中断”。具体为：

1. `target_memory` 给当前候选按类别权重排序：
   `red_cross=10, tank=5, panzer=2.5, bridge=2, pillbox=1.5, tent=1`；
2. 只有已经确认、最后观测年龄不超过 `0.5 s` 的候选能发布为
   `/uav_vision/selected_target`；若同一帧/时间窗同时可见多个目标，权重高者优先；
3. 导航组 `CandidatePolicy` 只检查 `map_valid/state/class/有限坐标/新 ID`，不读取权重；
4. manager 在 `SEARCH` 收到第一个合法 `selected_target` 后立即切到 `APPROACH`；
5. `APPROACH/TARGET_HOLD` 期间的新目标回调被忽略，不进入持久任务队列；
6. ID 在准入时就加入已接受集合。即使后续 `capture_timeout`，同一 ID 也不会再次执行。

因此本轮 pillbox 与 tent 同区域出现时，pillbox 因 `1.5 > 1.0` 先被选中，证明了局部权重
有效；但尚未看见的 bridge/panzer/red_cross 不会参与比较，失败 pillbox 也没有冷却重试。
若要满足“全场记忆—权重队列—三投”，任务层后续应消费 `/uav_vision/targets` 的长期地图
候选，显式维护队列、执行结果、冷却/重试和剩余时间，而不能只订阅 `selected_target`。
