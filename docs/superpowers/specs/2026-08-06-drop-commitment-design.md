# 最终下降投递承诺设计

## 背景

新视觉固定三投仿真在高位完成圆环精修、连续稳定对准并发布有效
`ReleaseEvidence`，但无人机进入最终下降后，相机视野无法继续完整覆盖靶标，检测转为
`stale_observation`。现有链路要求实际释放时仍有 0.5 秒内的新鲜证据，因此正确对准的
任务也无法获得 `/mission/release_permission`。

视觉新鲜性检查本身正确，缺陷在于任务层没有区分“仍在寻找/对准”和“已锁定目标并
进入最终下降”两个阶段。

## 设计目标

- 未获得稳定、有效视觉证据时，任何下降和释放请求都保持拒绝。
- 获得稳定视觉证据后，允许在受控的短时窗口内依据锁定位置继续下降和投递。
- 陈旧视觉记录不得被重新标记为新鲜证据。
- 投递承诺必须绑定目标、对准模式、载荷槽位、锁定位置和时间。
- 超时、水平漂移、模式切换、状态切换、重复目标或重复槽位必须使承诺失效。
- 原始旧模式默认行为保持不变。

## 方案

### 任务层承诺

`release_permission_arbiter` 在收到 `evidence_valid=true` 时，仅在以下上下文同时有效时
建立投递承诺：

- 对准模式为 `drop_circle` 或 `drop_cross`；
- 控制状态为 `Aligning` 且状态消息新鲜；
- 飞机位姿新鲜；
- 视觉目标类别与当前对准模式匹配；
- 目标和槽位尚未成功投递。

承诺保存原始证据、目标 ID、类别、对准模式、待用槽位、锁定时间和锁定时的 XY 位姿。
承诺有效期和最大水平漂移通过参数配置。当前视觉随后变陈旧不会修改原始证据，只要承诺
仍有效，仲裁器可在释放高度窗口内发布短时 `ReleasePermission`。

### 控制端门控

`patrol_control` 继续使用新鲜 `drop_ready` 进入最终下降，但实际调用 guarded `/Servo`
时改为要求任务层发布的当前释放许可。为避免 `patrol_control` 与 `uav_mission` 形成 Catkin
循环依赖，仲裁器同时发布一个 `std_msgs/Bool` 许可状态话题；控制端记录接收时间并按短时
超时检查。完整目标、槽位和重放校验仍由 guarded proxy 使用 `ReleasePermission` 执行。

### 清理与失效

以下任一条件立即清除承诺并发布拒绝：

- 对准模式离开原模式；
- 控制状态离开 `Aligning` 或变陈旧；
- 承诺超过超时；
- 当前 XY 相对锁定位置超过最大漂移；
- 对应槽位成功完成；
- 目标已在成功集合中。

## 审计与日志

`visual_delivery_audit` 分别记录当前视觉证据、最近一次有效锁定证据和实际释放许可。
原始 Servo 调用验收使用锁定证据验证稳定帧数，并使用当前许可验证高度、模式、槽位和目标
一致性。这样不会要求释放瞬间仍能看全靶标，也不会把陈旧帧当作有效当前帧。

## 测试

- 单元测试：没有有效证据不能建立承诺。
- 单元测试：有效证据后当前帧变陈旧，在承诺时间和漂移范围内仍可于释放高度获得许可。
- 单元测试：承诺超时、水平漂移、模式变化、重复目标和重复槽位均拒绝。
- C++ 测试：新视觉模式只有收到新鲜任务释放许可才调用 guarded `/Servo`；旧模式不受影响。
- SITL：`newvision_fixed3` 必须完成三类地图候选、三次锁定许可、三次 guarded mock ACK，
  且无重复、越权或未许可调用。

## 默认参数

- `commitment_timeout: 30.0` 秒，覆盖当前仿真约 20 秒的最终下降过程；实机必须按下降速度
  和控制延迟重新标定。
- `commitment_max_drift: 0.20` 米；实机必须结合落点要求和定位噪声重新验证。
- 控制端许可新鲜度沿用 `permission_lifetime` 的短时语义，不使用 30 秒承诺时长代替最终
  释放许可。
