## 可减少重复等待的后续方向（本轮不实施）

1. **起飞Z领先独立于走廊前视。** 评估独立起飞Z目标领先参数或起飞专用目标生成，保留起飞XY固定。当前3D限幅使爬升全过程多数时候仅领先约0.4m；它值得与FC爬升控制一起验证，但旧bag不能模拟扩大领先后的响应，不能承诺节时。不要全局改px4_max_distance影响走廊。
2. **对齐两层起飞ready含义。** 当前控制端3D<0.3、启动器Z<0.15且1s稳定是不同条件，不存在已证实的“两次各1s重复sleep”。若优化，保留一个明确授权起飞/任务启动的稳定性判断，共享其结果与阶段时间；另评估暂存位→2m单独到点的必要性，不将仅变更阈值当轨迹合并已验证。
3. **优先处理下降完成后的0.77～1.13s交接。** high_view_stage_limits.py:20、46～78按阶段/任务完整签名复用结果；同一失败重试已经不会重复写整套参数。可评估只写真正变化项、复用已确认不变参数，保留与完整事务/限高/新鲜度绑定的ACK；提前计算复访排序，避免到达回调里重复重算。应先区分同步参数读写、候选计算和ROS传输耗时，不能把0.5s状态延迟都归给某一项。
4. **减少人为造成的位姿恢复窗重启。** navigation_mission_manager.py:551与motion_observations.py:FreshPoseWindow在实际陈旧/失效后需要≥3个新样本、跨度≥0.2s才恢复。若长临界区/同步参数调用使本来持续更新的位姿被误判旧，应把非必要工作移出关键调度区；仍保留真实陈旧数据的恢复窗。当前记录证实guard存在，未证实陈旧的唯一来源。
5. **单独评估原到点dwell=.8。** planner_execution.py:1013以后结合新鲜同帧运动、距离、速度和持续时间确认到达。低位高度已进窗不等于满足全部条件；如要减少重复稳定检查，应先核对下降到达后下一阶段确需的条件与是否能复用同一事务的连续观测，不能跳过高度确认/有效地图或使用历史满足释放。

当前最小可优化候选是交接内计算/同步读写与重复资格验证。真实爬升、刹车和低位轨迹跟踪需另行动态验证；本轮不把调度时间和真实运动合并估算收益。
