# 2026-10-11 两轮高位逐航点停顿统计

结论：**正式到点后的普通任务派发不是数秒停顿的主因**。两轮6次普通高位换点，到点确认→下一命令累计0.309秒，到持续恢复运动累计3.004秒。6段可观察的规划器到达→任务确认累计14.838秒，但其中约7.056秒在12cm圈外、1.938秒圈内超速；不能全部算静止。优先核查高位终端跟踪与12cm到点判据的交互，再评估仅高位扫描的驻留时间；不盲目全局合点。

## 比旧提速计划更具体的优先项（仅提出，不实施）

1. **先看终端跟踪和高位12cm判据**：重点第一轮seq4、第二轮seq5/7；约14～17cm残余偏差时已低速，驻留却不能开始/会出圈。最小后续实验仅针对“已验高位的普通扫描点”，离线比较12/15/18cm的资格时刻，同时保留3D高度、新鲜度、目标ID和有效目标约束；不直接放宽全局SEARCH、升高位、下降、APPROACH或门/H验收。源码插入点是planner_execution.py约1069–1103行的距离/速度判据，任务角色需由manager显式区分，因为SURVEY reason也含低位准备与升高位，不能仅按SEARCH或SURVEY字符串分流。轨迹跟踪本身先核对误差分量、终端setpoint与FC，不先改增益。
2. **再看仅高位普通扫描的0.8s驻留**：7个完整扫描点最终资格窗口合计6.032s。可作为后续单因素候选对照0.8/0.5s，保持速度≤0.20和空间/新鲜度保护；这只压最后资格等待，无法消除前面7.056s圈外修正。候选是否够用必须验证观测覆盖、转角运动和轨迹衔接，不能把历史窗口差直接承诺为实飞节时。
3. **定向分析第二轮seq4近终点重规划及扫描结束交接**：已有首轨迹很快，分别关注106.106附近replan与135.874～136.778的构造/发布链；必要时只给_retreat/propose/派发边界补CPU耗时观测并避免重复计算。保持图新鲜、下降柱净空和原deadline，不缓存过期地图绕过许可。
4. **低优先级：任务派发和路线合点**：普通派发累计只有0.309s；当前大多数换点是真实90°扫描拐角，盲目合点可能切角、失去观测位置且影响边界。若以后只在已确认安全的同高度直线段预备下一轨迹，也必须保留逐ID事务与覆盖事实；门前后/下降/H/未确认观察点不得并入此优化。先用本表定位收益，再选单因素，不全局提速或全局合点。
