# 第一轮自动启动门槛逐时复核

2026-10-11。源录包：flight_debug_0 (1).bag。只读离线分析，未启动ROS节点、仿真或实机。

直接读取运行时/board_trials/run_metadata的ground_reference.takeoff_z=1.1877801418、mapping_startup.pose_topic=/navigation/local_pose、frame=camera_init。不是用原始MAVROS高度替代任务坐标。6474条录制任务位姿均通过按收录时间模拟的frame/年龄/四元数/有限数过滤。

复用生产run_trial.py的样本逻辑：最近1秒至少10帧，最新年龄<0.3秒，高度误差<0.15m，XYZ各轴1秒峰峰值<0.12m；OFFBOARD、armed、connected和state新鲜；上述条件连续满足1秒才调用start_mission。生产循环sleep 0.2秒。

| 相对bag秒 | 重算阻塞项 |
|---|---|
| 143.475起飞完成至约144.00 | 尚未到高度范围，且Z一秒变化超12cm |
| 144.00～145.60 | 高度进入范围，但Z一秒变化仍超12cm |

| 146.66～160.82 | 仅高度误差超过15cm；帧数、新鲜度、位置峰峰值和飞控状态通过 |
| 160.82之后 | 条件恢复合格，之后实际162.229秒启动任务 |

例如155秒：任务Z=1.40790，距目标+22.01cm；1秒XYZ跨度约0.30/2.43/1.67cm，已相当稳定。159秒距目标+23.28cm；161秒回到+12.75cm。不是一直抖动、缺位姿或缺OFFBOARD。

关键细节：1.06秒合格窗口不保证0.2秒轮询观察到连续1秒。对10种20ms间隔的轮询相位做离线检查，3种可在146.60～146.64触发，7种会错过，下一次在161.86～161.98才有资格触发。此比例只是相位敏感性，不是实际发生概率。bag没有supervisor每次循环的monotonic时刻/回调处理时间，无法唯一恢复实际轮询相位，也不能把离线161.86与实际162.229之差定性为某条新故障。

可明确结论：约14.16秒连续阻塞是实际任务坐标中的高度误差门槛；最早短窗口存在，但可以被当前轮询+连续计时方式错过。不能再说需要另外拿任务位姿才能检查。至于飞机为什么持续偏高，仍不是启动门槛回算能直接诊断的动力学问题。

本次不改启动条件、不放宽高度容差。起飞交接中间点遗留修复421e6023与本分析分开；不能宣称4.34cm目标修复能消除全部高度超差。
