# 同动作许可刷新与仿真接触记录修正

## 实际问题
初次开启续扫的 seed38 已在119.801 ROS秒得到缺少的真实panzer线索，131.600秒交给投递。139.550秒的许可已获准，但代理139.549秒报告permission_stale：bag支持节点间/clock处理相差约1毫秒的解释，不支持“许可长期陈旧”。由于未记录代理内部所读对象与now的原子快照，具体负年龄数值仍为推断。

旧代理将负年龄和过期都当作立即拒绝，Bridge随后将NOT_STARTED终结为可重试失败。任务撤销本次对准，转入低空再复核/冷却路径，最终148.701秒进入补扫，159.600秒重新接近，173.141秒才释放。正确目标已经找到了，这次额外折返没有必要。

## 最小修复
在已有异步舵机服务线程中，为同一固定动作增加最多0.25墙钟秒的许可刷新等待；不会阻塞控制定时器。未来时间戳独立记为permission_clock_ahead，必须等本节点时钟追上后才允许调用，不放宽年龄/高度/几何门槛。

等待期间释放共享锁，新许可或撤销可及时进入。只允许固定任务、决策、尝试、槽位、目标身份及模式一致的许可；对准撤销、身份变化、几何拒绝、已执行/不明执行直接拒绝。服务发现后再次使用同动作的最新有效许可检查。实际调用一旦开始仍锁住动作/槽位，不自动重试执行器。旧无身份Servo入口保留立即判定行为。

因此正常的毫秒级时间差在投递代理内被吸收，不再制造“未开始失败→丢掉当前对准→补搜”的任务转换。若0.25秒内仍没有有效许可，继续如实返回NOT_STARTED，由原有失败处置处理；不能因为目标正确就无条件释放。
