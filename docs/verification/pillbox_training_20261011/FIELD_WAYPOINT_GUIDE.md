# 现场走廊打点与起飞前核对

本说明对应08工作台的实测坐标入口，不改变控制参数。10月11日两份新bag记录的路线仍是X=7.7m的旧现场路线；不能仅凭“已抵达新的场地”认为程序自动重新测量了门的位置。

## 先统一原点和方向

1. 在地上标记起飞时FC中心的垂足为O，标记场内前向为+X，面对+X时左侧为+Y。飞机移动、起飞位置改变后重新测量相对坐标，不能仅修改一扇门。
2. **当前生成器对航点只加起飞参考XY，不依据当前机头自动旋转整条路线。** 这两包配置为`legacy_static`，map到camera_init为单位变换。必须确认定位任务轴与标记的场地轴一致，不能把任意起飞朝向视为自动生效的航线朝向。
3. 地面未解锁时检查遥测：向场内平移应主要增加任务X，向左平移应主要增加任务Y。该检查在定位初始化后进行；回到原点后若重新初始化，重新核对。检查时不要把机体系速度、地图位姿、相对航点混用。
4. 沿长度测的是X分量，沿宽度测的是Y分量，不是到起点的斜距。尽量用两条垂直基线和卷尺/激光测距确定分量。轴向角误差也会累积：在7.7m距离上，1°约对应13.4cm横向偏差；这是几何量级，不是本次已测误差。

## 每扇门测什么

- 测**实际打开的净空门洞**两侧边缘，取中点；不要使用整面墙的中心、铰链或门板中心。
- 测门平面位置、门洞净宽、净高、实际墙厚，以及门前后可用直线空间。
- 若门平面为`y=d`，门洞左右端在X方向，门中心`x_c=(x_left+x_right)/2`。沿-Y穿门时，门前点`(x_c,d+a,agl)`，门后点`(x_c,d-b,agl)`；两个点均对准实际门中心。
- 若门平面为`x=d`，则交换轴：沿+X穿门时门前`(d-a,y_c,agl)`，门后`(d+b,y_c,agl)`。
- `a/b`不能仅取很小数值或套用旧场地距离：需要给机身及通过判定留出空间，并确认门后点位于整机已离开墙面的区域，之后才允许转向。以实际机身包络、到点容差和现场空间核对，不在本说明中写死通用距离。
- 两扇随机门的`x_c`可能不同，不能把所有走廊点都固定在走廊中线。调整在门间净空处完成，穿门段尽量沿门法线，不能靠近门框才斜切。

## 工作台如何填写

“有序走廊航点”每行恰好三个数，英文逗号分隔：`x, y, agl`。按入口前→入口内→第一门前/后→第二门前/后→H区低位终点排序；AGL指FC中心离地，不是脚架或相机高度。H中心单独填`x, y`，不把H观察爬升点重复填入走廊序列。

“墙面常量轴/墙面位置”是现有走廊速度调度和路线优化的辅助几何，**不会代替真实地图，也不会自动生成或校正门洞中心**。本次旧配置是Y轴、`0.0,-1.4`，对应两道横墙平面；它不是X方向两侧长墙的位置。该表只有一个轴，不能把互相垂直的四面墙混填进同一串数值。

“低入口序号”从1开始，指达到走廊低位阶段的那个航点。所有实际处于走廊内的点必须符合走廊高度限制；H观察高度由H阶段单独接续。

`flight_area.center_bounds`是允许FC中心到达的范围，`target_bounds`是目标候选范围，`search_bounds`是搜索区。不能把实体墙外沿直接当作机身中心可以贴到的界线，也不能扩大这个矩形来假装门洞变宽。

## 提交前看生成结果，而不仅看输入框

1. 预览所选卡片、现场YAML及临时overlay路径，确认没有使用旧草稿覆盖刚修改的YAML。
2. 核对最终路线所有点，尤其随机门的两个不同中心、门前后顺序、走廊到H的转向。现有运动优化会合并部分共线中继点，输入了门前/门后点不代表生成后一定逐点执行；本次bag确实从入口内向H区低位终点发布长段目标。预览须检查优化后的路线；规划器也可在端点之间侧向绕行，不能把端点X当成全段X的硬约束。
3. 核对本次run_metadata中的实际路线、参考坐标与阶段高度；旧现场文件只用于对照，不当作今日测量值。
4. 如在回放里出现偏差，分开比较“输入航点→实际发布规划目标→设定点→实测位姿”。没有外部实测门框位置时，只能确认飞行器跟踪了什么，不能把定位轨迹本身当成门中心真值。
