## 结论与应先处理的问题

最新收尾确实按用户要求取消高位重复精密停稳，允许冻结后补偿与下降并行；最终释放位置/速度窗口、物理杆臂旋转、防重复执行保留。H缩短低位确认，并补了微未来状态有限暂缓。恢复代码已选择性进入整机/试飞/导航候选，正式模板仍默认关闭。昨日08实飞成功成立，但没有验收今日这些新行为。

1. **P1：B试飞分支的独立正赛入口仍有依赖遗漏。** `navigation_competition_manager.py:30`调用`CompetitionManager(hardware=True)`，但同树`navigation_high_view_full.py:19`父类构造器不接受hardware，第53行还固定实例化HighViewFull而不消费runtime_type。因此独立正赛启动存在TypeError，并且离线`deployment/competition/check_wiring.py:74`实际失败（没有构造出HardwareFullRuntime）。F及两个导航分支对应依赖一致，F检查通过。B的08专项成功不能代替这条独立入口验收。此问题在本轮只记录，未修改源码。
2. **P2：正赛flight_bounds不是全程XY硬围栏。** `competition_config.py:72`用它校验配置，第126行平移后的area未用于输出全场运行限制；第155行投后关闭search_region。搜索区限制、局部投递边界与实体避障仍存在，但不能宣称飞机在所有阶段都受flight_bounds硬约束。无实体外墙场景尤需区别“航点在边界内”与“整段轨迹/控制不会越界”。
3. **同步遗漏：导航liveness的fork远端仍旧。** origin和本地为f8795273，fork仍为e3ae668e，缺最新运行与来源说明两提交。其余本表origin与本地一致。本轮只核验，未代推fork。
4. **配置说明容易误读。** 距离档不是速度档；低位重访经SEARCH时仍使用巡航前视。`motion_optimization.survey_line_weight`当前不驱动全局权重，真正字段是顶层`planner_line_preference_weight`，默认2.0。B本地交付旧索引仍说恢复未进入整机、H为0.03/0.05m/s与0.5秒，已落后于当前代码，不应继续作为操作参数依据。

另有两项**仅在启用新恢复时生效的流程缺口**，应与入口遗漏一起优先修复：

- **P1：终态/适配器故障没有撤销恢复上下文。** `navigation_planner_bridge.py:946`的`_apply_outcome()`只记录`CANCEL_REQUIRED/STOP_REQUIRED`，没有发布inactive恢复上下文；第1184行的异常处理关闭普通输出，也未撤销它。生产方法复现：60秒原期限中，第12秒初始规划超时已产生terminal和CANCEL_REQUIRED，恢复撤销消息仍为0；异常路径同样为0。独立控制接收门在旧active上下文下仍接受新鲜恢复指令。因此下一决策未及时到达时，不能保证Bridge结束即停止恢复。局部8秒和原deadline仍有效，不是无限运行，更不是已证实的实飞故障。

既有恢复三轮PASS使用生产map/FSM/server/controller＋合成运动模型，不含真实PX4/Gazebo动力学及完整runtime Bridge；最新正式接线也只做离线验证，因此没有覆盖本次发现的终态撤销和失败收口。普通膨胀退出的既有夹具采用0.45m膨胀、0.275m机体半径；正式候选为0.25m膨胀、0.39m机体半径，不能沿用夹具PASS承诺正式配置也有足够可豁免缓冲。故“昨晚门前ABORT本次一定能救回”尚不能承诺，尤其该轮实际障碍来源与净空仍需注入重现。
