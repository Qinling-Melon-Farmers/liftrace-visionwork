# 已知线索延期复核与统一接近许可

## 修复内容

修复在导航权威既有工作树完成，并同步研究、板端试飞工作树，未新建分支。

1. REACQUIRE超时或REVISIT执行失败时，记录TARGET_DEFERRED，优先调度尚未尝试的其他有效高位线索；第一轮处理完再回访失败目标。
2. 沿用原每类最多两次复访预算，不增加独立计时器或恢复状态机。预算耗尽后才进入原冲突复核/低空补搜；原任务deadline、已投槽位和已投类别保留。
3. 粗地图不能给访问顺序时，只按距离提供待检验的下一目标，由原3D规划器判定可达性，不把粗排序失败直接当作整批线索失效。
4. MissionCore.choose分配投递槽位前统一检查可选approach_admission。HighViewFull将已有BoundaryRevisit判定接入该入口；高位重捕和LOW_COVERAGE使用同一函数。队列里之前已接受的候选在派发前也会重新检查。
5. 越界候选不会永久拉黑整个类别；后续新鲜坐标合格时仍可接近。高位线索仍可保留用于导航，不伪装成释放许可。

改动限于mission_core.py、high_view_full.py及相应测试。普通MissionCore未设置该可选许可时保持原逻辑；板端高位试验继承此实现，独立视觉中断试验不因此自动获得新的场地规则。没有修改旧patrol_control、Servo、PWM或速度参数。

## 验证

- 定向HighViewFull测试28项通过，含新增6项：失败目标延期后完成另外两投再重访；全部失败时最多两次/类；不可达目标改选其他线索；补搜派发前检查已有队列；不让越界高权重候选阻塞合法目标。
- 实际研究整机工作树uav_mission完整回归340项通过；板端专项配置/事务8项通过。
- 曾在导航参考工作树直接运行整机全套测试，因其旧patrol/FreeDOM旁证副本不同及未加载ROS环境出现失败；未将这组结果算作通过，也未覆盖旧基线来迎合测试。最终整机验证使用实际集成工作树，ROS导入环境已加载。
- Python修改不涉及C++二进制，本轮未启动仿真、未操作硬件。不能将单元回归写成seed40实飞/整场已通过。

## 仍需验收

此次修复解决“一个目标失败就放弃其他线索”和“补搜绕过接近许可”。它不保证实际机体跟踪误差为零，也不等价于RECOVERY时实际位姿必定可规划；实际恢复位置、不同定位源误差和近边净空仍需单独验证。保留原恢复与释放确认，不伪造成功以提速。

后续明确授权后优先复测seed40：另外两条线索应继续被利用；同一个不合格候选不能经补搜绕过许可；若坐标被新观测纠正，应允许重新接近。再测seed38补搜和普通成功布局，保持完整报告与原FAIL记录。
