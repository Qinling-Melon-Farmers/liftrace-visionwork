# 初始搜索规划等待上限：可选修复候选

本次用户授权的seed34单轮重跑已完成37/37 PASS；失败搜索等待约360→40秒，三投/两门/自主降落完整通过。[对照报告](rerun/REPORT.md)。默认与交付包仍保持原版本。

针对用户“尝试修复，太困难则保持当前版本”的请求，仅保留范围小的候选。当前d1ab9208交付两包、默认飞行行为、主干验收结果均不替换；初始开发阶段仅离线验证；用户随后明确授权重跑已修复seed，本阶段将只运行seed34一次，仍不做实机动作。

## 修改范围

PlannerMotionExecutor增加`search_initial_plan_timeout_ns`，ROS参数为`execution/search_initial_plan_timeout`（秒）。默认0关闭；仿真入口增加同名launch参数，供未来明确授权的试验显式传入，例如20秒。

只在SEARCH/RESUME已被规划器接单，但该请求从未产生有效TRAJECTORY_READY或TRAJECTORY_FINISHED时，达到初始等待上限便通过既有TIMED_OUT/CANCEL_REQUIRED路径结束该次尝试。底层反复FAILED_ATTEMPT不能重置计时。

- 一旦该请求有过有效轨迹，即使后续重规划失败，也仍受原来的90秒运动期限管理，本补丁不提前截断。
- APPROACH、RETURN_HOME、LAND、ABORT及释放/恢复流程不适用此新上限。
- 旧请求的READY不能给新请求豁免；超时只产生一次终结事件，保留既有取消处理。
- 任务层仍按原覆盖游标和重试次数运行，没有伪造到达、跳过投递、放宽碰撞或提高高度。

这修正的是“初始规划一直失败却等满运动期限”的消耗边界，不是完整路径修复。默认0保证当前版本行为保留，20秒只是待SITL验证的候选值，不能视作已优化阈值。

## 验证

254项任务/执行/Gate等回归通过，含7项新增边界测试（已加入现有Catkin登记的test_planner_execution.py）；Python检查通过，默认0与显式20秒的ROS launch静态展开通过。整机构建日志另留本地。

对原五组决策及按请求时间戳归属的规划状态做离线筛查：20秒阈值仅影响seed34的decision_seq 2/3/4/5，它们分别约90秒且从未有轨迹。五组其余搜索请求首次轨迹延迟均小于1秒。这里不是闭环重放：新超时会改变后续时序和观测，不能把原任务用时直接减掉280秒后宣称成功。

新SITL应先核对超时取消→下一决策交接、既有成功样本和seed34，再考虑扩大范围；用户随后授权对已修复seed重跑：使用原seed34完整场景、相同算法/几何，显式search_initial_plan_timeout:=20，关闭录像/bag，observe_full_trial=true；只运行一次并保留原始结果。

## 暂不修改的部分

- seed31近地IMU/估计分离：仍需高频真实刚体运动与输入对照，不能凭已有尖峰直接调融合或接触参数。
- seed33门洞后占据：放大目标调整半径会涉及到达判定与安全有效目标，且源回波原因未完全隔离，不做猜测性改动。
- ABORT回收策略、局部地图窗口、搜索horizon和预算均保持原值。本补丁不声称解决这些问题。

候选保存在本地feature分支`feat/search-planning-wait-bound`，未更新交付压缩包或主干。关闭参数为0即可保持原策略，不需要改变现场配置。
