## 二、为什么旧版能过，新版反复失败

不能说旧成功失效，也不能说最新版本已经更稳。新版本多项变化连续推进，缺少每项变化后的成功基线固定；前期把“固定航点挪开占据区”当作主要解决手段，对地图更新后的目标适配与实际停车余量考虑不足。这是本轮推进方式需要纠正的地方。

还有一个容易忽略的几何差别：R57/0.85m两处通口中心的横向错位约0.2204m，R58变为0.70m。前后引导距离由0.45m增至0.70m后，两墙之间用于横向转移的航点间纵向距离又从约1.335m缩至0.835m，直连段斜角约从9.4°增至40.0°。所以新场景不是仅把通口缩窄5cm；转弯要求也明显不同。退远航点虽然有利于单个目标离开墙角占据区，也压缩了中间转移空间，之前没有把这两方面一起考虑充分。

已经区分出的失败链：

1. **R57严格0.80m：固定目标占据。** 两处墙点相对真实墙面偏移约12–14cm，经普通膨胀覆盖第5点，90s超时，零护圈接触。移远航点能改变这一个点的可达性，不能解决后续地图变化。
2. **R58首轮：搜索区单点成柱。** 一个孤立点生成全高柱覆盖第二靶接近点；结构支持修复后后续多轮恢复三投。
3. **R58结构支持轮：接触与飞控位置波动。** LIO水平观测仍连续，飞控估计出现大幅波动；几何回放还发现早于护圈事件的桨盘贴近外墙迹象，完整动力学因果未唯一确定。
4. **航向修复轮：入廊停车余量不足。** 飞控水平误差约1cm，实际比北向停车目标多走约10.2cm，目标距墙仅40cm，护圈接触。入廊点移到中线后，这个位置没有再触墙。
5. **中线停点轮：门后点再次占据。** 已到第一通口截面，但门后原目标被更新的长墙地图覆盖；关闭的局部调整使重试无效，最后超时、零碰撞。
6. **最后局部调整轮：仍有外墙接触。** 三投完成，179.495s在第一短墙前触及外侧长墙，FAIL。冻结图的局部选点通过不等于当前窄口闭环鲁棒，剩余墙边余量/跟踪问题没有解决。

R58共6次启动尝试：5次进入飞行、1次在起飞前因平面起降垫接触类别结束；十seed未开始。详见[分轮历史](../r58_corridor/REPORT.md)、[最后一次原始Gate](last_run/gate_status.json)及[最后飞行图](last_run/flight_analysis.png)。全部失败按实际结果保留，没有放宽Gate或删除失败来统计成功率。

## 三、比赛坐标系换角度怎么兼容

**可以兼容，但当前工程还不是“随意改个frame名称就自动支持任意角度”。** 当前FAST_LIO多处输出硬编码`camera_init`；任务、覆盖范围、水平柱区域与返程点也按这套局部坐标给出。实机入口的`map_frame`参数没有贯通所有这些部分。仅传`map_frame:=field`或只改消息`frame_id`会造成数值坐标与标签不一致。

### 当前改动最少的现场方式

选择一套场地局部坐标，起飞前让机头/初始化方向与选定场地轴对齐，测量起飞点相对场地原点的位置。确认LIO与飞控融合后的局部轴向实际一致，再把赛会给的坐标换算到这套局部坐标。用两处相隔较远的已知点或一条有方向的场地边确定平面旋转和平移，再用另一处点复核。传感器外参保持相对机体固定，摄像头下方21cm不随赛会坐标图旋转而重标。

这种方式优先保留当前按轴对齐矩形生成搜索航线的实现。坐标表只是换了画法时，不需要为了跟随图纸方向重构整条定位链。

### 若必须支持任意起飞朝向

将赛会坐标记为F，内部飞行坐标记为L，统一使用同一个刚体变换：

```text
p_L = Rz(theta) p_F + t
yaw_L = wrap(yaw_F + theta)
z_L = z_F + t_z
```

例如theta=90°、t=(0.5,-0.2)，赛会点(2,1)转换后为局部点(-0.5,1.8)。原点、角度方向、米/厘米、度/弧度都必须明确；旧`patrol_real.yaml`航向用度，新`post_delivery_yaw`用弧度。

要一起转换的是：搜索航线、返程航点、降落点、飞行边界、水平绕障区域和目标航向。相机到机体的固定外参不参与这次场地旋转。现有覆盖搜索和部分ROI是轴对齐矩形：任意旋转后应保留多边形/旋转坐标查询，不能仅旋转两个角点再取外包矩形，否则会扩大搜索或允许区域。仿真评测截面当前按x/y轴表达，旋转场景时也要同步处理。

建议只在场地配置进入任务系统的边界统一转换，内部LIO/Planner/控制继续使用一致局部系；不在每个节点各做一次补偿。TF应记录实际变换，改`frame_id`不是变换。采用右手系、米和弧度，ROS机体/光学轴约定参考[REP103官方源](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0103.rst)；局部连续坐标与场地参考的分工参考[REP105官方源](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0105.rst)。此兼容方案尚未在当前工程完成任意旋转实跑验收。

坐标换算解决原点/轴向不同，不会自动消除定位漂移、测高零点误差或时间戳误差。

## 四、仿真碰撞检测会不会带到实机

**Gazebo接触插件和接触评分节点不会被当前实机入口启动。** 本次只用`roslaunch --nodes/--dump-params`静态展开`competition_hardware.launch`，没有运行节点：共22个应用节点，无Gazebo、碰撞评分、真值评测、mock、自动解锁或PX4参数写入节点。名单见[静态展开结果](hardware_nodes.txt)。

仿真插件保留护圈碰撞响应，并对额外虚拟护圈代理关闭雷达射线可见性；R58补充观察机身/桨盘既有碰撞。它不会在实机修改雷达原始回波、控制飞控或设置PWM。真实护圈若遮挡雷达，不能照搬“虚拟代理对雷达不可见”作为实机滤点策略。

**共享代码和参数仍会影响实机。** 硬件入口目前默认加载同一`horizontal_planner.yaml`和`vcl06_horizontal_field_runtime.yaml`，所以柱体支持、局部目标调整、航点和目标航向会进入实机。仿真接触观察隔离，不代表所有从仿真阶段产生的算法改动都已隔离或实机验收。

还发现一个实际配置差异：仿真入口覆盖了返程航向容差0.10rad和转向开始距离0.50m；硬件入口没有相同覆盖，前者走源码默认pi，后者仍为4.0m。不能把仿真的“入廊前转向停稳”直接当作硬件入口已一致实现。本次记录这个差异，未继续修改冻结飞行行为。

## 五、去年0.65m与上下运动，如何参考

原实机`patrol_control_real.launch`加载的`patrol_real.yaml`确实写了：

| XY点（旧坐标） | 高度顺序 | 各点悬停 |
|---|---|---|
| (6.50,3.63) | 0.65m | 0s |
| (8.08,1.80) | 0.65→0.15→0.65m | 2→2→1s |
| (8.19,-1.90) | 0.65→0.15→0.65m | 2→2→1s |
| (8.29,-4.40) | 0.75m降落点 | Land_point |

旧任务共16点，`waypoint_skipping_index=8`之后返程/走廊共8点、4处不同XY，全部yaw=0；`flag_planner_px4=0`使用Planner。`Nothing_point`按普通跑点和悬停执行，上下变化是写入航点表的固定动作。文件没有说明它们究竟用于哪个门的穿越、低空观测或现场调参，不能擅自写成“主动上下扫描能保证定位”。

值得保留的是低空通行、进入狭窄段前准备、关键点悬停和明确的阶段顺序。0.15m低点需要核对机架下沿、相机、地面和高度基准，当前不自动照抄反复升降。

### 接受的低空目标与尚未满足的条件

- 走廊名义目标按 **0.65m**，希望实际通行高度 **≤0.70m**。本报告暂按机体参考点相对地面解释；如果0.70m指门洞净高，还必须扣除机顶雷达/护圈高度与倾斜包络。
- 最近一轮返程阶段，真值高度减飞控估计高度P50约 **9.64cm**、P95约 **14.62cm**、最大约 **16.68cm**。0.65到0.70只有5cm余量，当前数据不支持实际不超过0.70m。
- 降低航点z不等于约束整段轨迹。当前Planner仍有2.30m全局顶界，必须在明确的走廊阶段限制规划与执行高度，并用地面参考核查实际高度；不能把整个任务全局顶界改成0.70m，否则会破坏1.40m搜索和1.60m取景。
- 新相机在机体0.65m、相机相对机体z=-0.08588m时，短边地面视野约 **0.56m**。当前H检测依赖完整1m外圈，无法简单沿用1.60m取景流程到0.65m；外参正确不会扩大镜头视场。
- 完全离开限高区后，可保留现有H1.60m取景再下降。若H降落区也受0.70m限制，需另做低空H局部特征/先识别后持续跟踪的降落策略，目前未实现或验收。

因此本次保存[低空方案文件](LOW_CORRIDOR_PROPOSAL.yaml)，没有把未满足上述条件的0.65m草案直接替换实机默认配置，也没有假称已实现硬限高。

## 六、还能不能上实机

**可以作为上板静态联调的工程基础，当前R58不能直接作为已验收的比赛飞行版本。** 代码能够构建、关键逻辑回归通过、仿真多轮完成三投；窄走廊全流程仍失败，且低空新要求和实机参数一致性尚未闭环。R56与R57/0.85m的SITL成功也不等于实机飞行验收。

后续至少还有四块工作：

1. **现场坐标与高度基准。** 固定轴向/原点映射，确认机体/IMU/相机参考点，测定实际控高误差。需要时再评估下视测距，不能先假设现有高度链能保证5cm余量。
2. **走廊与降落。** 选定成功基线，最小范围实现低空阶段及H区域边界；解决当前墙边余量/跟踪问题，补实跑。十seed当前暂停，不继续消耗轮次。
3. **板端实时视觉与导航链。** RKNN离线已有历史性能记录，但真实相机、CameraInfo/TF、同步、板端持续运行和延迟没有因笔记本SITL成功而自动验收。
4. **整机执行与人工接管。** 机械组Servo执行/ACK、载荷、实际落点、遥控接管及急停需要现场联调；当前三投是仿真mock执行记录。

建议将R57/0.85m成功标签作为同类错列墙的回退对照，R56作为完整历史闭环对照；R58保留作实验分支，不直接合入main。已经验证的相机安装修正和完整任务功能继续保留，后续按单一明确问题推进。
