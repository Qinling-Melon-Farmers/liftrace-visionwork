## 验证

- 任务层unittest discover：565项，561通过、4项既有跳过。
- 控制层49项通过：23项异步舵机、6项真实生成消息/生产授权回调、12项边界缓存、7项像素高度、1项对准保持。
- 1秒模拟舵机服务期间保持23次模拟设定点发布，最大间隔约50.24ms；这是离线生产方法验证，非板端测量。
- plan_manage（fast_planner_node、traj_server）、patrol_control、uav_mission构建成功。
- 实际生成的ReleasePermission、ReleaseAuthorization、ServoAction请求序列化/反序列化保留epoch和revision；两种许可消息字段结构一致。
- 本机系统Python3.8的em生成器连续发生TypeError；改用已有rl_drone解释器和临时路径中的系统em.py完成代码生成与构建，没有安装新环境或依赖。

控制缓存仍沿用原参数语义。ROS缓存首次订阅/失效可能访问master，1Hz刷新不是跨多键原子事务；不据此宣称彻底消除整机控制抖动。现场参数应在地面配置。

## 超高回入与虚拟柱退出：已确认缺口，未启用恢复旁路

当前正式链缺少持续验证的任务参考、权威FC reset和独立LIO健康生产者。不能把FC反馈跳高直接当作物理超高下压。保留既有拒绝/保持及任务期限，不把“未ABORT”称为已恢复。本轮没有实现自主超高回入或纯虚拟柱退出。

完整调查、生产方法复现、限制与后续范围见[恢复调查](recovery/REPORT.txt)。后续在EV连续性方向补齐可信输入及同一坐标代次，再做实体/虚拟分层、完整恢复轨迹及执行端接通；需要按真实超高/上升制动/柱内退出/实体重叠/FC独跳分别动态验证。
