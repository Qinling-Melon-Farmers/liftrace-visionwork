# 工作台回放整合与分发验证（2026-10-10）

工作台新增 `/replay`，从主页面和日志页面均可进入。本次只改本地工具，不连接板端、不启动 ROS 节点、不改飞行参数。

## 使用方式

- WSL 开发工作区默认发现 `试飞产物/` 与工具 `data/` 下的已封闭 bag、已验证回放。
- 在回放页选择 bag、帧率和显示坐标系后生成；状态目录保存独立作业、进度和日志，同一输出库只允许一个生成任务。
- 已有回放可直接打开；播放器提供四种视频，支持 HTTP Range 和拖动。原 bag 不修改，重复生成使用新目录。
- Windows 原生工作台可浏览已有回放。分发包内含回放源码，但生成 ROS1 bag 回放仍需已有 ROS Noetic 的 Linux/WSL 环境；界面明确显示依赖状态，不自动安装或桥接。
- 默认使用 CPU 编码；`auto` 实际探测四路 NVENC 后选择，探测失败回退 CPU；显式 `nvenc` 不可用则报告失败。运行中编码失败不会冒充成功。
- 图像叠加、地图和曲线仍由 CPU/OpenCV 绘制。缓存重复图像缩放与曲线坐标，减少全帧复制；不改录包时间线与画面语义。

## 实际验证

1. WSL 源码工作台 HTTP：最新真实 bag 的独立3秒片段，经 `/api/replay/start` 生成四视频并完成校验；显式请求 `auto` 实际选用 NVENC。硬件会话始终为空。
2. HTTP Range：`bytes=100-199` 返回206及100字节，长视频不整文件装入内存。
3. Windows Edge：主页面、日志、回放页、今日完整回放均打开，无脚本异常；视频拖动至第100秒、画面解码通过。
4. Windows 原生分发包：BAT启动、页面/配置预览、离线执行阻断、端口占用自动顺延通过，未连接设备。
5. 打包使用显式白名单，包含 `video_encoder.py`，不包含用户未跟踪的 `merge_bags.py`、bag、模型、个人配置、密码或密钥。

定向回归：回放8项、原日志16项、独立分发1项通过；ULog在修复后3项通过、1项因未指定外部真实ULog输入跳过。编码器与原replay契约共14项通过。

发现并修正两处真实接入问题：工作台为终端复用的系统Python路径污染conda回放依赖；沙箱视频请求无Origin且带cross-site标志导致只读媒体被误拦。环境隔离仅作用于回放子进程；仅回放只读资源允许对应媒体请求，API动作仍保留原同源检查。

同样的系统Python路径污染也影响既有ULog分析子进程。本轮使用当前解释器的 `-E` 启动该离线分析，避免系统NumPy遮蔽conda环境；保留主工作台终端依赖，原ULog上传/解析/导出回归恢复通过。

GPU与CPU实际对比见[编码优化报告](../replay_gpu_20261010/REPORT.md)。真实25秒片段两次运行中位：旧CPU 10.72秒、新CPU 9.83秒、NVENC 11.79秒。因此保留CPU默认，约8.3%的片段收益不能外推为全部bag同等提速。编码质量参数不等价，不声称CPU/GPU输出逐像素相同。
