# 后续开发：覆盖查询与任务历史账本

本轮新增`uav_coverage_memory.queries`，只读、未接入飞行链。接口输入为状态栅格、源时间戳、mission epoch、generation及待观察区域，输出为面积统计和观察价值排序；没有导航目标或跳点许可。

`Snapshot.query`精确计算矩形与部分栅格的交面积，分别报告当前可见估计、未知/质量不足/遮挡/待累计面积；拒绝陈旧、未来、错误frame或epoch，超出地图范围的区域不进入排序。`rank`提供可配置的质量重看/遮挡换视点权重及代价归一化，输出始终携带`requires_reachability_validation=true`，障碍可达性仍需原规划链处理。

在线旁路保留60s活动估计是新鲜度策略，不代表60s前的地方从未看过。`MissionLedger`将过去的估计与当前状态分开：同一epoch内保留历史，当前视角遮挡不抹去过去观察；新mission、generation、几何或真实时钟回退清空；过期/重复/乱序输入不混入账本。新场景/定位重置必须由上游提供正确epoch，不能把该账本当作已经解决联合地图重置。

历史区域仍保留非零复查价值，不永远禁止复访；100状态也不等于已知自由或目标召回。该层为后续安全补扫/恢复提供基础，目前仅离线测试和数据复盘使用。

10项查询/账本测试覆盖南北侧排序、精确边缘面积、超界、错误身份/时效、历史与TTL分离、视角遮挡、epoch重置和乱序。观察器相关总计61项测试通过。纯查询模块没有加入正在运行的0.70m基线进程；后续0.80m对照保持相同在线观察器代码/配置。

已完成的0.70m seed32旁路验证：37/37 PASS，任务523.659s，三投类别见`run_metrics.json`。采到的被处理图像中99.94%匹配有效地图，活动估计峰值20.86m²；活动窗口面积不是全场召回或真实覆盖率。首次10万点容量问题的95s诊断轮独立标注DIAGNOSTIC_STOP，不混入完整任务成功率。
