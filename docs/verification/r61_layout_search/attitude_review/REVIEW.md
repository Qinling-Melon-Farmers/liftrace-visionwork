## 实际机头和相机

`mission_core.Pose.yaw`默认0；当前post_delivery_yaw=pi/2。`traj_server.cpp`发送到控制链的PoseStamped使用interpolateYaw(current_yaw, yaw_goal, distance...)，不是航段切线；内部另一个PositionCommand带样条yaw，不能把它误当最终MAVROS航向。LAND交接目前没有完成保持走廊航向的修复。

固定下视相机没有独立云台，不会自动朝靶标转动。飞机可侧飞/倒飞；机体roll/pitch由实际位置控制产生，不能因为位置目标四元数的roll/pitch为0，就认为飞机始终水平。pose_tf_broadcaster传递完整实测四元数，Gazebo相机随刚性机体姿态渲染。视觉TF能补偿投影姿态，不能恢复已经离开视场的圆环或消除运动模糊。

R60 seed11 MAVROS记录，在原始pose z≥0.5m的1793个样本中，|roll| P95=1.62°、|pitch| P95=2.00°，峰值4.42°/4.72°；移动速度≥0.2m/s的692个相邻样本，机头与航迹方向夹角中位数88.10°，62.86%超过30°。这是整段过滤统计，混合搜索、接近和返程，不是仅搜索统计，不是新的实机测量；原始z筛选也不冒称精确AGL。详见[data/recorded_fields/r60_seed11_attitude_summary.json](r60_seed11_attitude_summary.json)。

新安装FC高1.4m、光心高1.24m，平地短边视野约1.23m。yaw0时长边沿世界Y、短边沿X，适合X航带/Y换带；yaw90则交换。在FC高度1.4m、纯pitch5°时，光轴地面交点距FC正下方约1.4*tan(5°)=12.25cm。投影必须同时旋转光轴和16cm安装位移；只减高度会漏掉倾斜时的光心平移。

## 设计是否合理

分层设计合理：纯Python适合快速比较覆盖、航程、遮挡、有限载荷决策，成本远低于SITL。复用现有牛耕/A*/LOS，比为每条策略另造一套几何更易比较。记录场景适合发现旧分布过拟合。

但当前结果只支持几何预筛：

- 旧M0/M2使用2.4m、随航段转头、演示障碍、假设Cue概率。尤其M2升到3.4m水平直飞的绕障近似不适用于2026要求水平绕障的搜索验证，不能拿其计分/耗时直接推荐整机策略。
- `recorded_search_replay.py`采用实际布设、固定安装相机；A*仍拥有精确静态地图，无SLAM误差、过期点、重规划、控制跟踪、加减速/风场。
- 0.30m点路径净空是比较参数，不代表任意姿态的55cm方形机架有足够净空。其45°水平扫掠宽约0.55*sqrt(2)=0.778m；姿态敏感性中的“feasible”仍仅表示原点路径/固定膨胀模型可行。
- 四个圆环极点入画、五点遮挡门控只是近似，不等于完整圆环像素、YOLO识别或实际精修接受。单seed测得的0/1 Cue不能当精确概率。
- 当前布局采用生成器分布而非真实赛场分布；11套样本不能证明全局泛化，不能按同一组调参与验收。

## 本次更新与结果

新增installed_camera.py：世界/机体/光学变换、刚性安装位移、完整四元数；记录场景比较新增--roll-deg/--pitch-deg/--yaw-deg。默认仍是yaw0水平状态，未改变既有seed11五条策略结果。姿态参数为恒定敏感性条件，不是假装有动态飞控模型。

新增tools/analyze_recorded_attitude.py，读取既有t,x,y,z,qx,qy,qz,qw日志，统计姿态与运动方向差；不启动ROS或飞行。全仓57项测试通过，包含倾斜光轴地面交点、旋转不变性、yaw90视场交换、无效/向上四元数。

## 后续随机场景设计（尚未实现/启用）

1. 固定当前seed11 world、靶位、树箱、门与参数，先完整Gate通过；必要修复只针对首个失败阶段。不能边改地图边声称在复现同一基线。
2. 门只固定墙面X位置、总宽1.5m、开口0.8m和墙高；按用户2026-09-09最新确认，每扇门只取左开口或右开口，净宽始终0.80m；两扇门共左左、左右、右左、右右四种组合，不设居中或连续横移。1.50m通道中剩余0.70m为靠另一侧的短墙，几何生成时直接换边。机载链只能知道墙面先验，实际开口由雷达观测得到，不能从布设JSON给它航点。
3. 四组箱+树按复合几何一起移动，避开H、走廊入口和靶板；使用场内/不重叠/物理通行的规则约束，不以“当前算法能过”为拒绝采样准则。树冠尺寸/箱高随后单独引入测量支持的变化。
4. target_seed/gate_seed/obstacle_seed独立派生并记录布局，保留完全冻结的baseline fixture。先单因素靶位，再门，再树箱，最后联合；保留未用于调参的holdout seeds，统计所有失败，报告三投/两门/降落/零碰撞/耗时和首个失败阶段。
5. 随机化先在轻量仓验证生成器约束，再到相同几何的Gazebo；真值只进评测。几何随机之后才增加定位、跟踪、延迟、光照/反光误差，分清失败来源。只有多个维度和独立种子通过，才逐步支持泛化与鲁棒性结论。

当前最先要做的是seed11端到端验收，而不是扩大搜索策略和场景组合数量。
