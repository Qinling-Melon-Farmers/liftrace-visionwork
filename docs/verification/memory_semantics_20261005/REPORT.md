# 低空异类观测错误刷新旧类别确认：修复（2026-10-05）

## 已确认的原因

八轮固定2b0678b9中，seed38新矩形在碉堡上方将1号槽作为panzer模拟释放。ROS88.000s收到raw_actuator_ack，机体真值XY约(4.6741,-3.2965)，碉堡中心(4.6379,-3.2991)，约3.6cm；真实panzer在(7.0512,-4.1322)。这是执行了模拟释放，不是仅低空确认；没有模拟包裹弹道，机体距离不等于包裹落点。

低空mapped观测78.784s已经是pillbox，置信度0.9524、几何0.8326；候选id1却仍为panzer，last_seen刷新、连续计数继续增长。79.320s检测pillbox置信度0.9569，而旧候选仍输出confirmed panzer、streak56。任务79.359s复核放行，后续按错误标签投递。

根因是类别切换比较全生命周期累计票数，历史panzer积累压过新pillbox；与此同时确认计数按物理位置连续可见累积，没有绑定当前类别。低空重新确认只看到候选中的旧标签，未看到原始异类证据。

## 为什么之前的类似处理没挡住

此前HighViewFull._resolve_low_location已经实现“同一位置低位确认异类→替换假设→不投已被否定的类别”；test_conflict_verification直接构造新鲜pillbox候选验证这条链。问题在更上游的视觉记忆：正确检测没有及时成为正确候选。之前针对短暂类抖动的测试只有少数历史帧，没有覆盖长时间高位历史+低位新证据。因此不能说此前没有纠正机制，也不能说低空YOLO一直识错。

本批23次模拟释放逐次按释放时机体真值最近靶位核对，仅此1次标签/靶位不符。其他轮次存在高空panzer/pillbox误线索，但最终释放地点匹配；seed38双线、三线均记录低空改判pillbox并跳过，三线随后在补搜阶段碰树，不是误投。

## 代码修正

- 连续确认只计同一观测类别；异类新帧不能刷新旧标签的可用地图状态与确认计数。再次回到旧类也要重新满足3帧确认。
- 切换仍沿用2帧、0.70和票比1.0条件，改用连续挑战证据与有界原类别支持比较，避免历史观测越久越难纠正。未降低YOLO/圆环准入阈值。
- 物理ID合并不再用历史票数重新指定当前类别。合并遇类别冲突则重新确认，防止旧记录使旧标签再次可用；不把两个记录的命中数量相加冒充新帧。
- 物理坐标与ID记忆保留；消息格式不变，不删除其他位置的同类目标。
