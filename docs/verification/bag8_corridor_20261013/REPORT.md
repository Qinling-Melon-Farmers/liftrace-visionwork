# 10月12日晚（8）实飞：第一门倒退碰撞与投递时序

记录日期：2026-10-13。输入为 `试飞产物/flight_debug_0 (8).bag`，222.50秒，2026-10-12 23:47:54.64起。现场确认：倒退碰到第一道内部门，之后飞手切POSCTL。本次仅离线分析，没有修改飞行代码、参数或部署。

## 结论

本轮三次机构软件回执成功，随后走廊下一航点及其邻域被规划器判为占据，未生成新轨迹。规划/最终控制持续发布同一个保持点，飞机在该点附近出现约14.7cm反向摆动，等待12秒后任务ABORT。**没有发现任务重新派发上一扇门、脱困主动倒退或旧轨迹把飞机带回的证据。**

避障检查有工作：它拒绝了占据目标。缺口在于这种拒绝没有形成能从门边安全继续/退出的动作；保持点也没有保证具有足够机体与跟踪余量。现场碰撞事实与这段倒退相符，但bag无法唯一确定接触瞬间及碰撞前整个机体是否已完全通过门。

## 地图、前视与执行链

- 门口必要航点均存在，不能把本轮归咎为运动优化再次合并了门前后点。
- seq15邻域调整向较大Y移动0.1m，可能减小通过侧余量，但缺真实门平面坐标，不能直接认定这一调整导致碰撞。
- seq16目标在到达前已有膨胀占据；195秒附近切片也显示目标邻域被占据。203.489秒一度起点不占据，目标仍占据，依然无法规划。
- bag只有`/sdf_map/occupancy_inflate`，没有原始或FreeDOM实体点云，不能区分实体膨胀与虚拟柱，更不能据此清空占据或断言真实门宽。
- 实际走廊开阔档前视0.6m持续到失败，ABORT后0.4m。输入墙位置Y=[0,−1.4]；其与现场门平面是否一致须实测确认，不能从膨胀云直接反推可飞航点。
