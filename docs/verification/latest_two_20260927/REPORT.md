## 地图诊断：已知事实与尚待验证项

1. 参数快照虚拟顶棚为3.13m；目标2.38m低于它。搜索XY边界内也包含此目标。因此不能直接归咎于目标超出配置高度或场地。
2. 首次失败保存的局部static_map点云中，距目标最近的三维点分别约1.0994m和1.0991m，位于起飞后墙附近。这一局部快照未显示目标附近真实物体；它不是完整时序点云，也不是内部占据数组。
3. inflated_map采样两轮均超时，缺少当时内部占据的直接快照。不能仅凭局部点云就声称已准确重建全部错误体素。
4. 源码发现高度相关风险：MiddleHeightColumnSelector对每个XY连通结构的中部轮廓取凸包并填充；结构筛选只依赖几何竖向支持，不区分树和墙。连通的U形墙若组成同一结构，凸包会填满其内部空地，再向上建柱。这与“低处能到、升高目标占据”的表现相符。
5. 使用当前C++头文件离线复现：三面连通墙，中间无任何输入点；forEachFootprint仍输出中间测试点，合计填充30951格。见wall_hull_probe.cpp/json。**这确认了算法存在此失效机制，但仍是合成几何复现，不是两轮实时完整地图的等价重放。**

优先下一步：让轮廓补实仅适用于可信紧凑树冠，墙体/过大连通结构保留真实三维占据和局部向上延伸，避免对开放墙围合区域作凸包填充；补连通墙、树靠墙、多树粘连和缺失中部回波的离线回归。随后先验证此升高段，再验收完整链。不要先降低膨胀或延长超时掩盖问题。

本轮未修改运行代码、地图参数、视觉门槛或模型，也未启动第三轮仿真。
