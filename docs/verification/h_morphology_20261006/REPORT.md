# 实拍H形态主判据优化（2026-10-06）

本次修改只属于视觉检测，不改另一对话负责的AUTO.LAND/POSCTL控制交接。原分析阶段只做本地验证；后续已完成板端部署与ARM复跑，详见[部署与同步记录](DEPLOYMENT.md)。本轮没有启动新飞行。现场只有一个终点H，不应让固定黑色HSV上限成为主判据。

## 数据与原因

源包：`logs/h_flight_review_20261006/board_landing_20261006_160434/flight_debug_0.bag`，101.41秒，464张轻量录制JPEG（约4.6Hz）；既有回放在同级`replay_160434`。现场已成功识别H并进入下降，但软件记录89.96秒人工接管及landing_failed，不能把检测成功表述为无人接管整场COMPLETE。

原黑色结构分割要求S≤90、V≤110。约64秒左H笔画实拍区域HSV饱和度中位107，明度中位40；固定S门槛把偏色黑笔画切碎。此轮主要缺口是分割而非缺少H形态、也不是应放宽释放/降落许可。

## 修改

- 新默认 `landing_h_segmentation: grayscale_otsu`：根据当前帧灰度分布分割深色结构，不以H色相/饱和度硬否决。`landing_h_min_contrast: 15`仅拒绝不足以区分深浅的图像；不是降低H身份要求。
- 原外圈候选、椭圆完整度/形状/内部结构检查保留；形态主路径增加显式两竖笔画、中央连接和上下凹口检查，不能仅因“有黑圈”接受。
- 外圈完整用椭圆中心；近距离外圈裁切仍走既有笔画兜底，中心由内部笔画边缘计算。兜底的启用由原入口负责，未取消其开关。
- 深色mask每张图只生成一次，供外圈H检查和兜底复用。保留 `legacy_hsv` 作明确离线对照/回退。
- 没有跨帧沿用旧中心、没有补造检测、没有改变原10新帧/8cm/0.5秒条件、没有改变质量评分下限、控制/投递/降落状态机。
