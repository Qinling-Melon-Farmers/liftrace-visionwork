## 2. 投递主流程

`类别/几何确认 → 冻结靶心和补偿后的FC目标 → 保持捕获高度完成水平补偿 → 固定XY下降 → 当前高度合格且许可有效即调用 → 调用后0.5秒开始投后恢复`

### 2.1 捕获、冻结

- 类别匹配当前目标，目标确认状态及几何有效；类别和几何置信度均至少0.60。
- 距相机主点的像素误差不超过30px；累计5张不同时间戳的新图像。不是反复收到同一帧就算5帧。
- 当前观测年龄不超过0.50秒；旧帧短暂过期先停止ready，但同动作的既有确认计数可保留至1.0秒间隔；不把旧帧刷新成新证据。新帧明确不合格、身份变化等仍可重置。
- 12cm槽位表是机体系物理杆臂：后仓(-0.12,0)、右仓(0,-0.12)、左仓(0,+0.12)。FC目标XY=靶心XY−按当前完整姿态旋转后的杆臂XY。
- 目标从未补偿的靶心计算，不重复累加；已有边界检查必须允许补偿终点。冻结后不追低空残圈，未新增下降点云准入。

### 2.2 水平模式H1/H2

|模式|开始下降前的判定|
|---|---|
|H1|FC与实际姿态投口误差的较大者≤4cm，FC/投口水平速度较大者≤0.10m/s，持续1秒、至少3个新odom样本|
|H2（本轮使用）|同样取两项误差较大者；标准四类严格＜6cm，红十字严格＜4cm；当前有效反馈通过即开始下降，无速度上限或额外停稳时间|

反馈须新鲜且当前连接、解锁、OFFBOARD。H1/H2只是投递补偿模式，不能和H靶降落的vh/non_vh混为一谈。

### 2.3 D1～D4投递下降

|模式|指令|
|---|---|
|D1|冻结XY＋最终Z位置，经过通用三维目标距离限幅|
|D2（本轮使用）|冻结XY位置闭环＋随时间变化的Z位置目标；绕过通用三维领先限幅|
|D3|VX=VY=0＋Z位置斜坡；不是把机体持续拉回冻结XY位置|
|D4|冻结XY位置闭环＋垂直速度加速/制动；默认最高0.60m/s、加速度和制动0.60m/s²、距终点0.015m切回Z位置保持|

D2的1.5/1.0m/s是目标Z变化率，不等于飞机实测下降速度。D4参数在D2中不生效。反馈陈旧或控制权不满足时暂停斜坡，不补走断流期间的下降距离。已下降后水平误差反弹不会自动命令爬回捕获高度。

### 2.4 当前正常释放不是再次检查4/6cm

当前 `release_height_only: true`：先前已经过H2补偿确认，正常释放时不再用水平误差、低速度或0.30秒窗口阻塞。仍检查冻结目标/动作绑定、当前位置反馈、连接解锁OFFBOARD、动作期限、当前有效许可、槽位身份及防重复。

- 15:02本轮正常高度窗口是0.10～0.45m；进入该窗口即可具备高度条件，不必先到0.15m目标，也没有“必须曾到0.35m”的锁存规则。
- 08远端默认窗口上沿是0.43m，不能直接替代本轮0.45m。
- 文件中的 `settle` 标准10cm/红十字6cm、旧速度/稳窗值仍保留兼容，但当前height-only路径不拿它们作正常释放门槛。下降前的6/4cm仍生效。
- 正常使用冻结承诺、短时缺视觉时，检查承诺位置漂移≤20cm。正式带上下文链路按当前动作deadline约束，08目标动作预算60秒；配置中的45秒仅是缺少上下文deadline时的旧路径后备值，不应说成所有动作统一45秒。
- 控制器odom通常要求≤0.20秒；许可消息在控制器要求≤0.20秒，代理还核对版本/身份/有效期。任务状态和执行状态不是“高度到了就无条件开仓”。

### 2.5 两个需要明确的现存行为

**20秒兜底比“放宽水平精度”更宽。** 从首次真正开始下降计时，满20秒后，控制器绕过水平及高度窗口；许可节点也有独立timeout授权来源，在普通高度/冻结承诺漂移分支之前判断。仍须同一未取消动作、期限未到、冻结有效、新鲜位姿和OFFBOARD、对应槽未执行/未锁定。因此不能将它描述成“必须先到低空，20秒只放宽XY”。本轮未修改此行为。

**投后恢复不等待ACK。** 当前 `recover_without_ack: true`、`recovery_delay_sec: 0.5`，从客户端工作线程开始RPC计时；0.5秒后可推进恢复，无需先收到成功回执。调用尝试用于飞行顺序推进，但不伪造Servo成功ACK；真实回执另行记录。这也不是硬件证明货物已经脱离。

本轮红十字进入ALIGN至冻结约6.85秒，冻结至补偿达标约1.35秒；开始下降后约1.38秒飞手接管，当时AGL约0.63m，仍高于0.45m。后续许可虽成立，因已非OFFBOARD而未调用，不能归因于最终4/6cm门槛。

## 3. 当前H降落流程

`到H观察点 → 识别并持续修正H中心 → vh高位确认 → 冻结H坐标 → D2下降 → 低位高度窗口持续合格 → 请求POSCTL → 地面状态与任务收尾确认`

### 3.1 观测与高位确认

- H须有有效地图投影、几何确认、正确坐标系和新时间戳；相对LAND原始目标锚点偏差≤0.60m，观测年龄≤0.50秒。
- **vh（08和实际03）**：pose/odom水平误差取较大者≤6cm，水平速度严格＜0.10m/s，持续至少1秒、至少3个推进的odom样本；新鲜H才能完成锁定，不另叠加10帧条件。
- **non_vh（独立正赛默认）**：水平误差≤8cm累计10张不同的新H图像；超差/过期重置。当前这条调用路径没有额外速度/持续1秒门槛。
- vh中H观测年龄和间隔已与外层0.50秒对齐；之前内部200ms问题已修。odom年龄/间隔仍≤0.20秒；FC State/ExtendedState有效期已为2.5秒以适配约1Hz反馈。
- 冻结后守住H坐标，不因低空看不全H改追新中心或回升观察高度。

### 3.2 低位POSCTL交接到底看什么

本轮/08：目标AGL0.35m、上限0.50m、高度容差0.05m。实际检查odom高度在 **[0.30,0.50]m**，pose也须不高于0.50m。连续至少0.15秒、至少3个不同odom时间戳、间隔与新鲜度≤0.20秒，且H已锁定和控制权有效，才请求POSCTL。

**当前低位交接已不检查XY误差、水平或垂直速度。** YAML里仍有5cm、0.10m/s等字段，它们不作为这一步阻塞条件。此变化适用于D1～D3，不是D2单独豁免。因此不能声称本轮仍要求“低处中心停稳后才切换”，也不能声称一定下降到0.35m才交接。

独立正赛默认目标同为0.35m，但上限0.40m，所以对应低位区间为[0.30,0.40]m。

服务接受请求不代表模式已切换；还要观测实际POSCTL，转换等待2.5秒、失败每1秒重试。Bridge另保留0.5秒交接事件等待，用于处理状态与事件的到达先后，不是H图像年龄或落地总时限。

### 3.3 其他降落方式与完成标准

H D1、D2、D3的水平/垂直指令含义与投递同名模式相似；**H D4与投递D4不是同一种功能**。H D4是保持冻结XY的OFFBOARD直接下降至触地：默认垂直速度0.30m/s，须本次先见IN_AIR、再见ON_GROUND持续至少0.30秒和两个新样本，之后普通上锁并观察实际未解锁；不是仅凭低高度强制停机。默认最低反馈护栏为静置FC高度−0.04m（按0.22m静置值即AGL0.18m）。本轮未选择/验证D4。

当前08使用POSCTL，不是AUTO.LAND，也不是D4直接触地。POSCTL只是交接，后续由飞手油门输入控制下降；任务还要观察本次LAND后的有效地面状态等才能判完成。不能将“切入POSCTL”写成“自主落地已经完成”。
