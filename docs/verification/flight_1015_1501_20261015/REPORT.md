## 2. 为什么有类别争议却仍然中断

原始JPEG人工核对：约61秒画面中的圆环板中心是地堡图案；它在同一位置被交替识别为panzer和pillbox。图中标签来自原日志；录图约5Hz，与检测最近图像时间差已标注，示例不是精确同一曝光帧重新推理。

本轮高位线索接纳窗口是 **1.8～2.2m**。错误panzer入库时高度在窗口内，稍后的正确pillbox超过上限约1.5～2.3cm，未进入任务导航记忆。中断时保存的panzer坐标为约 **(1.815,−2.503)**，正是地堡所在处；支持来源为bbox，两个独立源图像时间相差约0.429s，符合0.1～1.0s、位置一致性0.5m的现行规则。旧线索被保存为重访知识，约21秒后仍可参与中断，不要求三类刚好在同一帧出现。

因此，程序没有登记到双方有效类别冲突。当前 `navigation_memory.py` 本身有同位置异类/多位置同类冲突处理，但被前置高度规则拒绝的观测到不了这一层。这里同时存在模型混淆与任务接纳衔接问题，不能简单解释成“冲突保护被删了”。HINT已是0.75，提高到0.75不是新修复；0.864的错误也证明单靠置信度无法处理这轮。

58～80秒原始YOLO记录中，所见地堡位置有59次panzer输出与9次pillbox输出（消息数量，不是独立人工标注召回率）。此外选帧还看到机体遮挡部分被判为panzer、桥梁画面短暂被判为panzer；没有将这些额外误报都归因到本次中断。中断所用panzer坐标已单独核对。

源码参考：导航0928 `af599680` 的 `high_view_full.py:174–221`、`high_view_probe.py:168–200`，以及 `vision_ws/src/uav_high_view/src/uav_high_view/navigation_memory.py`。前者先过滤高度，后者只能处理实际进入记忆的观测。

## 3. 低空复核失败后，会不会续扫

**本轮开关为true，并保存了剩余高位航点；能力仍在，但不是每次复核失败立即升高。**

当前流程是：低空重访与类别复核；新鲜、有效的低空证据可把错误panzer位置纠正为pillbox并清掉对应旧假设；无有效复核则退役该位置。先处理其余可用目标和已有局部复核；已知目标耗尽、仍有缺失的高价值类别和空仓时，尝试一次高位续扫，重新接上保存的剩余航线。续扫还要求没有进行中的动作、位姿新鲜、当前可返高通道成立、剩余预算至少10秒；续扫预算最多90秒且不延长600秒总期限。无法续扫时走原低空覆盖兜底。

代码路径：`_resolve_low_location()`、`_defer_selected()`、`_start_fallback()`、`_try_resume_survey()`；续扫尝试只有一次。不能保证任何复核失败条件下都一定返高。

本轮停在首个red_cross，尚未低空复核地堡。`resume_attempted=false`并不表示开关没开，而是流程还没走到那里。当前bag不能证明低空复核一定能纠正，也不能证明续扫已经失效。

## 6. 红十字为何没投

冻结中心约(2.137,−0.273)，冻结FC目标约(2.256,−0.261)，第一槽为后仓，FC向前补偿约12cm，方向与后仓安装向量一致。本轮没发现再次累加补偿或低空追残圈。下降前FC误差3.76cm、投口误差3.81cm，通过红十字4cm检查。

118.927秒开始下降；120.309秒飞手主动切POSCTL，FC估计AGL仍约0.63m，高于0.45m释放上限；120.578秒任务许可才为true。随后控制器记录 `geometry=false / permission_active=true / fresh=true`，现行释放仍要求连接、解锁且OFFBOARD，因此接管后不执行新投递是正常行为。

本版日志明确 `release_xy_check=disabled`：已先完成补偿，末段不再以4/6cm水平误差卡住；不能把这次未投重新归因于严格水平门槛。没有成功释放回执，槽提交数0。接管之后的下降/接地不算自主投递或H降落验收。

0.15m目标比本轮静置FC离地参考0.22m低7cm；若投点与起点支撑面同高，目标低于接地FC位置。下降参数1.5m/s不是实测速度：接管前FC速度记录最大向下约0.90m/s。配置与此前0.40m约定不同，应先核实/恢复所需的现场目标，而非继续降低。此轮仅分析，未改板端高度、速度或模型。
