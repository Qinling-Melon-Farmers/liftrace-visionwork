## 为什么R60没有、R61静态展示没有发现

R60实际MID360 SDF是publish_pointcloud_type=1，与SITL FAST-LIO lidar_type=4所需PointCloud2匹配。R61新装配从另一模型复制时保留了type=3，发布livox_laser_simulation/CustomMsg，初次日志明确拒绝连接。它是仿真配置回归，不是新相机应当独立转向，也不能归因于实机硬件。

R60原保守护圈不是落地支撑；R61改成55×55×40cm实体包络后，通过1g独立link/固定关节承担接地约束，叠加新安装几何发生未解锁滑移。先前预览主动固定机体并移除飞行/传感器插件，只验证外观与16/21/6cm位置，不能覆盖消息连接和动力学。

## 已作修复及重试暴露的新错误

1. Gate原本仍继承旧8m边界，已按当前9.6m内场校正，防止合法位置被误判越界；门宽/碰撞/限高未放宽。
2. 雷达改回PointCloud2。重试中类型已经接通；但点云仍不可用。
3. 同尺寸保守碰撞体直接附着主base_link，1g质量并入主刚体，去掉独立微小质量支撑关节。重试真值机体在起飞H附近保持稳定，初次米级滑移未再出现。这不是完整动力学/接触验收。
4. 原计划让闭合的雷达CAD自身外壳不遮挡内部激光原点，同时保留外壳实体碰撞。但本次插件没有成功加载，不能声称该射线设置已生效。

重试的直接集成错误已由Gazebo服务器日志和离线SDF展开确认：[服务器日志](attempt2/gazebo_default.txt)报`Contact envelope link is missing`，随后说明该插件不会运行。Gazebo将include展开成`iris::base_link`和`mid360::lidar_link`；补丁却用`base_link`、`lidar_link`查找，未匹配展开名。这是本次重试补丁中的命名错误。

因此接触心跳为0、ready=false，不能把碰撞计数0当作零碰撞验收；包络/自身外壳的射线排除也未执行。只读抽查一帧20000点，只有6点超过0.2m，最远0.3762m，全部小于现有0.5m盲区，LIO持续报Too few input point cloud/No point。结合仍不透明的包络包围激光原点，可以定位为自身遮挡链未正确建立。没有通过降低盲区、关闭接触检查或放宽启动Gate来掩盖。

飞控估计位置也发散，尽管Gazebo机体本身停稳；修复有效点云后还须重新核查IMU/估计状态，不能据外观稳定宣称传感器动力学均已正确。启动早期EKF2_BARO_CTRL暂未同步的警告在R60成功轮也存在，且当时最终参数读回成功，不能仅据此认定固件不支持该参数。
