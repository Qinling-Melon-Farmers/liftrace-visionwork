## 当前避障能做什么，缺什么

两轮都保留了门前后航点，运动优化没有再次把必要点合并。规划器会查占据、找邻近自由目标、拒绝失败路径，不能简单称为避障没开。

但“保留门口航点”没有约束整段穿门曲线，也没有要求邻域调整后的点必须处于门的正确一侧。规划可能绕行后折回目标，实际又叠加跟踪误差；一旦进入占据区域，现有普通搜索和首次规划失败的保持方式没有完成安全退出。门边持续保持并不等于处于安全净空中。

新（6）192～221秒LIO输出年龄中位33ms、P95 54ms、最大82ms，队列为0；没有这段LIO超时断流证据。两轮只有膨胀图，缺FreeDOM原始实体云，不能区分真实门框、安全膨胀与虚拟柱。膨胀图可指出现有打点/轨迹与当前地图不相容，不能直接给出可用于实飞的新门洞中心坐标。

建议优先级：

1. 各门分别实测门平面和中心，不把所有门中心X固定成一条线；前后点与门洞法线一致，并留出机体完整通过及跟踪超调余量。
2. 保留必要点之外，再约束穿门段和目标邻域调整的侧别，避免已经通过门后为追旧终点重新折回。
3. 对当前起点占据/首规划失败，按当前地图验证安全退出或继续的短路径；不能把无人机起点虚移到自由区、清空实体占据，或无检查退回历史点。
4. 不以扩大前视或延长12秒等待代替上述问题处理。要验证的是整段路径及真实通过后净空，而非“没有ABORT”。

这些均为本轮建议，没有擅改代码或参数。新（6）现场是否发生接触尚无用户确认，本报告不把地图占据或画面接近门框直接算作碰撞。

## 新（6）投递为何更久，超时许可能省哪一段

### 用户认可的低空超时许可

用户已明确：低空等待门槛时精度总体可接受，许可保留。本轮按此处理，不撤销、不修改。

新（6）三次正常ACK成功，所有释放日志`release_xy_check=disabled`，**没有强投许可或强投日志**。元数据未记录实际timeout开关/秒数，不能将远端最新默认20秒当作当轮已启用，也不能仅凭没有日志断言板端完全没有该代码。

可以借鉴去年固定目标下降、减少重复复核的思想；本轮已经没有低空追残圈和释放XY门槛，继续优化应优先针对实际多余的稳定等待、整链一致的高度范围及低空超时执行，而不是重写视觉或单纯增加下降速度。

识别关联方面，新（6）没有记录同一目标ID类别切换或投递上下文特定类别冲突；下视关键画面与桥梁/车辆/红十字顺序相符。未做逐帧人工标注，不将其写为五类零误识别。详细数据见[投递专报](../../../试飞产物/bag6_20261013_analysis/DROP_REVIEW.md)。
