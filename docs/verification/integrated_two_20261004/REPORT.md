# 最新整机链两轮仿真与靶心误差复核

日期：2026-10-04。正式运行来源：`feat/r2026-competition-integrated@4cb75a3b`。两轮正式运行均完成并通过。

## 本次到底验证什么

使用当前整机代码、五分类模型和历史 seed31/38 场景，验证高位粗线索 → 低位重访 → 模拟投递三次 → 两门走廊 → H 视觉降落。障碍柱开启，水平膨胀 0.25m、上 0.20m、下 0.10m；虚拟顶棚关闭。两轮串行运行，未连接实机、未驱动真实舵机。

本轮使用研究场景的整机仿真入口，不能等同于对独立硬件 `competition_application.launch`、现场 TF、真实 RC 或 PX4 外部定位超时恢复的验收。此前集成的 H 反光处理、降落模式暂停 YOLO、观测时间戳和相机高度换算等代码参与本次运行；手动模式切换和接管互锁仍需要相应地面/实机验证。

## H 高度、80cm 资产和笔画兜底

- 本轮两组研究场景的有效 `external_landing/capture_height=0.68`，这是本地坐标 Z；`ground_z=-0.22`，对应约 **0.90m 飞控中心离地高度**。高位巡航仍为 2.6m AGL。未修改降落观察高度或 1.2m 的走廊/H 验收高度门槛。
- 通用控制 YAML 的 1.60m 被场景覆盖；独立正赛入口 `deployment/competition/field.example.yaml` 的 `landing_capture_agl: 1.8` 是另一份示例配置，既不是本轮有效值，也不能称为研究分支统一使用的正赛高度。
- 研究入口原本启用 `landing_enable_h_stroke_fallback=true`。本次准备过程中错误地额外覆盖成 false，试图对齐独立入口默认值，导致诊断轮近距离标准 H 漏检；该覆盖已撤销。不是为了这次通过而新增宽松算法。
- 单帧生产 C++ 算法对照：外圈半径约 356.5px，大于 300px 上限；仅关闭笔画兜底时未检出，仅恢复兜底时检出中心 `(635, 377.5)px`。详见 [同帧诊断](H_FRAME_DIAGNOSTIC.md)。这说明保留原有近距离补充路径有实际作用，不能用升高飞行高度替代此次回归核查。
- 起飞 H 与终点 H 都使用 0.8×0.8m 的视觉面和碰撞几何。场景显式引用唯一名称 `landing_h_80cm`，避免 Gazebo 优先读到 PX4 外部模型目录中的旧 1m 同名资产；标准 H 纹理不变。

两轮准备/诊断记录保留但排除正式结果：`002834` 为旧同名 H 资产遮蔽检查；`003709` 为错误关闭兜底的诊断轮，虽三投并通过走廊，但未完成 H 降落，不能算通过。

## 统计口径

任务时间从任务启动被接受计，以 ROS 时间统计，不含前置准备；视频通过实际帧时间戳对齐，重复保持画面会明确标示。慢于实时的 WSL 仿真墙钟时间不当作飞行耗时。

靶心分析使用记录的映射点、融合记忆、选中目标及当时的高位线索，与场景真值比较 XY。按观测时间去重，排除无效、陈旧数据；高位首次线索不能从已被低位更新的最终记忆反推。分类错误造成的远距离单独列出，不能全部解释为投影误差。没有观测的类别记为缺测，不记作零误差。

H 视觉中心误差、飞控中心落地误差、释放时机体位置误差和快递盒落点是不同指标。本次没有真实抛投物理落点验收，不以模拟舵机 ACK 代替落点精度。

## 尚不能由这两轮证明的事项

- 独立硬件入口与研究入口的 H 默认配置仍有差异，尤其是示例的 1.8m 与笔画兜底配置；本轮验证的是明确记录的研究场景参数，下一次上板需使用已核对的现场配置。
- 零接触不等于机体投影完全不越过树木最大轮廓。seed38 的机体中心没有跨入离线树体＋底座水平凸包，但旋转后的55cm包络仍有72个插值采样与该凸包重叠，最深约23.6cm；seed31无此重叠。当前使用的是已约定的树冠中部建柱、允许经过下部外缘上方的口径，不能把PASS另行解释为最大树冠投影全禁飞验证。详细结果在各轮 body_projection.json。
- 未模拟真实 LIO 延迟、外部定位融合停启及高度重置。日志存在 MAVROS 时间同步重置提示；不能把本轮完成任务解释为已根治实飞高度跳变。
- 标准无反光 H 的两轮动态回归通过，不代表所有反光、遮挡、不同曝光场景都通过。H 离线反光修复证据与本次标准 H 回归应分别使用。
- 真实舵机、RC 模式切换/接管、板端性能和现场外参没有在本次硬件验收。飞机断电后未部署新内容。
- 原始逐帧导出和视频仅保留本地；Git 中保留脚本、场景、摘要、图表和可复现说明。
