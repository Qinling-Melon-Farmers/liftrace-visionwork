## 1. 原需求复述

视觉组对导航组下发需求的理解如下；本节只压缩表述，不改变原文语义。

1. 评测目标不是单帧 YOLO 召回率，而是完整 operational chain 在高度 `h`、实际速度
   `v`、横向偏差 `d`、相对方向 `ψ` 和类别 `class` 下的 `P_confirm`、`P_interrupt`、
   `T_confirm` 与 `E_map`，供导航选择搜索高度、速度和航带间距。
2. “稳定候选”必须类别正确、达到 `CONFIRMED`、地图和关联有效、无拒绝原因、观测年龄
   不超过 0.5 s，并满足当前连续 3 帧确认；`/uav_vision/targets` 中存在合格候选和该候选
   成为 `/uav_vision/selected_target` 必须分开统计。
3. 本轮正式统计 `tent/pillbox/bridge/panzer/red_cross`。`tank` 只作兼容或压力样本单列，
   是否纳入正式统计由双方冻结的规则 profile 决定。
4. 实验依次分为：A 五类×五高度静态基线；B 五类×五高度×四速度中心线主矩阵；C 中心到
   部分出画的归一化横向偏差；D 偏航、加减速、转弯、角速度和多目标 stable ID/排序压力。
5. 真值必须独立于检测器；每个样本需记录 seed、目标真值、相机位姿、实际线/角速度、
   CameraInfo/TF、目标是否完整入画、各处理阶段、地图误差、候选状态、选择结果和延迟。
6. 输出需覆盖 `P_raw_detection`、`P_geometry_association`、`P_map_valid`、
   `P_confirmed_candidate`、`P_selected_target` 和 `P_interrupt`，以及精确率、召回率、
   FP/frame、输入覆盖率、延迟、地图误差、过期、TF/CameraInfo、类别、关联和重复 ID；失败
   必须定位到具体处理阶段。
7. 实验顺序应先静态，再高度×速度，再关键横偏，再视角/动态/多目标，最后实拍和 OrangePi；
   Gazebo 固定 seed 是可复现基线，不能代替实拍与板端 ROS 链。
8. 每轮必须冻结模型/backend/类别表、imgsz/conf/NMS、几何与 memory 阈值、确认和新鲜度、
   相机分辨率/帧率/曝光、CameraInfo、外参、运行平台、实际 FPS 与处理器负载。
9. 每轮交付 `manifest.json`、`frames.csv`、`events.csv`、`summary.json`、`report.md` 和便于
   导航读取的 `vision_search_performance.csv` 聚合性能表。
10. 导航组将以这些数据选择航高、航速、航带宽度与重叠率，估计漏失概率和下降复核时机，
    并平衡覆盖收益、得分、时间和风险；最终应得到有适用边界的性能曲面，而非单次演示。

## 6. 新相机 CameraInfo 的交付方式

本节保留 2026-08-29 的方法备忘；用户现已在仓外完成内参标定，待文件验收与接入状态见第
12 节。

新相机内参不以 GUI 为前置。视觉组将使用最终运行分辨率和成像链拍摄棋盘格或 ChArUco
图片，再由离线脚本检测角点并求解内参/畸变，输出 ROS CameraInfo YAML。GUI 只可作为
实时观察角点与画面覆盖的采集辅助，不是标定算法或验收的必要组成。

标定前必须冻结分辨率、裁剪、binning、焦距/对焦、曝光和 ISP 模式；交付至少记录棋盘格
内角点数、方格实际尺寸、有效图片清单、相机模型、`K/D/R/P`、图像尺寸、重投影误差和
独立图片复核结果。广角/鱼眼镜头使用对应模型，不能强行套 `plumb_bob`。相机固定上机后，
`camera optical frame → body frame` 外参由视觉与飞控/结构组结合最终机架另行标定，导航组
确认 `body/mission frame` 的 TF 消费合同；外参不能由内参脚本代替。

- `pillbox@3.6 m` 首阻断为 `raw_classifier`，应通过高空小目标数据/训练改善，不全局降低
