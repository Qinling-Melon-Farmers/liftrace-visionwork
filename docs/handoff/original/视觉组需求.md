## V-SIM-04扩展需求：高度—速度—横向偏差下的稳定候选性能评测

### 1. 背景与目的

导航组目前已经跑通：

```
覆盖搜索
→ /uav_vision/selected_target触发中断
→ 候选接近
→ 恢复搜索
```

下一步需要优化搜索高度、速度和航带间距。为此，我们需要视觉组量化完整 operational chain 在不同飞行条件下产生可靠候选的概率，而不只是报告单帧YOLO召回率。

希望最终得到可供 `uav_mission` 查询或拟合的数据：

```
P_confirm(h, v, d, ψ, class)
P_interrupt(h, v, d, ψ, class)
T_confirm(h, v, d, ψ, class)
E_map(h, v, d, ψ, class)
```

其中：

- `h`：相对目标平面的飞行高度；
- `v`：无人机实际水平速度；
- `d`：目标相对航迹中心线的横向偏差；
- `ψ`：目标相对相机/机体的方向；
- `class`：目标类别。

本实验属于视觉性能量化，不要求视觉组实现搜索路径、Planner goal或任务调度。

### 2. 稳定候选与中断成功定义

不能把“YOLO在某一帧检出目标”直接算作中断成功。

建议分别统计以下阶段：

```
目标完整入画
→ raw detection正确
→ resolved detection有效
→ 圆环/红十字几何关联有效
→ center_refined
→ map_valid
→ target_memory连续确认
→ targets中出现可操作候选
→ selected_target成功发布
```

导航组需要的“稳定候选成功”定义为：

```
class_name正确
state >= CONFIRMED
map_valid == true
association_valid == true
reject_reason == ""
now - last_seen <= 0.5 s
连续确认达到当前confirm_frames要求
```

当前配置为连续3帧确认。请同时记录：

- `/uav_vision/targets` 中是否产生合格候选；
- 该候选是否成为 `/uav_vision/selected_target`。

两者需要分开统计，因为多目标排序可能使合格候选存在但未被选中。

### 3. 正式评测类别

按照2026正式PDF，本轮比赛搜索性能重点统计：

```
tent
pillbox
bridge
panzer
red_cross
```

当前六分类模型中的 `tank` 可以继续作为兼容类或额外压力样本单独报告，但请不要把 `tank=5` 纳入正式比赛得分或总体比赛目标统计，除非后续有比正式PDF更新且可核验的补充规则。

### 4. 建议实验分阶段进行

#### A. 静态高度基线

无人机/相机静止，目标位于画面中心，首先测量纯高度影响。

建议高度：

```
1.2、1.8、2.4、3.0、3.6 m
```

每个类别、每个高度使用固定seed重复运行，统计：

- raw detection recall；
- geometry association rate；
- map-valid rate；
- confirmed-candidate rate；
- map error；
- end-to-end latency。

#### B. 高度—速度主矩阵

保持目标接近航迹中心，执行直线匀速飞越。

建议速度：

```
0.5、1.0、1.5、2.0 m/s
```

与上述高度组合，记录：

- 目标进入、离开有效视野的时间；
- 完整入画持续时间；
- 实际处理帧数；
- 正确检测帧数；
- 最大连续有效帧数；
- 首次正确检测时间；
- 首次确认时间；
- 是否在离开视野前产生CONFIRMED候选；
- 是否成功发布selected_target。

重点输出：

```
P_confirm(h, v, class)
P_interrupt(h, v, class)
T_confirm(h, v, class)
```

#### C. 横向偏差实验

在选定的代表高度和速度下，改变目标相对航迹中心的位置。

建议不要只用固定米制偏差，而同时记录归一化画面位置：

```
中心
半视场半径的25%
50%
75%
接近画面边缘
部分出画
```

输出：

```
P_interrupt(h, v, d, class)
```

这组结果将直接决定搜索航带间距和允许的有效视场重叠率。

#### D. 视角与动态压力实验

在代表性的高度—速度组合上增加：

```
偏航：0°、45°、90°、135°
运动：匀速、加减速、转弯
角速度：记录实际值
场景：单目标、同类双目标、不同类双目标、目标与H同帧
位置：中心、四象限、边缘、部分出画
```

多目标场景需要报告：

- 每个物理目标是否进入 `/targets`；
- stable ID是否保持；
- 是否发生ID合并或重复ID；
- 是否发生错误实例关联；
- `selected_target`排序结果；
- 高优先级旧目标是否长期遮蔽其他新目标。

### 5. 真值与记录要求

请沿用 `uav_vision_eval` 的独立真值原则：

- 真值不能来自检测器输出；
- 每个场景保存固定seed；
- 记录实际相机/无人机位姿；
- 记录实际线速度和角速度；
- 保存目标真实位置、类别和几何中心；
- 保存CameraInfo、TF有效性和时间戳；
- 延迟使用墙钟口径，不能用Gazebo `/clock` 代替算法墙钟延迟；
- 单独记录输入覆盖率，不能只在“实际完成推理的帧”上报告高召回率；
- 基础设施失败、TF失败和算法失败必须分开归因。

建议每个样本至少记录：

```
seed
class
truth position
camera pose
height
linear velocity
angular velocity
normalized lateral offset
yaw
truth_fully_in_frame
raw detected
resolved valid
association_valid
center_refined
map_valid
map_error_xy
candidate state
consecutive_observe_count
selected_target
first_detection_latency
confirmation_latency
reject_reason
```

### 6. 必须提供的分阶段指标

除总体成功率外，希望输出以下条件统计：

```
P_raw_detection
P_geometry_association
P_map_valid
P_confirmed_candidate
P_selected_target
P_interrupt
```

并报告：

- precision、recall、FP/frame；
- input coverage；
- P50/P95端到端延迟；
- P50/P95地图XY误差；
- 首次检出时间；
- 首次确认时间；
- 连续有效帧数分布；
- candidate过期率；
- TF/CameraInfo失败率；
- 错误类别率；
- 错误实例关联率；
- 重复stable ID率。

失败必须定位到具体阶段：

```
YOLO漏检
类别错误
圆环/红十字关联失败
center_refined失败
TF或地图投影失败
连续确认不足
0.5 s新鲜度超时
多目标排序未选中
```

### 7. 实验顺序建议

为避免一次性全因子组合过大，建议按以下顺序收敛：

```
静态高度基线
→ 高度×速度中心线矩阵
→ 选取临界组合测试横向偏差
→ 视角、转弯和多目标压力测试
→ 真实相机/板端复核
```

第一轮可以先使用固定Gazebo场景和固定seed建立可重复基线；但Gazebo结果不能替代实拍回放和OrangePi完整ROS链验证。

### 8. 环境和版本冻结

实验开始前请共同确认并记录：

- 正式PT/RKNN模型路径、版本和类别表；
- `imgsz`、confidence及NMS参数；
- 圆环、红十字和memory阈值；
- `confirm_frames`和`selected_max_age`；
- 相机型号、分辨率、帧率和曝光；
- CameraInfo是否属于当前相机；
- 相机—机体外参；
- dev/sim还是OrangePi；
- 完整链实际输入FPS、处理FPS和CPU/GPU/NPU负载。

当前仓库中的1920×1080内参只能视为历史标定，需要确认是否适用于当前相机。

### 9. 希望的交付物

建议沿用现有评测资产格式，每轮输出：

```

events.csv
summary.json
report.md
```

另外增加一个便于导航组直接读取的汇总表：

```
vision_search_performance.csv
```

至少包含：

```
class,height,speed,lateral_offset,yaw,

p_confirm,p_interrupt,
mean_confirm_time,p95_confirm_time,
mean_map_error,p95_map_error,
input_coverage,p95_latency
```

### 10. 导航组最终用途

这些数据将用于：

- 选择低空主搜还是高空主搜；
- 计算不同高度下的有效航带宽度；
- 确定搜索速度上限；
- 设置航带重叠率；
- 估计目标被漏过的概率；
- 决定何时触发下降复核；
- 比较单位时间覆盖收益与稳定确认概率；
- 建立比赛得分、时间和风险联合优化模型。

我们希望得到的是带适用边界的视觉性能曲面，而不是单一的“推荐飞行高度”或单次成功演示。
