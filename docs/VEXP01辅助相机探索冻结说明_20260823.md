## 1. 决策

即日起冻结斜下辅助相机架构探索，不继续 Step 3 辅助 YOLO、Step 4 单 YOLO 双输入调度或
Step 5 全随机双相机 A/B。生产和比赛准备统一回归：

```text
单个下视 RGB 相机 + MID360/飞行位姿
  -> 六分类检测
  -> 圆环/红十字/H 几何精修
  -> 地图投影
  -> stable ID 与目标记忆
  -> 候选队列/搜索恢复
  -> 下视重捕获、对准与 release_evidence
```

本决策不删除任何实验代码、日志或分支。辅助相机提交从未合入 `main`，所以主干本来就是
单下视相机模式，不需要回退生产代码。冻结点保留在：

- `feat/oblique-camera-search-feasibility@b60a4d9`；
- `feat/oblique-active-search-stability@ab6e447`；
- `feat/oblique-aux-proposal-provider@3f2e55a`。

只有比赛规则、场地尺度或单下视覆盖实测明确证明无法在时限内完成时，才重新评审这些分支；
不得仅因“第二相机可能更快”恢复开发。

## 2. 辅助相机方向冻结时完成度

原路线共 5 个阶段，完成 Step 1 和 Step 2，按里程碑计为 **2/5（40%）**。这表示可行性
原型和接口抽象已经存在，不表示比赛级双相机方案完成。

### 已完成

1. 45°/55°/60°斜下 RGB/RGB-D 派生机架、相机话题与固定姿态评测入口；原下视相机未改。
2. 单目射线—地面求交、深度 ROI、单目回退、粗地图点和辅助候选记忆 L0。
3. OpenCV 蓝环匿名粗发现、覆盖 shadow、无 GUI A/B 与零控制/释放输出保护。
4. 辅助候选 stable ID 和
   `DETECTED -> APPROACHING -> VERIFYING -> CONFIRMED/REJECTED` 生命周期。
5. 辅助粗候选到下视候选的新鲜空间交接；强制轮已有 2/2 交接证据。
6. `Aux Proposal Provider` 已统一 mock `AUX_CV/AUX_YOLO` 来源，并完成双来源 L0。

### 证据边界

- 三轮默认 guided 与基线均 3/3 PASS，但 guided 的辅助激活率为 0；21% 节时来自四点稀疏
  航线，不能归因于辅助相机。
- 强制访问两个匿名候选虽然 2/2 交接成功，却使搜索时间和路径显著增加。
- Provider 中 `AUX_YOLO/red_cross` 只由 mock 验证，真实斜视 YOLO 未接入。
- 因此该方向只能判定“几何、候选和交接原理成立”，不能判定“增加第二相机能稳定提速”。

### 冻结的未完成项

- 真实辅助相机 YOLO 和红十字斜视粗发现；
- 单个 RKNN/YOLO runtime 在斜下与下视图像间的阶段切源；
- 真实辅助相机型号、安装、标定、带宽、重量和 OrangePi 调度；
- 五类标准靶与红十字全随机、0/部分/全部辅助可见的多 seed A/B；
- 真实环境蓝色干扰、光照、透视域差和粗地图误差 Gate；

这些项目全部转为“冻结待重新评审”，不再列入当前下一步。

## 4. 单下视主线已具备的业务能力

- 单个下视相机输出六分类和红十字候选；
- 圆环、红十字和 H 使用各自几何证据，不把红十字外围黑环当标准蓝环；
- 非深度相机可使用 CameraInfo、相机外参、飞机位姿和地面平面求交计算粗地图点；
- 多帧连续命中、置信度和类别投票保持物理目标 stable ID；
- 搜索时记录地图候选，按权重排队，高权重目标可中断搜索，投后恢复覆盖索引；
- 投递前用下视相机重新捕获和对准，视觉只生成 `release_evidence`，最终动作由任务许可仲裁；
- 仿真中已完成 12/12 覆盖、五类五 ID、tank/panzer/bridge 三投、零碰撞和降落的成功轮次。

## 5. 回归单下视后的待完成任务

按优先级执行：

1. **P0：全随机五靶单相机闭环。** 4 个标准靶和 1 个红十字全部随机布设，H 固定；真值只
   用于评分。验证覆盖搜索、目标记忆、权重排队、中断/恢复和三次投递。
2. **P0：红十字搜索阶段门控。** 搜索阶段允许 YOLO 或红十字几何单路形成“疑似候选”，
   由任务层抵近；投递前仍要求严格红十字语义/几何复核。视觉组负责候选与证据，航线抵近
   和规划可达性由导航/控制组负责。
3. **P0：单相机地图记忆 Gate。** 在运动相机和随机位置中量化重复 ID、地图误差、年龄和
   错配，确保搜索过程中看见的点能在后续投递时重新找到。
4. **P1：H 视觉降落。** 补真实 H、普通黑圈、残圈负样本，完成 landing 阶段门控与仿真
   落地 Gate。
5. **P1：实拍域差。** 标注圆环实例/中心、红十字和 H，采集同步 CameraInfo/pose，停止用
   自洽关联率代替人工真值指标。
6. **P1：30-seed 与 10 min。** 闭环成立后统计发现率、stable ID、地图误差、候选恢复和
   错误释放；延迟只检查持续积压和陈旧数据，不再卡仿真瞬时 P95。
7. **P1：OrangePi ROS 链。** 使用 FP32 RKNN 跑真实相机输入、CameraInfo/TF、5–10 Hz 和
   10 min 稳定性；PyTorch 仍只用于笔记本 dev/sim。

Fast-Planner 低空下降/返航可达性和北区走廊是联合/导航 Gate。视觉组记录失败阶段，但不以
更换 LIO、重写 planner 或恢复辅助相机来绕过这些问题。
