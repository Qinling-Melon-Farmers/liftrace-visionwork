## 3. 当前竞赛任务执行流程

```text
SITL 自动 OFFBOARD/解锁
  → 飞向起飞点 (0, 0, 2.0)
  → 3D 误差小于 0.30 m 后发布 control_ready
  → 等待随机场、地图、Planner 锚点、Manager 全部 READY
  → /navigation/start_mission 只调用一次
  → 12 点蛇形覆盖搜索，高度 2.40 m
  → 视觉候选连续确认、关联并形成 camera_init 地图坐标
  → red_cross/panzer/bridge 可中断当前搜索航点
  → 飞到动态候选 (target_x, target_y, 1.20 m)
  → 冻结目标上下文并进入圆环或红十字视觉精对准
  → release_guard 检查身份、上下文、时效、位置和控制态
  → 短时 release_permission
  → Servo 安全代理 → raw mock ACK → payload slot commit
  → 恢复到不低于 0.95 m，并继续同一个被中断搜索航点
  → 累计 3 个 committed slot 后停止搜索
  → 执行 8 点已知走廊路线，依次穿过三门
  → 到达 H 上方 0.75 m
  → 新鲜有效 H 连续对齐、渐进下降
  → SITL AUTO.LAND → ON_GROUND → disarm
```

当前候选权重和中断集合：

| --- | ---: | --- |
| red_cross | 10.0 | 是 |

发布返航而不是猜测成功；当前这会使完整竞赛 Gate 失败。

### 4.2 r33 计时口径修正

r33 的 `gate_status.json` 报 `mission_ros_sec=111.404`，实现取的是第一个 LAND decision 的时间，
即“开始/接受 LAND”，不是 `LAND SUCCEEDED`。根据 bag 事件：

- 首个投后路线决策：25.815 s；
- 第 8 点成功：137.159 s；
- LAND started：137.219 s；
- LAND succeeded：165.990 s。

所以真实后段时长是 `165.990 - 25.815 = 140.175 s`。Gate 的通过事实不变，但最终整场计时器在
正式验收前必须改为成功终态。
