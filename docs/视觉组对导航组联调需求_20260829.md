# 视觉组对导航组的当前联调需求

更新时间：2026-08-29

适用分支：`feat/navigation-mission-visual-delivery@d9f0bd92b2ff6f2aa106bec818a84a5d46f45d66`

相关回复：[视觉组对导航组 V-SIM-04 扩展需求的阶段回复](./视觉组对导航组V-SIM-04扩展需求阶段回复_20260829.md)

## 1. 目的与来源冻结

本文基于当前联动分支已经跑出的接口和 Gate 事实，整理视觉组现阶段需要导航组提供的任务层
能力。它不是要求导航组承担视觉召回、地图投影或相机标定，也不是要求视觉组在 adapter 中
复制第二套导航策略。

两个导航来源必须分开记录：

- 正式搜索 manager：`liftrace-controlwork@5144aa8f536bdcd214aea2f39ada558383b3bcb0`，当前联动
  分支保持上游源码逻辑不改；
- 地图实验：`liftrace-controlwork@a68925d15293e5510e2b4351c6b3d9bc5aa136ab`，仅含 6 棵 Oak
  tree 和 3 座 radio tower 场外定位特征，不含 manager、接口或调度更新。

当前正式链中，导航 manager 发布 `/navigation/goal_raw`，adapter 是唯一
`/fastplanner/goal` 和 `/mission/command` 发布者；临时 `coverage_search_manager` 只保留
V-CL-05 回归，不得进入正式 launch。

当前正式数据流为：

```text
/uav_vision/targets
  -> profile_candidate_selector
  -> /mission/profile_selected_target
  -> target_search_manager_py
  -> /navigation/goal_raw
  -> navigation_visual_delivery_adapter
  -> /fastplanner/goal + /mission/command
```

manager 和 adapter 都通过 launch remap 消费 `/mission/profile_selected_target`；视觉原始
`/uav_vision/selected_target` 仍保留用于视觉侧统计和 raw/profile 双层 Gate 审计。

## 2. 当前事实与主责判断

### 已接通的能力

- 视觉已发布 `/uav_vision/targets` 长期候选记忆和 `/uav_vision/selected_target` 当前新鲜
  排序提案；后者要求连续 3 帧、地图/关联有效、无拒绝原因、年龄不超过 0.5 s 和 profile
  准入。
- adapter 已能把导航 raw goal 与仍然新鲜的候选空间匹配，实际发布
  `MissionCommand.APPROACH`，随后进入捕获、对准、安全 mock ACK、恢复和返航链。
- field/anchor/contact/pose/control/map READY 屏障、唯一 goal 发布者和 30 s 预检已经可验证。
- `r2026` 当前只准入 `tent/pillbox/bridge/panzer/red_cross`；tank 资产、权重和 `full` 回归
  保留，但正式 r2026 raw/profile selected 与 accepted 必须为 0。

### 当前不能由视觉接口替代的缺口

上游 manager 在 `SEARCH` 收到第一个合法 `selected_target` 后立即中断，`APPROACH` 期间的新
目标不入持久队列；它调用的 `CandidatePolicy.accept()` 在准入时即把 ID 加入
`_known_target_ids`，但 manager 没有结果输入去移除或重排失败 ID，因此后续抵近/捕获失败
不会重试。当前链没有完整候选生命周期、失败结果、冷却重试或剩余时间调度。

因此，**本轮跨组联调的主要代码改动主责在导航/任务层**：持久队列、接受/结果回流、失败
重试、三投与剩余时间调度，以及高度/轨迹跟踪。视觉组仍主责把当前 13/23 的候选准入效果
提升并补齐性能曲面；这两类缺口不能互相代替。

## 3. 职责边界

| 能力 | 视觉组 | 导航组 | 联合验收 |
| --- | --- | --- | --- |
| 候选观测 | stable ID、类别、地图点、质量、关联、拒绝原因、`last_seen` | 校验任务可达性和当前状态 | 同一 ID 可追踪 |
| 当前排序 | 发布新鲜 `selected_target` 提案 | 决定接受、忽略或延后 | 接受事件不能由 selected 推断 |
| 长期候选 | `/targets` 保留粘性记忆，不伪造新鲜度 | 持久队列、优先级、终态、冷却和重试 | 失败后行为可复现 |
| 搜索与接近 | 提供性能曲面和地图候选 | 航线、航高、航速、planner goal、恢复搜索 | `P_interrupt` 与轨迹关联 |
| 投递结果 | 对准/释放视觉证据 | 任务结果、槽位、重试/终止决策 | 三个不同 ID 按槽位完成 |
| 相机与坐标 | CameraInfo、optical frame；与飞控/结构组联合标定安装外参；TF 失败关闭 | 与定位/飞控共同冻结权威 mission pose/TF，并按合同消费 | 同时间戳、同 frame |
| 安全与时限 | 不发布飞行/机构命令 | 高度、碰撞/边界、10 min 调度、返航/降落 | 600 s 硬 Gate |

## 4. P0：导航侧必须补齐的任务语义

### 4.1 把“立即中断”和“稍后调度”分开

导航 manager 需要接收两个任务输入语义，同时保留一个只读审计输出：

- `/mission/profile_selected_target`：当前正式 launch 中由 selector 从 `/uav_vision/targets`
  产生，只代表此刻新鲜、完整准入且 profile 允许的**立即中断提案**；
- `/uav_vision/selected_target`：视觉原始排序结果，保留作算法统计与绕过 profile 的审计，不得
  在正式 r2026 链中绕过 selector 直接触发任务；
- `/uav_vision/targets`：包含跨航段保留的地图候选，导航可在执行同一 profile 过滤后建立
  **持久任务队列**；若改用过滤后的数组，应先冻结其单一发布者和 schema。

不得通过周期性重发 selected 刷新候选，也不得把长期 `CONFIRMED` 状态当成当前连续帧有效。
导航侧队列至少以 stable ID 为键保存类别、地图点、质量、首次/最后观测、尝试次数、最近结果、
冷却截止和终态；选取时再叠加可达性、距离、规则 profile、剩余时间和已用槽位。

### 4.2 不能再用空间邻近反推接受的 stable ID

当前 `/navigation/goal_raw` 是 `PoseStamped`，不携带 stable ID；adapter 只能在 0.6 m 内用
空间邻近关系绑定候选，并在报告中明确标为 `target_id_binding=spatial_inference`。该方式在
相邻目标、多目标和地图抖动下不能作为正式合同。

建议导航组复用现有 `patrol_control/MissionCommand` 类型增加一个 raw decision 输出，例如
`/navigation/mission_command_raw`：

- `SEARCH/RESUME/RETURN_HOME/LAND` 携带 goal；
- `APPROACH` 必须同时携带 `target_id`、`target_class` 和 goal；
- adapter 继续是唯一 `/fastplanner/goal` 与正式 `/mission/command` 发布者；
- `/navigation/goal_raw` 可在过渡期兼容，但正式多目标 Gate 必须使用显式 ID 绑定。

这只是复用现有消息，不要求新建跨组自定义消息；最终话题名由双方冻结。冻结前不得让 manager
和 adapter 同时发布同一个 planner goal 或正式 mission command。

### 4.3 提供候选接受与任务结果回流

视觉的 `selected_target` 是提案，不是导航接受。导航侧至少需要提供以下有序事件：

```text
candidate_accepted
approach_started
approach_failed / capture_failed / alignment_failed / release_failed
delivery_succeeded
retry_scheduled / retry_exhausted
candidate_skipped
mission_returning / mission_completed
```

每个事件至少包含：

```text
schema_version
event_seq
event
stable_id
class_name
previous_state
state
result
reason
retryable
attempt
source_stamp_ros
receipt_monotonic（仅由同机 recorder 记录，不作跨机时间基准）
profile
```

字段语义应先冻结，传输形式可在现有 `std_msgs/String` JSON 状态与正式消息之间另行选择。当前
`/mission/target_search_status` 由 adapter 单独发布，已经包含 event sequence、前后状态、当前
候选、profile 和 command events；在新的所有权方案冻结前，不得增加第二个同名状态发布者。

`P_interrupt` 的唯一计数口径为：同一 stable ID 已被接受，adapter 实际发生
`SEARCH→APPROACH`，并发布 `MissionCommand.APPROACH`。仅出现 selected 或 raw goal 不计数。

### 4.4 失败、冷却和重试归导航任务层

- 候选不能在“收到即接受”时永久进入 terminal 去重集合；
- `approach_unreachable`、`capture_timeout`、`alignment_timeout`、`release_rejected` 必须区分；
- 可重试失败要有有限次数和冷却，成功/不可重试/次数耗尽才进入终态；
- 同一 ID 重试不得重复占用 payload slot，成功 ACK 后不得重复投递；
- 第三投优先级、停止全覆盖、返航余量和任务超时由导航根据剩余时间调度。

上述持久队列、重试和剩余时间调度不得继续塞进 `navigation_visual_delivery_adapter`。
adapter 当前作为联调执行/安全桥，保留既有起飞屏障、命令转发、抵近后的捕获/对准、安全
mock ACK、恢复、三投、返航/降落、timeout/stall 和联合证据记录职责。

### 4.5 收敛航高、速度与地图 profile

同 seed A/B 已得到：

| profile | 30 s 预检 | 90 s 最大高度 | RMS 高度漂移 | 共同首段耗时 | 结论 |
| --- | --- | ---: | ---: | ---: | --- |
| baseline | PASS | 4.798 m | 1.106 m | 60.01 s | 高度超限，FAIL |
| `a68925d` | PASS | 3.254 m | 0.513 m | 71.67 s | 单轮安全，但比 baseline 慢 19.43% |

比较 Gate 为 FAIL，`promote_candidate=false`。导航组需提供收敛后的航高/速度/路线或规划参数，
同时满足最大高度不超过 4 m、碰撞/越界为 0，并把同进度墙钟退化控制在 10% 内。当前默认保持
baseline 只表示候选未满足推广合同，不表示 baseline 的 90 s 运行安全通过。

若继续使用 `a68925d`，manifest 必须显式声明依赖 6 棵 Oak tree 和 3 座 radio tower 场外高大
特征，并始终保留 `baseline` 回退入口。

## 5. 最小接口合同

### 视觉提供给导航

| 接口 | 语义 | 导航侧要求 |
| --- | --- | --- |
| `/uav_vision/targets` | 粘性地图候选集合 | 以 ID 建队列；重新检查 frame、质量、任务终态，不把重发当新观测 |
| `/uav_vision/selected_target` | 视觉原始当前排序 | 用于视觉统计和 raw/profile 审计；r2026 不得绕过 selector 触发任务 |
| `/mission/profile_selected_target` | 当前 profile 过滤后的新鲜提案 | 正式立即中断输入；接受后必须回流明确事件 |
| `/uav_vision/reset_memory` | 清空视觉任务记忆 | 仅在任务/地图边界调用并记录结果 |
| `/uav_vision/drop_offset`、`drop_ready`、`release_evidence` | 末端视觉观测/证据 | 由任务安全层组合为许可，不能直接驱动执行机构 |

正式候选输入条件维持：`state==CONFIRMED`、当前连续帧不少于 3、`map_valid`、mission frame
匹配、`association_valid`、无拒绝原因、所有数值有限、`0<=age<=0.5 s` 且 profile 允许。

### 导航需要返回

| 输出 | 最小语义 |
| --- | --- |
| 带 ID 的 raw decision | 明确 SEARCH/APPROACH/RESUME 等命令、stable ID、类别和 goal |
| 接受事件 | 说明何时、为何接受哪个视觉提案，不能由视觉反推 |
| 结果事件 | 成功、失败阶段、原因、是否可重试、尝试次数和终态 |
| 队列快照/摘要 | 当前 pending/cooldown/executing/terminal ID 与剩余时间 |
| 导航运行 manifest | manager revision、地图 profile、路线/航高/航速、阈值和模型/seed 身份 |

## 6. 联合 Gate 与进入条件

### 30 s 预检

- 固定 world、非零 seed、`r2026`、模型、CameraInfo/TF 和两个仓 revision；
- 随机真值、footprint、field/anchor/contact、pose、map 和所有必需 publisher 持续有效；
- manager 是唯一 raw decision 发布者，adapter 是唯一 planner goal 发布者；
- profile selector 是唯一 `/mission/profile_selected_target` 发布者；
- 0 碰撞、0 越界、无 readiness dropout；必须生成 `gate_status.json`。

### 90 s A/B

- 同 world、seed、真值、模型、路线和 debug-off；
- 双方都安全，最大高度不超过 4 m，0 碰撞、0 越界、无 pose 长断流；
- 规划失败或高度漂移至少一项改善；同进度墙钟退化不超过 10%；
- 未满足全部条件不得切换默认，也不得进入 600 s Gate。

### 600 s 联合硬 Gate

- 三个不同 stable ID 依次按 payload 槽位 1/2/3 完成 software mock 投递；
- 每个 ID 都能关联 confirm→selected proposal→accepted→actual interrupt→result；
- 三投后返航并落地，0 碰撞、0 越界、0 错误释放，最大高度不超过 4 m；
- r2026 下 tank raw/profile `selected=0`、`accepted=0`；
- manifest、逐事件日志、最终状态、`gate_status.json` 和规定报告齐全。

如果 Gate 暴露队列、重试或时间调度缺口，应保持同 seed FAIL 并回流导航仓，不在 adapter
复制任务策略。当前 A/B 未通过，因此 600 s 暂不启动。

## 7. 希望导航组下一次交付的内容

1. 导航自有 feature 分支与明确 revision；不要只更新地图资产而不说明 manager 是否变化。
2. 持久候选队列、立即中断和延后调度的状态图与参数配置。
3. 带 stable ID 的接受/命令合同，以及结果、失败、冷却、重试和终态事件合同。
4. `selected_target`、重复 ID、乱序、陈旧数据、APPROACH 中新候选、失败重试、三槽和超时的
   确定性单测或 replay 结果。
5. 收敛后的 baseline/候选路线、航高和速度配置，以及同 seed 的 30 s/90 s 结果。
6. 更新 handoff：分别写清 manager 源 revision、地图实验 revision、已通过 Gate、失败证据和
   尚未实现项。

## 8. 本轮不要求导航组做的事

- 不要求导航实现 YOLO、圆环/红十字几何、stable ID、地图投影或新相机内参；
- 不要求删除 tank 资产、权重或 `full` 回归，只要求 r2026 任务准入为 0；
- 不要求在本轮替换 FAST-LIO 或 Fast-Planner；但其高度、可达性和轨迹执行结果仍归导航验收；
- 不要求启动真实 `actuator_pwm`、解锁、实机起飞或真实投递；
- 不接受以视觉放宽新鲜度/地图/关联门槛，或 adapter 跳点来掩盖导航任务层失败。

## 9. 需要双方立即冻结的决定

1. 带 stable ID 的 raw decision 是复用 `MissionCommand`，还是采用另一种已有消息；
2. 导航生命周期事件的发布者、topic 和 schema，确保单一所有权；
3. 已冻结 r2026/tank 口径在导航端的配置与 Gate 实现；
4. 下一轮导航实际工作高度、速度、航带间距和横偏/yaw frame；
5. 达到何种 `P_confirm/P_interrupt`、确认时间和地图误差后，导航才采用对应工作点；
6. baseline 与 `a68925d` 下一轮要调整的参数，以及重新进入 90 s A/B 的判据。

当前接续顺序应是：导航先补结果语义并收敛安全 A/B，视觉并行修复 10 个失败 trial；两侧都
满足各自前置条件后，再做带实际 `P_interrupt` 的 90 s smoke 和 600 s 三投 Gate。
