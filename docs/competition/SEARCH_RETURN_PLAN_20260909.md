“完成所有投放后”是正向前提，文本并非另外写了一句“少一投进走廊罚多少”；因此本方案采用保守且直接符合流程的任务分支，不将其夸大成已确认的额外处罚条款。正常三投完成且状态/时间足够时走廊终点降落；未投完、释放状态不确定或没有走廊时间余量时，走搜索区可达绕障路线回起飞H。不能越隔离墙抄近路，也不能为了进入走廊把未知释放伪装为投递完成。

当前代码实际上已有这种基本分流：`mission_core._return_action()`使用home_xy=(0,0)，常规第三槽完成恢复后才调用_post_delivery_route_action；LAND由bridge读取当前有效里程计位置进行交接。后续重点是完整验收起飞H分支、航向与时间预算，不是仅把一个“home”坐标改成走廊终点。完成安全回收与完整竞赛Gate PASS应分别记录。

## A. 障碍柱与搜索高度

思路可用，而且当前Planner已开启horizontal_avoidance：搜索区内有竖向结构支持的障碍，在规划占据层中从floor_z延伸到virtual_ceil_height。它相当于飞行范围内的“无限高柱”，不是修改真实点云、把树识别成数学无穷大。

当前条件：搜索区X=[−4.8,4.8]、Y=[−0.5,7.6]；障碍起始z=0.18local（0.40m AGL），支持点至少3个、邻域0.15m、竖向跨度至少0.20m；柱底−0.12local（0.10m AGL），顶部取当前规划顶界。普通3D占据仍保留。该实现识别的是受支持的竖向结构，不是专门的树语义分类器。

后续复用这一实现，把树箱的水平占据足迹及位置不确定度统一用于绕行，同时保持原始LIO/FreeDOM地图可读。柱顶延伸至有限飞行顶界即可，避免浮点inf或无谓扩大地图。柱子只限制XY穿越，不应让少量漂移点、树叶噪声永久堵死端点；占据支持、更新/消退与覆盖补扫共同验证。

提高高度要同时满足四项：真实比赛限高与机体上沿余量；明确体现低于障碍顶界的水平绕行过程；像素尺度/模糊/反光仍能支持粗检测；MID360仍能及时看到前方树箱。正装雷达位于机顶，高飞时地面及低处树箱可能更难进入有效视场，不能假设已建地图永不遗漏。

因此不把搜索全程直接改到树冠上方。先以当前1.40m FC AGL水平搜索作为基线；后续研究已确认自由区域内取景高度的适应性变化，接近靶标时的取景与低空绕障分阶段处理。高空规划即便绕过虚拟柱，也必须按真实轨迹判断避障得分；不能用虚拟障碍代替实际规则。

## B. 按相机视场在线调整遍历覆盖

复用Mission Manager维护的搜索计划和Planner执行链，不增加第二个目标发布者。输入是现场统一坐标后的边界/起降点、当前地图、真实机体pose和CameraInfo/安装TF；未知靶位、未知左右门口不能作为任务侧真值输入。

维护“已有效观察、尚未观察、当前不可达/遮挡”的地面覆盖网格。用图像曝光时刻的相机姿态将有效图像区域投到地面，再扣除墙/树遮挡、边缘质量差和图像积压影响。飞机飞过或航点完成，不自动等于下方地面已经观察；投递中断、重新规划和高度改变不能清空已有覆盖记忆。

按当前高度和航向的有效横向视野生成剩余区域航带：`航带间距 ≤ (1−重叠率) × 有效横向视野宽度`。相机是刚性安装，roll/pitch/yaw及16cm偏移一起参与投影；高度增加扩大几何视野，但目标像素变小，有效识别视野未必同比扩大。粗搜索覆盖与完整蓝环精修分开，不能要求搜索的每格都完整装下1m环。

根据当前占据地图选择可达端点、拆分被树箱截断的航带，对暂不可达区域保留补扫记录。高度稳定变化、新障碍阻断或明显覆盖缺口才更新剩余计划；当前安全短段保持连续，保留进度与重规划滞回，避免每帧改航线重新引入路线波动。

目标是三投完成前持续降低全场有效搜索域的未观察面积；三投完成后结束搜索。若时限/电量/不可达条件提前触发返航，报告未覆盖区域，不伪称全场覆盖或强行拖到失去返航余量。评价至少含有效覆盖面积、遗漏靶/重复覆盖、可达端点失败与搜索时间，不只看名义航程。

## C. 分线路的安全返航阈值

当前实际配置为forced_return_at=420s、return_land_reserve=180s、总时限600s、motion_action_timeout=90s、delivery_reserve_per_slot=60s、nominal_speed=0.5m/s、path_factor=1.5、decision_guard=15s。核心默认510s不是当前全场配置值。

现有_delivery_eta()用到home的距离加统一return_land_reserve；不能用一个固定余量同时准确描述“到起飞H”和“廊外下降→入口→两门→终点H”。后续两条路线分别估时，并把当前释放/恢复事务尚需的时间一起计入。

[原始提取结果](return_timing.json)。这说明仅按最后约10秒降落来留余量会严重低估总返航时间。三条成功记录不足以估计可靠P95尾部；失败/超时不能计为0或从统计里消失。起飞H的新返航路线尚无本场景完整记录，不能套用上述终点H耗时。

后续动态预算定义为：

`B_return = B_remaining_path + B_altitude_and_settle + B_H_capture_and_land + B_replan_and_error_margin`

`最晚退出搜索 = T_limit − B_return − B_current_uninterruptible_transaction`

接受一个新投递候选前还需满足：`当前时间 + 候选接近/对准/释放/恢复预算 + 对应返航预算 ≤ T_limit`。路径预算采用当前地图下的实际剩余绕障长度与保守有效速度，不只采用到终点的直线距离。下降、稳定、H重捕获、落地确认、必要重规划都要计入；发现地图不可达或电量条件不满足时提前退出。

起飞H线路的第一版候选预算为150s：沿用单段90s运动预算，再为H取景/下降/落地预留45s、余量15s，因此无进行中投递时的候选退出点为450s；若实际路径/高度/事务预算更大则更早返回。这是待验证的工程初值，不是基于新线路统计得到的最优值，也没有应用到当前代码。当前420/180继续冻结，直到seed11/随机化阶段之后，起飞H线路完成独立实跑再评估是否采用450/150或动态阈值。

穿廊线路保留当前较长余量，基于多轮同一版本、同一路线的分阶段记录更新。样本少时用已观测最大值加工程余量；样本充分且保留独立验证集后，再使用高分位数及其不确定度。不能因成功样本快，就忽略墙距/跟踪失败而延后返航。

验收要分别覆盖：0/1/2投安全回起飞H、三投后正常穿廊、临近阈值且正在对准/释放/恢复、最长可达返航路径、H短时丢失以及预期时限内落地解除武装。起飞H目前贴边，也必须验证低空机架净空和H接近方式。无人机实际安全收尾可持续到比赛计时结束之后，但超时不得记作比赛PASS。
