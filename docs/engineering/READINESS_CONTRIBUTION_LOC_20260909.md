## 1. 已到哪一步

**固定场景的软件闭环已经成立，比赛级实机闭环尚未完成。** R64 seed11在新机架/地图完成37/37 PASS：搜索、三投mock确认、三次恢复、走廊两门、H降落和解除武装。随后十seed原始7/10完整PASS、8/10三投，5/7/8有旧布设压墙，生成器已修但新分布没有重跑；合法seed3仍有近地降落失败。不能把单轮PASS或70%仿真成功率直接当项目完成度。

若用于安排工作，可给**软件功能实现约85–90%，整体比赛交付成熟度约60–70%**的工程粗估。前者反映主要状态链与接口已存在且固定场景闭环；后者还包含规则随机性、板端真实链、机械带载、现场启动与重复可靠性。它们不是统计测量，不是按代码行数推导，也不包含尚未知的队员现场成果。没有充分依据报成95%或承诺几天完成。

## 2. 还剩八个必要工作包

以下是八个可验收交付包，不是八次改代码；每包可能需要多次地面/分级飞行验证。实施优先级仍只在[ROADMAP](../../VISION_2026_ROADMAP.md)维护。

| 1. 固定实机源码、固件和整套参数 | 实机组＋本机软件维护 | 核对R64 PX4重置补丁与实际飞控版本；硬件runtime/control/launch统一；实际高度零点、起降坐标及走廊高度明确 |
| 2. 设备/坐标/启动/接管链 | 实机组 | MID360/飞控/相机输入与16/21cm外参、源时间/TF对齐；真实高度与地面测量一致；赛前调整后缓存刷新、一次启动、RC接管/急停可验证 |
| 3. 板端视觉和整机负载 | 实机组＋视觉 | 真相机/实际曝光与反光；RKNN＋LIO/FreeDOM/Planner同时运行，连续10min无持续积压，关键频率/时延/温度/RSS有记录 |
| 4. 三槽真实执行器 | 机械组＋任务接口维护 | 提供匹配Servo类型的raw服务、槽位映射/脉宽/动作顺序、真实执行结果；带载释放和落点有实测，不能只返回软件成功 |
| 5. 分级实机闭环 | 实机组 | 起飞/悬停/航点→单靶识别和定位→单投与恢复→三投→低廊/降落分项通过；保留原始失败与参数 |
| 6. 两项现有软件鲁棒性问题 | 导航/控制＋视觉 | seed3近地降落根因与修复验证；安全接近点转视觉捕获时保持净空，不追向贴墙原目标 |
| 7. 规则随机性与覆盖 | 导航＋仿真 | 0.80m左左/左右/右左/右右实际点云规划通过；合法随机树箱/靶位下被占据端点可处理，遗漏区有覆盖或补扫依据 |
| 8. 固定最终版重复验收 | 联合 | 修复后合法多seed与实机完整重复；600s任务时限、三投、过门、圈内落地/解除武装、零碰撞记录成立，更新最终包 |

实机组可推进前5项，本机继续按现有授权范围分析第6–8项；没有因此自动授权新仿真或实机动作。辅助相机、远程服务器、追求更优搜索路线属于后续提效，并非完整闭环的必选硬件/架构。当前安全返航按用户要求不启用，不能将尚未启用的提案算成已完成安全能力。

**当前部署前的具体差异**：`competition_hardware.launch`仍选较早的runtime/control组合，搜索1.40是local高度；R64仿真搜索1.18local对应1.40m AGL。不能直接解压默认参数自动飞，也不能只换一个yaml漏掉launch覆盖。飞控补丁需要确认目标板固件适用性；真实MID360与仿真PointCloud2输入类型不得混用。[硬件说明](../HARDWARE.md)、[机载包说明](../../deployment/README_ONBOARD.md)。
