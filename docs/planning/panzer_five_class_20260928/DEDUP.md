# 同位置类别纠正与投递去重：当前行为和需要补上的闭环

日期：2026-09-28。本文描述实码行为与复现，**本次模型训练/接线没有顺带重写任务去重**。

## 不是“只会给同类去重”

正式 target_memory 已按地图邻域关联标准靶，bridge/panzer/pillbox/tent 可属于同一物理 ID；连续合格的新类别可以更新该 ID。圆环几何候选是辅助观测，不等于另一个可投递目标。最近两包中，ID1 就发生过 bridge→panzer。回放工具历史轨迹键使用 class#id，也会把一个 ID 的先后类别都保留显示，不能仅凭画面两行文字判定实时队列有两个物理目标。

## 两个实际缺口

1. **接近后改类，但释放预约仍是旧类。** 队列当前 snapshot 更新成 panzer，reserved_snapshot 仍为 bridge；成功 ACK 按旧预约写入已投 bridge。后续真实 bridge 即使检出，也会被已投类别过滤。两份最近 bag 的类别更正早于 ACK 约30.14/24.60秒，不能归因于“改类太晚来不及”。模型更准确能降低触发频率，不能修复事务语义。
2. **先证实真正 bridge，另一处误标 bridge 的真 panzer 可能失去重访机会。** 高位记忆内部仍留有另一位置，但高质量 bridge 压过低质量同类假设；bridge 已投后，按类别跳过的调度又不再访问弱假设。因此不是坐标一定物理删除，而是调度上遗忘。`dedup_counterexample.json` 用当前 NavigationMemory 和相同类别过滤条件复现了这一点；它是离线状态复现，不是飞行验收。

用户提出的“先访问真桥梁是否会忘掉错标桥梁的装甲车”：**当前确有这种风险**。低位确认一个位置，只应排除该位置的竞争类别，不能顺带判决别处的未复核位置。

## 最小修复设计

- 保留物理位置/局部ID的 `unverified / verified / released / rejected` 状态，与全局已投类别分开。
- 低位同位置通过稳定类别验证后，清除该位置的其他类别假设；别处仍未复核的位置继续保留。
- 三个高权重类别尚有缺口时，优先在有界预算内重访未复核位置，再考虑补搜；禁止一处失败抹掉其余有效线索。
- 释放前比较预约类别和新鲜稳定类别。如果发生实质变化，取消尚未释放的预约并重新确认；已经释放或ACK不确定的槽位继续保留已用/隔离状态，不能借改类重复投递。
- 不把单帧类别跳动当作已确认改类；不把所有近邻坐标强行合并，以免两张近距离真靶被压成一个。

建议补例：真桥梁先投/错桥梁先投两种顺序；同物理ID改类；两处同类弱线索；低位验证与APPROACH交接；ACK延迟时改类；投后重新看到同靶；两个真实相邻靶。通过后再扩大导航逻辑改动，本轮不会用新模型的抽帧结果冒充这些事务测试已经通过。
