# 2025旧链与2026研究链：全阶段速度调查

2026-09-19，只读分析。依据文件与关键行见[SOURCES.md](SOURCES.md)，本批测量见[measurements.json](measurements.json)。

## 1. 先区分四种不同的“速度”

1. **规划速度/加速度上限**：约束搜索、优化和时间重分配，不等于真实飞行速度。
2. **前视/跟随距离**：`target_dist`、`px4_max_distance` 的单位是米。它们控制当前位置前方的设定点距离，不能写成m/s，也不能乘20Hz直接得到飞行速度。
3. **阶段实际速度**：须从位姿时间序列计算，区分水平、竖直、移动样本和含等待的阶段均值。
4. **任务效率**：完整用时包含搜索、加减速、等待、重捕、投递、恢复、过门和降落；失败运行不能以提前终止时间冒充节时。

两代链路主要都把 `PoseStamped` 送给MAVROS。轨迹消息中即使算了速度/加速度，旧patrol订阅位置设定点的主通路并不把这些量作为速度前馈完整送进飞控。提高规划上限是否有收益，还取决于前视距离、位置环、拐弯、垂直运动、PX4限制与识别时延。

## 3. 去年各阶段具体如何控制

| 阶段 | 旧链实际控制方式/配置 | 能确认的速度事实 | 不能误读的地方 |
|---|---|---|---|
| 起飞 | 直接给起飞位置；统一1.0m位置球限幅；patrol发送20Hz | 没有独立的固定起飞m/s命令 | 桌面z=2.0、导入版z=1.1是局部坐标；不能直接套今年ground=-0.22换算 |
| 去预设检测点 | `Run_point`→Fast-Planner→位置设定点；上限3.0/2.0，前视0.4或0.6m | 旧路线主要是已知检测航点间移动 | 不是今年未知靶全覆盖搜索，路径长度与任务语义不等价 |
| 途中红十字中断 | 保存原游标，切Aligning；完成后恢复原航点 | 同样需要中断和恢复；有0.1s清理等待 | 不能把旧语义简化成“不停顿直接投递” |
| 对准 | 直接跟随视觉位置修正；converter默认像素比例0.0015、单次修正上限0.5m；主位置球仍限幅 | 无统一“对准速度=某m/s” | 0.5m是修正量，不是0.5m/s；实际取决于误差、检测更新和位置环 |
| 投递下降 | 桌面converter有5s线性降高；从1.4到0.8的指令斜率示例为0.12m/s，后面代码还切到0.4 | 这是条件满足后目标高度的变化率 | 导入机载版patrol会用独立align_height覆盖z，常见1.2→0.10→1.2，不能把5s参数当所有入口生效的速率 |
| 稳定/释放 | 桌面默认稳定2s；检测计数/15s对准上限；导入链还有4s/45s等状态超时；部分发布循环5×0.1s | 存在有限等待和机构时间成本 | 上限不等于每投固定耗时；计数也不是秒，不可全部累加 |
| 投后恢复 | 桌面回原航点；导入版恢复到约1.2、观测到z≥1.0后继续 | 没有可确认的独立恒定上升速度 | 需要辨别目标高度、阈值及实际飞行高度 |
| 走廊/普通Nothing点 | 沿旧预置航路，未发现独立0.15m走廊速度档；仍用planner上限和全局跟随限制 | 相比今年整段0.15m前视，旧配置较激进 | 地图、机型包络、高度、门位置不同；旧Nothing点还可能有1–2s或10s hover_time |
| H对准/降落 | 桌面 `land_height=0.3` 且H识别默认关；导入版0.2且默认开；部分旧入口 `auto_land=0` 最后发送z=-1 | 未找到可确认的统一降落m/s设置 | 不能把旧负高度目标或缺少到地确认作为今天提速模板；AUTO.LAND实际下降速度还取决于PX4 |

旧`Detect_point`上写着 `hover_time` 不代表代码一定执行该悬停时长；桌面源码在Nothing分支明确处理hover，在Detect分支主要按检测/对准状态推进。调查结论采用代码分支而非把所有yaml数字相加。

### 旧实现为什么“看起来更敢飞”，但不宜恢复

- 旧traj_server遍历整条曲线，取距离球内时间最大的点；没有可用点时选终点。这可能跳过回环的中间路段，不能把这种缩短当合理优化。
- 旧FSM按经过时间推进/宣布轨迹到尾，重规划还把起始速度归一为0.1m/s；当前按实际投影进度推进、尽量保留安全曲线。后者增加了“不能假装已经飞到”的约束，但缺少独立活性兜底。
- 因此保留今年的到点事实、轨迹分支连续性与事务约束，再修无进展恢复；不恢复“时间到了就算完成”或“找不到就直跳终点”。

### 参数核查发现的误读风险

- `fast_comparison.launch`设置manager/search/optimization为1.2m/s；启动dump另留`bspline/limit_vel=1.0`。活动kinodynamic代码在planner_manager.cpp通过 `setPhysicalLimits(pp_.max_vel_,pp_.max_acc_)` 做统一时间缩放，**不能仅凭这个旧bspline参数断言当前硬限就是1.0m/s**。后续观测应记录实际生效上限和重定时比率。
- MissionConfig的 `nominal_speed=0.5` 是任务成本/预算参数，不是飞控巡航命令；把它调大不会直接飞快，还可能乐观低估返航成本。
- 0.15m跟随档与0.45m投影误差重规划阈值并不协调；在这个活性问题未修前，改某一个“速度数字”可能只是改变触发概率。
- 当前保存的PX4 readback以EKF配置为主，没有足够MPC限速/位置环数据支撑反推每阶段真实速度。不能假定源码默认值等于当轮飞控生效值。

## 5. 速度空间排序与可证伪实验

| 优先 | 优化点 | 可尝试方向（设计，未实施） | 不退化条件 |
|---|---|---|---|
| 0 | 90s无效等待 | 无进展判别→同目标有界重规划/显式失败 | 不伪造过门或延长任务预算；仍保留真实等待/故障时间 |
| 1 | 走廊宽裕直段 | 修复后将“整段都0.15”细化为入口、直段、门前/门内、出口；先小步标定实际速度 | 以净空/曲率/跟踪误差决定切档；门内不追求上限，参数切换有确认 |
| 2 | 门前后与最后一投转场 | 当前已把降速推迟至第1投后航点完成；继续核查不必要驻留/恢复交接 | 第1点以后先下降再过门的几何条件不取消，不提前算到点 |
| 3 | 远距离REVISIT与末段接近 | 中段快，按墙体/目标误差预算提前制动；先去内侧可见复访区域 | 32/38/40原近墙靶不移动；不能高速直追偏向墙侧的高位线索 |
| 4 | 搜索路线 | 修理理想视场中央窄缝/边缘漏区，减少重复与不必要转弯 | 固定同一场景评估，维持禁越障碍投影；识别/投递价值不下降 |
| 5 | 垂直运动和释放后恢复 | 验证捕获、下降、回升的高度事务与真实净空，减少重复升降 | 不压缩必要新鲜证据、释放互锁、机构ACK和稳定时间 |
| 6 | 更高巡航上限/前馈接口 | 前述稳定后再做独立对照；若换速度前馈需导航/控制联合设计 | 同时验证位置/速度/加速度限制、PX4生效值和板端时延；不混入本次修复 |

标定时用**实际速度**为目标，不把跟随距离命名成速度。每次只变一个阶段；可先检查当前走廊约0.11–0.12m/s的直段是否能达到0.15–0.20m/s，再评估下一档，而不是直接照搬旧3.0m/s。具体跟随距离要由跟踪误差、曲率、制动和前视推进共同标定。

### 收益量级，不是承诺

- 37/39完整任务中高位平面搜索为29.5/31.5s。若只让这一阶段提速20%，理想节时仅约4.9/5.3s，且假定路径、识别与转弯全不受影响。
- 若有10m**已验证宽裕直段**，实际速度从0.12到0.18m/s，纯移动理论节时约27.8s；等待、过门和加减速不在这个公式中，不能按整段112s等比例扣减。
- 清除36的90s停滞不是自动获得一次完赛，也不能把90s全部填为可兑现增益；恢复后的重规划/跟踪仍耗时。但它首先恢复了到达终点的机会。
- 39第二门约40s包含规划失败后恢复，37约15.9s是不同场景；差额不能直接称算法可优化24s。应在**同一scene与相同版本**下重复测量。
