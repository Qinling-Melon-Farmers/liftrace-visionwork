## 2. 正赛任务与专项隔离

```text
硬件与静置定位 -> 坐标一致/地面基准 -> 清初始化旧图并建新图 -> READY
  -> 人工确认后的既定起飞时序 -> 低位入场 -> 高位巡航/粗线索
  -> 低位重访/身份确认 -> 对齐/许可/逐槽实投与恢复
  -> 达到投递任务收尾条件 -> 走廊/门洞 -> H视觉对齐 -> 自主降落/终态
```

- 正赛显式使用完整HighViewFull链，不能用第五组“优先中断→投后回起飞点→30cm悬停”代替。
- 不包含 `deployment/board_trials_4x4`、site测试组脚本作为运行依赖；需复用的通用初始化/许可/记录能力留在正式模块，避免把整套专项runtime复制进正赛又形成第二套权威。
- 现场已验证的静态TF、关闭虚拟顶棚、负载参数、位姿跳变保护保留。场地尺寸、巡航高度、走廊点/门/终点、障碍柱开关均按比赛实际档案明确设置，不直接沿用6m×±1.5m、2m、0.5m/s室内专项值。
- 现有0.25/0.20/0.10m膨胀及机体包络含义一致记录；不为追求速度缩小避障余量。

- 从实际使用的电脑/引脚映射取 `actuator_pwm` 源码、初始化脚本与服务定义，实体复制进本工程；保留原来源说明。内部ROS服务只有一个raw提供者。

- 地面实测三个槽的真实动作、复位、带载释放及失败反馈；用户现场授权后才能执行PWM/释放。服务成功只确认服务层结果，不臆造物理离机反馈。
