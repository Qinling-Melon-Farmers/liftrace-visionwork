## 5. 完整正赛链具备哪些能力、还缺什么接线

当前视觉研究/板端副本的 `uav_vision`、`patrol_control`、主要mission实现已基本同源，已有：五分类RKNN链、高位粗线索/冲突位置支持、低位新鲜重捕、对齐许可与槽位补偿、事务化三投、失败延期/局部复核、下降扫掠评估、规划/轨迹交接、走廊/H策略。不能因此认为旧 `competition_hardware.launch` 已把它们全部启动。

| 集成点 | 现在的缺口 | 候选应具备的结果 |
|---|---|---|
| 任务入口 | 老硬件入口仍起普通navigation manager；仅换YAML不会自动选HighViewFull | 独立正赛入口显式创建完整高位优先runtime，复用成熟硬件适配，只有一个任务权威 |
| 定位→建图启动 | 旧入口直接起FreeDOM，未等现场初始化对齐/清旧图 | 复用近期稳定定位→对齐→新地图→READY时序；保留位姿保护 |
| 相机/地面基准 | 老入口相机旋转、固定ground_z等与现场known_rig不同 | 继承确认过的安装外参、模型metadata；静置未解锁建立FC地面零点，不让每次手填高度 |
| FAST-LIO负载 | 研究线缺板端的可订阅低频地图发布等设置；通用入口参数旧 | 纳入1Hz可视化图按订阅发布、关闭PCD、现场负载参数；视觉链仍用需要的原始频率 |
| 高度 | 老控制/桥接限高2.3/2.5m，不可直接套研究2.6/3m | FC、相机、AGL、规划边界和阶段高度在同一参数源展开；本次2m专项不等于比赛上限 |
| 投递 | 安全代理、槽位、raw服务已存在；硬件源码仍可能跨目录链接 | 独立含服务定义及正确舵机源码；保留真实许可和失败反馈，不把mock当验收 |
| 后段任务 | 部分专项降30cm等人工接管；走廊坐标留空 | 三投后完整走廊/H降落，填实际门洞/地理范围；不绕过未知坐标检查 |
| 速度 | 研究快速分段与0.5m/s专项配置不同；board生成器移除corridor_speed_schedule | 正赛候选明确选档及用途，当前不落实提速；不能声称专项已经按研究最高速度验证 |

完整交付目标是复用这些已验证组件并统一入口，而不是再复制一份状态机。需要新整机同版验收的是“组合后的链路”；既有单元测试、三投成功或历史另一配置PASS都不能替代它。
