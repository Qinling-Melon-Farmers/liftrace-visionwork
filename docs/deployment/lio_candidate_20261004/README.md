# 下一轮板端验证：已完成的LIO修复

来源：视觉仓 `feat/ev-continuity-20261004` 的 `cc46ca00`、`df29c381`，本轮按用户要求拆出可独立使用的FAST-LIO修复，纳入整机、高位研究、板端测试及导航相关feature。**不把EV预测实验一起上线，也不宣称已经消除飞控高度重置。**

## 本次纳入

- 20m局部地图、6m探测距离下，原地图移动步长会跨入反向触发区，静止时反复移动。将步长限制在非触发内部区间；无有效内部区间的非法组合拒绝启动。
- 特征预处理修正未初始化的disB、全盲/短扫描/空扫描及平面判定尾端越界。保留现有特征提取档位与阈值。
- IMU初始化或缺失输入时清空旧去畸变点云，返回处理无效；初始化扫描时间锚点显式设置，禁止旧状态配上新扫描时间发布。
- 雷达时间回退时同时清空点云及时间队列，撤销已取扫描标志；这不是完整滤波器重置恢复。
- 修正里程计协方差的顺序与旋转表达，并在发布前填入本帧值；位置、姿态和源时间戳不改写成当前时间。
- 输出队列默认1，可通过 `publish/output_queue_size` 配置1–100；无人订阅时跳过非必要点云变换。输入订阅队列和完整复位机制暂不重构。
- 匹配缓存按实际点数分配；修复clear后下标写入及固定100000点数组越界。并行选择标志使用独立字节而不是vector<bool>。
- 支持编译期显式 `FAST_LIO_MATCH_THREADS=1/2/3/4`，大于1时要求OpenMP；值0保留原架构默认。下一轮板端明确使用3，不依赖ARM自动判断。
- 增加节点私有 `~realtime` 轻量诊断，记录输出年龄、主线程CPU时间、回调/匹配/地图插入/输出耗时及队列。主线程CPU不包含全部OpenMP线程，不能当总CPU占用。

没有纳入PredictionState、ev_predictor、ev_shadow及其launch，也没有改变MAVROS外部定位接线、300ms输入年龄门槛、位姿跳变保护、PX4参数、航线、投递和相机配置。新性能修复可先发挥作用；EV分支继续研究预测、完整坐标对齐和重置后的控制接续。

以下为下次停机状态部署后的构建步骤，本轮没有远程执行：

```bash
cd /home/orangepi/liftrace_board_trials_20260928
source deployment/site_20260928/environment.sh
cd patrol_uav_ws-patrol_planner

  -DCATKIN_WHITELIST_PACKAGES=fast_lio \
```

检查实际构建cache/flags含 `FAST_LIO_MATCH_THREADS=3`、`MP_EN`、`MP_PROC_NUM=3`，并确认启动路径仍指向0928生成的fastlio_mapping。已有绑定策略可继续使用，不将3线程等同独占3核，也不保证所有负载下必然更快。构建不启动ROS、舵机或飞行。
