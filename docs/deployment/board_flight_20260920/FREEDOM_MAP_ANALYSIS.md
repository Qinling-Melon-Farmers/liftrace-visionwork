# FreeDOM静态点云、SDF占据与实机ABORT复盘

## 结论

本轮可以确认的直接故障仍是：第二段目标`(3.0019, -0.0064, 1.1144)`在Fast-Planner的膨胀地图中被占据，15cm目标邻域内没有替代点，因此没有生成第二条轨迹。现有日志没有保存失败时刻的`/freedom/static_pointcloud`、SDF原始占据和膨胀占据，**不能仅凭事后现象认定FreeDOM产生了幽灵障碍**。

但FreeDOM链路确实是当前最值得优先验证的输入源。它把MID360实测点云长期融合成静态地图，再由Fast-Planner离散、膨胀并生成水平障碍柱。当前配置和实现具有四项会放大实机偶发占据的特征：全局地图不随飞机移动裁剪、静态点需要满足较严格的自由空间证据才能清除、输出点只有“本次发布时刻”而没有每点年龄、10cm地图和后续方形支持/30cm膨胀会把单点或小簇扩大。FreeDOM即使只多保留少量点，也可能在规划层变成整列封锁。

这不是板端独有类别。历史仿真十轮中seed31、36、40也出现“目标点在膨胀地图中占据且邻域无合法点”；其中seed36恢复并完成，seed31停滞，seed40显著拖时。板端真实点云、较粗栅格和固定长段终点使同类问题更容易暴露，但不能再表述为“仿真早已完全没有这种问题”。

## 1. 实际数据链

```text
/cloud_registered_body（FAST-LIO，body帧）
  -> FreeDOM按点云时间查询camera_init <- body变换
  -> scan_removal
  -> raycast / freespace_estimation
  -> map_removal
  -> staticspace_integration
  -> /freedom/static_pointcloud（camera_init帧）
  -> Fast-Planner SDF原始占据
  -> 30cm常规膨胀 + 可选水平障碍柱
  -> 终点合法性、A*和样条碰撞检查
```

FreeDOM的输入和输出坐标处理本身并非只改`frame_id`：节点使用点云原始时间戳查询`map_tf_frame <- sensor_tf_frame`，再融合到地图。当前专项采用单位静态`map -> camera_init`只是任务/MAVROS坐标与LIO地图之间的外层关系；若这两个原点或航向没有真实对齐，规划目标会落到地图中的另一物理位置。该可能性仍需飞前一致性检查，不能由单位TF配置本身证明正确。

## 2. FreeDOM为何可能保留错误或过期点

### 2.1 当前是进程生命周期的全局地图

板端使用`map/enable_local_map=false`。`remove_map_out_of_bound()`不会按飞机当前位置清掉历史区域，因此地图内容在节点重启前持续存在。这个设计适合静态场地，也意味着：启动初期的外点、反射点或坐标尚未稳定时写入的点，只能依赖后续自由空间证据删除。

### 2.2 清除不是“下一帧没看到就删”

当前MID360配置使用10cm子体素、`counts_to_free=6`、`counts_to_revert=20`、26邻域保守聚类。一个位置需被射线反复穿过，且邻域达到自由条件，才会进入增量自由空间并触发`map_removal`。遮挡边缘、桌腿/桌面附近、近地稀疏区和视场死角都可能很久拿不到足够清除证据。

`map_removal`确实存在，不能说FreeDOM“只增不减”。问题在于它的删除证据比单次观测更严格，且依赖射线覆盖；真实室内环境中，少量旧点可能持续存在。

### 2.3 静态积分保留已有更静态的点

`staticspace_integration`会把当前scan中的点写入地图；跳过`CONSERVATIVE_DYNAMIC`的代码目前被注释。若同一子体素已有较低`dynamic_level`的点，新来的更动态点不会直接替换它。旧点仍可经`map_removal`降级/清除，但不会因后续一帧把该处判断得更动态就立即消失。

这有利于稳定静态结构，也会让启动期错误静态点更依赖完整的自由空间清除流程。

### 2.4 发布话题没有每点年龄

`/freedom/static_pointcloud`只发布`dynamic_level == STATIC`的点，并把整帧`header.stamp`写为当前时间。Fast-Planner看到的是一张“刚发布”的地图，无法从消息区分某个点是刚观测还是数分钟前遗留。因此仅检查消息新鲜度不能发现陈旧体素。

## 3. FreeDOM之后还有两级放大

即使FreeDOM只保留了一个小点簇，最终终点占据仍可能由后续两级共同形成：

1. **SDF常规膨胀**：板端每侧30cm的安全膨胀会把家具边缘、墙边点和小簇扩展到航点。
2. **水平障碍柱**：用于禁止从障碍物上方飞过。当前10cm栅格中，名义15cm支持半径经`ceil`后成为±20cm方形，角点离中心约28.3cm；若邻域中高度跨度达到20cm，源点可能被扩成贯穿规划高度的柱。关闭虚拟顶棚不会关闭该柱。

因此“地图中有一个点”和“1.4m巡航层终点被封死”不是同一层事实。必须同时记录FreeDOM原始静态点、SDF原始占据、膨胀占据和柱支持来源，才能确定责任层。

## 4. 与仿真十轮的统一证据

| 场景 | 目标占据/邻域封锁 | 搜索失败 | 结果 | 说明 |
|---|---:|---:|---|---|
| 实机视觉中断第二轮 | 明确1个固定目标反复失败 | 第二段12s内反复 | ABORT | 失败地图未保存，来源层未知 |
| seed31 | 108/86条 | 110次 | FAIL | 走廊目标`(8.35,2.3,0.68)`占据，等待约90s |
| seed36 | 10/8条 | 22次 | PASS | 高位点`(1,3.5,2.38)`占据后恢复 |
| seed40 | 30/24条 | 121次 | FAIL/墙钟截尾 | 目标`(7,-0.1,1.18)`等反复失败并严重拖时 |

这组结果说明两个问题：

- 终点占据不是FreeDOM才会产生；理想仿真地图中的几何、膨胀和航点本身也能触发。
- 当前恢复是否成功具有偶然性。相同故障类别可在一个seed中绕过，在另一个seed中耗尽动作或整场预算，任务层没有稳定、有限、可解释的处置契约。

## 5. 下一次实机前必须补齐的诊断

只在首次出现目标占据或连续规划失败时保存5–10秒窗口，避免全场大bag：

1. `/cloud_registered_body`及其原始时间戳；
2. `/freedom/static_pointcloud`；
3. SDF原始占据、膨胀占据；
4. 水平柱支持点、柱XY和高度跨度；
5. 请求目标、实际替代目标、起点和邻域候选判定；
6. 同时刻`map`、`camera_init`、机体和MAVROS本地位姿关系；
7. FreeDOM节点启动时间、累计scan序号，以及失败体素首次/最近观测序号。

最后一项需要后续代码支持。它比简单把整帧时间写为“现在”更能区分新障碍与残留点。

## 6. 处置顺序

### P0：先阻止相同故障再次静默耗时

- 所有任务阶段统一首轨迹等待上限；不能只保护SEARCH/RESUME而让RETURN_HOME等阶段等待90s。
- 首次失败即输出分层地图快照和规划拒绝原因。
- 搜索/过渡航点支持有限的合法侧移、渐进航点或跳过；门前后、靶心和H等语义强目标必须采用专用恢复，不能任意搬动。

### P1：验证FreeDOM而非直接削弱安全边界

- 用下一轮失败快照离线回放FreeDOM，比较关闭旧点、调整清除计数或启用局部地图后的差异。
- 增加启动稳定窗口：LIO/TF稳定且地图基本建立后再允许任务；窗口前点不进入正式静态地图，或在稳定时重置一次FreeDOM。
- 为静态体素记录首次/最近观测和最近自由穿越，调试输出年龄直方图；正式运行仍可保持轻量。
- 对近地和远距点做传感器质量过滤，参数必须由实录回放决定，不能凭本轮单个终点直接删点。

### P2：修正离散几何的非预期保守量

- 水平柱支持邻域使用真实欧氏米制半径，消除10cm栅格下15cm变成±20cm方形的问题。
- 恢复仿真已用的较高柱候选下限作为待验证方案；低矮障碍仍留在普通3D占据，只避免把近地杂点拉到全高度。
- 维持30cm常规膨胀和禁止越障规则，先用实录点云证明误判减少且真实树/家具仍被封锁。

### P3：形成回归Gate

至少覆盖：空场静置、固定家具、家具移除后的地图消退、重复重启、起点边缘、高位障碍柱、固定终点恰落膨胀边缘。每项都检查原始静态点、最终占据、首轨迹时延和有限恢复次数。未通过这些Gate前，不把FreeDOM参数改动部署到正赛机载分支。

## 7. 当前不建议的操作

- 不直接关闭FreeDOM或水平障碍柱；这会损失真实避障和“不得从障碍物上方飞过”的规则约束。
- 不直接把30cm膨胀缩小；55cm碰撞盒和膨胀已承担实机定位/控制误差预算。
- 不单纯扩大终点换点半径；门、靶心和H会因此失去语义，且大范围候选搜索会隐藏地图问题。
- 不把12s改回90s；它只会让无轨迹状态更久。

本报告只分析已取回日志、现有源码和十轮既有产物，没有修改FreeDOM、规划器、任务逻辑或飞行配置，也没有启动仿真或实机。
