# panzer漏检与H混淆：优化实施计划

2026-09-28补充：[新两轮与最新策略评估](../flight_pair_20260928/LATEST_STRATEGY.md)证明panzer↔bridge高置信度混淆会导致事务错账。优先补释放前类别一致性与物理目标去重，模型数据增加panzer/bridge成对难例；不应仅按光照增强或H负例处理。本条为新建议，尚未实施。

依据：[本轮实飞报告](REPORT.md)、[92帧外观诊断](appearance_metrics.json)、9月26日19:12实拍及既有seed31/38高位研究结果。用户已说明H误判发生于仿真，当前实飞未摆H。

**推荐顺序：保存弱类别位置并有界复看 → 补充panzer/H及复杂照明训练数据 → 轻量质量选帧与条件增强 → 有收益才采用ROI多帧配准。** 不推荐直接全程叠加三帧图像、不推荐仅降低所有门槛。下文为待实施方案；本轮只做离线诊断，没有换模型或改变机上行为。

## 1. 两个问题分开验收

| 问题 | 已知事实 | 不能作出的推断 |
|---|---|---|
| 实飞panzer漏检 | 19:41包仅两次类别，均圆环关联/地图成功；正式记忆只有一次合格观察 | 不能说圆环关联坏了，或舵机拒绝了panzer |
| 仿真H→panzer | 用户确认发生过；历史H附近panzer假设引发提前退出/错误重访 | 本次实飞没有H，不可拿它证明H误报已消失 |
| 视觉外观敏感 | 本次Gamma有益、CLAHE有害；昨晚CLAHE局部有益 | 不可把一种全程增强当成通用解法 |
| 实际任务入口 | 试飞分支只是高位航点上的低空中断链，缺少研究粗线索队列 | 不能把此次“没重访”归因研究队列失败 |

验收同时看：真panzer发现/确认窗口、H假panzer数量、错误提前结束/错误访问、确认到释放时长，以及板端延迟。提高真靶框数量而同时把H错误记得更牢，不算优化成功。

## 2. 优先完成两个已有能力的正确接入

### 2.1 采用匹配的高位记忆—重访链

后续高位实飞用已交付的八组07（只记忆）→02（完整圈重访）→06（TOP3支持提前退出）→08（全任务）递进；保留现场静态TF、建图、速度上限等配置。不要只提高`search/manual_waypoints`的Z就认为已经启用高位策略。

当前研究链的一次≥0.60类别框可生成导航粗线索，并不要求正式三帧confirmed；panzer参与TOP3提前结束仍要求精修支持，低空重访才重新建立正式类别/几何/对准证据。两种门槛必须保持分工。

本包0.7476这一帧具有“值得再看”的信息，但只有在对应高位阶段、实时位姿、源时效、地图/边界准入均成立时才能进入该队列；不能把本包的2m飞行记录直接改写成2.6m策略已通过。重访位置约(4.06,1.25)是本包记录的结果，不应硬编码到正式路线。

### 2.2 复用已有局部重捕预算，增加有效观察机会

本包两次panzer检出分别发生在约0.127、0.062m/s的减速段；前后约0.6–0.74m/s时大多无类别框。建议沿用已有“到达后短驻留＋一次可达换位”，优先将目标保持在图像内部，观察0.5–1.0s；若仍不足，最多一次0.3–0.5m换位，总计不超过现有5s局部预算。

触发条件必须是在线存在panzer粗位置/类别歧义或可用标准靶几何位置，不对整场每个航点无条件停1秒。不能将旧类别+连续圆环直接当成三帧类别确认；追踪、补帧和重复发布都不是新的分类证据。投递所需证据仍来自当前低空新帧。

## 3. 相机和清晰度优先于复杂滤镜

先记录曝光时间、增益、自动曝光状态、图像格式、源帧号及处理耗时。现有bag只有图像/CameraInfo，没有UVC曝光参数，无法把模糊量单独归因曝光。

本包搜索目标local1.8、镜头到地约1.83–1.87m；按fx≈725、速度0.7m/s估算图像平移约270px/s。若要把理想平移拖影控制在2px内，曝光约需≤7ms（约1/150s）。这是基于平面、近垂直观测的估算，未计旋转/振动，不是立即写入相机的已验证参数。缩短曝光会增加噪声，应与增益/现场补光配对比较。

先采集同一靶、相同路径的“现状自动曝光”与“适度限曝光”样本；不自动改变板端摄像头。比较目标中心ROI清晰度、检出窗口和端侧帧率，不单看全图平均亮度。

## 4. 在线多帧处理：建议先做证据积累和选帧

### 4.1 第一档：原图推理＋物理目标级证据累计

- 空间/光流关联同一物理靶，保留短时0.5–1s窗口；按**不同源图像时间戳**累计类别证据。保持现有类冲突、定位epoch、已投目标、TTL逻辑，复用NavigationMemory与正式target_memory，不另起任务FSM。
- 单次类别与持续同位置圆环可维持“待复看位置”，但不能将几何观测当成重复类别确认，更不能刷新旧类别的时间戳。
- 高位位置记忆、提前中断支持、低空正式确认、释放许可四层分别保留。状态报告增加最后独立类别时间/类别计数/几何计数/冲突原因，避免同一ID掩盖稀疏分类。
- 对H等稳定误分类，连续投票本身可能使错误更确信；必须结合下节的H反证，不能只增加多帧票数。

### 4.2 第二档：短缓存质量选帧＋受控增强

本包现有检测输出源年龄P95已约0.421s，离0.5s只剩约79ms名义余量；不同环节耗时分布不能直接相加预测通过率，必须重测完整链。因此先限缓存和排队，再谈滤镜。

缓存最近3张相机图（约67ms跨度），在目标ROI计算亮度分位、过暗/过亮比例、归一清晰度和运动幅度；在原有推理频率内优先推送清晰且新鲜的图像。选择过去帧会增加年龄，所以只允许保留真实源stamp，仍执行现有0.5s源时效/TF等门控。缓存最多3帧，不累积推理队列。

Gamma作为低成本候选，优先只对亮度异常且仍有纹理的输入启用。**本次诊断是BGR统一Gamma0.65；将来改成只处理亮度通道属于另一个需要验证的方案。** 原图支路需可回退；增强结果不应取代相机原片录像或改写CameraInfo/外参。

每次只运行一个推理输入；如需要原图与增强图二选一对照，只在小范围复核时限频执行，不能让全图双推理常开挤占NPU。图像更亮不保证分类更好。[OpenCV文档](https://docs.opencv.org/4.x/d5/daf/tutorial_py_histogram_equalization.html)也说明全局均衡可能破坏局部细节，CLAHE需要限制噪声放大；本包的CLAHE零命中是暂不默认启用它的直接依据。

### 4.3 第三档：仅ROI的三帧配准融合（收益不足则放弃）

本轮全帧ECC版本P50/P95约51/138ms，只有4/92帧达到0.5，≥0.7仅2帧；不能直接上板常开。优先研究128–256px的目标ROI，采用稀疏光流/局部平移或已知相机运动先验，最多三张过去/当前图。OpenCV提供[稀疏LK光流与ECC配准](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)，这些是可复用的基础操作，不代表本项目效果已验证。

配准失败、大姿态变化、过度截断、亮度突变、定位重置时立即回退当前原图；不把错误对齐后的双影送进释放几何链。几何靶心仍在原始当前帧独立计算。若只改善肉眼观感却不改善有效确认窗口，或时延预算不满足，就不采用。

暂定端侧资源目标：额外处理P95≤10ms、最多3帧/2个ROI、额外内存≤20MB、原检测频率下降不超过10%，端到端源年龄不超过现有许可值。**这些是待测准入目标，不是当前板端实测值。** 最好先通过简单选帧和模型微调解决，不为了“多帧”增加无收益复杂度。

## 5. H假阳性：模型负样本与局部结构反证并行

### 5.1 数据层必须补H

现用网络没有H类别；形式上五个正式投递类，H由辅助几何处理。建议先保持小模型五类检测，加入完整H、残缺H、圆圈、文字、地砖反光等**背景负样本**，使网络学会“不输出panzer”；不必马上扩大任务类别集合。

- 仿真：从已有H误报轮提取源图、对应框和位置；补不同高度、姿态、亮度、目标靠边、H与panzer同画面等场景。若旧轮无源图，标为待采集，不从轨迹凭空生成训练标签。本轮不启动新Gazebo。
- 实拍：之后单独拍H与panzer相邻/分离、阴影/反光、旋转及运动样本，当前19:41包不能提供H负例。
- 标注口径保持中心图案框；H作为已检查的负例，不将未标出的真实投递靶误当背景。tank继续退出正式输出，但不能靠删metadata一行改变旧权重类别编号。
- 按日期/场地/飞行批次划分，不能将同一视频相邻帧随机散进训练和测试。本次92帧已用于选方案，作为开发集；另留完全未用于选方法的飞行批次作验收。

### 5.2 搜索阶段对可疑panzer ROI做H结构复核

当前`landing_detector.yaml`默认`process_only_in_landing_mode=true`，所以搜索时即使有H也不提供结构反证。不能仅打开完整landing模式，因为这会改变感知和任务语义。

建议复用现有H笔画/外圈检测函数，增加一个**仅用于分类消歧的按需ROI调用**：当panzer粗框出现且ROI内有圆形轮廓/黑色结构时运行；不发布降落命令，不切换align_mode，不启动第二套控制链。H与panzer同画面时仅作用于同一重叠ROI/物理位置，不能全帧发现H就压掉所有panzer。

| 证据组合 | 建议行为 |
|---|---|
| panzer有支持，H结构证据弱/不完整 | 维持粗线索；必要时低空复核，不直接删除 |
| 同一ROI在多个不同源图稳定满足H笔画/外圈，panzer缺少独立支持 | 不让该假设触发TOP3提前结束，标记语义冲突，安排有界局部复核 |
| 低空确认是H | 只撤销这个位置的panzer假设，继续保留其他位置的panzer |
| H和真实panzer相邻，分别有完整证据 | 分别建模，不使用固定home半径一刀切 |
| 仅有圆环，没有可辨H笔画或类别 | unknown几何位置；不擅自认定H或panzer |

“panzer有圆环”不是排除H的充分条件；H本身也可能有黑圈。颜色/尺寸只能作为支持特征，不能用“必须有蓝色外环”代替类别识别。所有反证和冲突必须记录源图、ROI、分数、撤销理由，防止再次只能看到错误地图点猜原因。

## 6. 模型训练：优先泛化，而非仅降低阈值

现用训练已有HSV亮度增强，但真实移动阴影、反射、纹理方向与运动模糊覆盖有限。先以同规模YOLO11n/640微调五类模型；补panzer旋转、俯视/轻斜视、图案占比、明暗混合与H难负例。保持panzer/pillbox/bridge等相近纹理的均衡，不只堆panzer正例。

按因素做小规模对照：真实难例微调基线→增加旋转/局部阴影/适度运动模糊→可选增强预处理配套训练。HSV与旋转参数含义参考[Ultralytics官方增强说明](https://docs.ultralytics.com/guides/yolo-data-augmentation/)；已有随机亮度增强并不能保证对本包阴影/反光稳健。原图与增强图的训练/推理分布应匹配，不直接将人眼“好看”的处理设为默认。

正式类分数与圆环质量目前耦合为min，后续可考虑让两者各表达自身质量，再独立标定阈值；这需要单独回归，不在模型优化时顺手下调释放许可。第一轮仍保持原释放链，避免无法判断收益来自视觉还是放宽安全条件。

导出RKNN后必须对相同图像比较PT/RKNN的类别、坐标、分数与耗时；验证成功才替换模型。旧权重和metadata继续保留，新增五类权重与metadata作为配套资产，不改旧六类编号。

## 7. 分阶段实施和停止条件

| 阶段 | 实施范围 | 输出/通过条件 |
|---|---|---|
| P0 已完成 | 本包回放、原始链诊断、92图外观试验 | 4份完整视频+11秒对照；两次panzer真实位置，未确认原因明确 |
| P1 数据与观测 | H仿真负例、panzer实拍正例、曝光/性能字段、原图关键帧 | 可按不同飞行/场景划分，错误框可追到原图；无邻帧泄漏 |
| P2 离线原型 | 证据累计/质量选帧/条件Gamma/H-ROI结构判据 | 配对统计真实panzer有效窗口、H假阳性、投递类混淆与处理耗时 |
| P3 模型微调与RKNN | 五类轻量模型、H硬负例、配套导出 | 独立实拍批次收益，仿真H误报不增；PT/RKNN差异可解释 |
| P4 板端影子验证 | 不改变飞行任务，仅录新旧判断；默认功能开关关闭 | 同时任务/建图负载下满足资源预算，没有积压或错误释放路径 |
| P5 渐进试飞 | 07记忆→02完整圈重访→06提前结束→08全流程 | 真panzer可重访确认；H不引发错误提前结束；再比完赛时间 |

P1–P5尚未执行。先锁定数据，再选方法；增强若在H假阳性、明亮场景或其他类别上明显退化，就不部署。多帧融合若不优于简单选帧或超预算，则停止该方向，保留更简单的实现。

最低回归场景：重复/倒序帧、相机停更、目标出画再入画、亮暗突变、H/panzer同图、多个同类目标、同位置类冲突、两假一真位置竞争、定位重置、低位正式确认后反证冲突、已投目标不复活。释放仍必须由当前目标/槽位、新鲜精修和执行反馈闭环决定，历史缓存不生成投递证据。

未来代码落点：视觉仓`uav_vision`维护质量/ROI/H反证及模型接口，`uav_high_view`保持证据分级；导航仓通过既有粗线索/候选接口消费，复用已有局部重捕预算。跨仓接口若增加H冲突字段，先写明兼容契约再同步；不在试飞组`板载代码`中另发展一套不兼容的视觉实现。
