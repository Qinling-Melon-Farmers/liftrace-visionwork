# 投递测高换算复核与观测时间（2026-10-03）

来源是导航 `feat/drop-height-pixel-scale` 的 b9af5d09，以及视觉板端集成 b0235bb7。原方案的 `dx*h/fx`、`dy*h/fy` 使用相机离地高度，保留原相机—机体旋转、航向、槽位补偿与步长；没有改类别、圆环阈值或投递许可。此次仅本地复核和修正，未部署。

发现的问题是缓存像素的时间与查高度的时间可能不一致：memory 对候选重发布时更新 header，而 `center_px` 仍来自 `last_seen` 对应的图像。尤其下降时，拿新时间的高度换算旧像素会产生尺度误差。

修复只作用于 `drop_circle` 和 `drop_cross`：复制输出 DropOffset 的 header，并将 stamp 设为该目标的 `last_seen`；不改候选原对象，不延长观测有效期，H 的现有路径不变。低空连续确认、证据/ready 的生成时间和真实释放允许条件不变。

验证：5 项实际 DropAligner 方法回归通过，覆盖圆环/十字观测时间、十字无地图缓存重发、过期/零时间拒绝、候选对象不变、稳定计数与证据时间、H 兼容。此前对来源换算的复核还包括实际控制编译、11项 DropAction C++ 测试、7项尺度/5项配置回归、27份生成配置差异与4份launch展开。详细中间结果保留在 `logs/deploy_review_20261003/alignment_review*`。

限制：TF 插值返回请求时间本身不证明原始 TF 样本间距满足0.2秒；本轮不把这一既有机制宣称为严格的源样本年龄保证。没有新实飞落点数据，也没有改变飞控的外部定位融合或高度重置机制。
