# 最新高位粗记忆＋低位重访：对此次类别错账的适用性

2026-09-28。依据[两轮实飞报告](REPORT.md)、实际源图、当前研究HEAD e4c2a33（任务/视觉实现包含dd01d8b/c9df53f链）和[当前类的实录快照复核](component_probes.json)。本页为评估和待实施方案，不是实飞/仿真验收。

## 1. 与本次实飞机制的区别

| 层 | 本次实飞 | 当前研究版 |
|---|---|---|
| 高位看见类别 | 正式候选确认后，直接中断并冻结投递类别 | ≥0.60类别框＋新鲜有效投影可记导航粗线索，不生成投递许可 |
| 结束高位 | 普通沿途中断，无完整高位记忆队列 | 三高权重支持齐备且无冲突可提前退出；不齐则走完高位路线，再携部分线索下降 |
| 提前退出支持 | 不适用研究门槛 | 一般粗类需两张独立源图0.1–1s、位置差≤0.5m；**panzer另需精修来源Hint**，仅两粗框不够 |
| 类别冲突 | 视觉可改ID当前类别，但已冻结事务不随之复核 | 高位有限多假设；低位REACQUIRE可用新正式标签改写访问目的，不继承粗类别为投递事实 |
| 低位确认 | 缺测打断正式计数的旧链 | 搜索模式相邻合格帧≤1s可累计；仍需三次正式类别＋几何，不能用圆环补类别次数 |
| 对准/释放 | circle几何可服务bridge/panzer，原事务语义冻结 | 几何与释放互锁保留；**进入投递后语义变更仍存在相同冻结风险** |

参考实现：研究`uav_high_view/navigation_memory.py`、`uav_mission/high_view_full.py`的`ingest_coarse/_interrupt_top/_resolve_low_location`以及`mission_core.py`。高位分级与正式投递是两种不同证据，不可把一条粗线索称为“可以投”。

## 2. 为什么新策略有帮助

本次高位把装甲车判为bridge，在决定投递前先低空重访，有机会看到稳定panzer，改以panzer新事务接近/释放；第二处真bridge仍保留名额。与立即冻结bridge相比，这个时序更适合处理图案随高度/朝向变化的歧义。

`NavigationMemory`保存每类最多两处假设，不用最后一帧覆盖前一帧。仅把两处实录bridge位置喂入当前记忆组件，两轮均标记bridge冲突；加入实录低位panzer确认后，错误位置的bridge可被撤销，另一处真实bridge保留。复核按原时间先错误bridge、再低位panzer、最后真实bridge输入，另有仅两粗位置的独立对照。

**组件复核边界：**输入Hint坐标取自已记录的正式地图点，用于检验现有记忆类的更新语义；没有重跑coarse投影器/Catalog、真实航线、TF等候、规划避障和机构，也未把低位panzer观测伪装成高位观测。假如飞行改成不立即下降，原bag中的低位图像本来就不会在同一时刻产生。故结果证明“有这条纠错路径”，不证明换入口必然成功。

## 3. 仍不能直接保证成功的四处边界

### 3.1 高位误报本身可能很自信

两轮误bridge最高0.849/0.915，并通过圆环几何。只调高confidence、增加连续帧或只要几何精修，都不足以保证语义正确。此前重点关注panzer假阳性，这两轮又证明相反方向“真panzer→bridge”也重要；H→panzer仍单列仿真负例，不能混用本次无H实拍当验证。

### 3.2 低空5秒是上限，不是强制等待到类别稳定

当前局部复核观察上限5s，满1s无正式结果可最多换位一次，约0.5m。若错误bridge先满足正式候选，策略仍可能提前进入投递；5秒不会自动留给后来的panzer纠正。

旧飞行中，真panzer首次合格出现在接近到达后4.08s/0.99s，说明短时近距离观察有信息价值；但它们是在local1.0m接近目标附近取得。研究默认低位AGL1.4m不等同这个视角，且计时零点不一定等于REACQUIRE起点，不能用4.08<5机械宣称预算足够。

### 3.3 APPROACH之后再变类仍可能错账

当前研究`CandidateQueue`和板载源码在本次涉及的ingest/reserve/commit/ranked行为相同。用真实合法快照依次输入：

```text
bridge ID1正式确认 → reserve槽1
panzer ID1新正式确认 → 当前snapshot=panzer，reserved_snapshot仍bridge
commit(bridge)成功 → delivered_classes={'bridge'}
真bridge ID5通过validate_candidate → ranked排除bridge
```

两份bag均复现；对照队列没有错误bridge提交时，真bridge会参与排序。这个探针验证的是任务组件缺口，不代表已回放所有整机互锁；必须结合实飞已经出现“circle证据通过、bridge ACK”的事实评估。`_resolve_low_location`主要作用于REACQUIRE，不能替代已进入DELIVERY后的语义检查。

### 3.4 不能直接把这两份bag当2.6m全链回放

研究高位粗线索还要求SURVEY阶段、新鲜pose、源年龄≤0.5s、frame/TF/地图/边界有效，以及AGL≥max(2.0, high_agl−0.2)。默认2.6m意味着实际AGL至少2.4m；本次local1.8/1.6不是同一高度口径，不能原样喂入后忽略高度拒绝。

高位变高会改变图案像素占比、模糊程度和航线覆盖；当前镜头实测视场也小于早期估计，中央盲区可能仍需补航带/局部复核。两轮路径宽度3m、长度7.2/6m，又不等同板端八组默认4×4；启用新入口必须带现场航线/边界/地面高度/TF配置，不是只改launch名称。

## 4. 建议先补的最小闭环（本轮未实施）

优先级应从“继续降低识别门槛”转向“纠错发生后，让当前事务能正确响应”。建议复用现有目标取消、重捕和承诺流程，不新建第二套FSM。

1. **保存同一物理位置的类别冲突标志。** 高位/接近期间出现bridge↔panzer反转，不因一次高分就把歧义当作已消失；低空要求不同源图像和清晰ROI的稳定一致证据。复核有总时限，不能一直悬停。
2. **释放承诺前核对最新正式语义与冻结事务。** 若同ID/邻近同位置的当前正式类与冻结类不同，暂停该次释放承诺，回现有有界重捕/重新选择入口。只看到circle不应清除已知的语义冲突；类别短暂消失不等于改类，不应因每一帧漏检反复取消。
3. **确认后以新事务接续，别偷偷改旧事务标签。** 不在已发出的release请求上替换class/slot/执行ID；若尚未触发机构，可取消原预留并按纠正类重新建立事务。若执行已触发或ACK不确定，按既有不确定释放处理，不能重新使用该槽。
4. **区分“物理目标已投”与“类别得分标签”。** 成功ACK保持不可撤销的槽消耗记录；错误类别的事后纠正需要显式说明，不能直接`delivered_classes.discard('bridge')`、删除历史ACK或把槽恢复FREE，否则可能对装甲车再次投递。先修释放前语义一致性，再处理历史错账恢复。
5. **补足诊断理由。** 记录active/reserved class、当前正式class、实际物理ID/位置、语义冲突来源stamp、未选候选原因（含class_already_delivered）。这些可以复用现有状态/事件输出，避免今后仅见“候选不足返航”而误以为检测失败。

模型侧将本次两组“高位panzer被报bridge、低位纠正”作为困难对照，和真bridge、H负例、不同阴影/尺度/旋转同时训练。独立飞行批次验收；不能把这两包相邻帧拆成训练/验证后宣称泛化提升。多帧积分若只强化稳定的错误bridge标签可能适得其反，应先按物理位置保留语义竞争与选清晰帧，不直接平均置信度放行。

## 5. 验收建议

- 首要回归：使用本次两个ID1→panzer与ID5真bridge的真实快照，确保释放前反转会阻止旧bridge事务继续承诺，恢复后真实bridge仍可被选择。
- 保留对照：类别始终一致不能新增无意义等待；单帧抖动/类别缺失、重复时间戳、同位置两类并存、两个真实同类靶、已投目标重新出现、ACK延迟/失败/不确定都覆盖。
- 后续现场先用模块07检验只记忆、模块02检验全圈后重访，稳定后再开06提前结束；默认模拟投递。先确认三处物理靶/任务类别/槽位逐一匹配，再比较完整三投时长。
- 实飞验收必须保存参数快照、源码HEAD、模型身份和原图。2.6m现场确认与1.4m复核要分别验证，不能由本次local1.6/1.8＋local1.0两包推断。

**判断：值得切换到研究版记忆重访，但应先补“投递开始后类反转”的小闭环，再以同布设做新旧配对。当前资料不足以保证直接切换就三投成功，也不支持量化预计节时百分比。**
