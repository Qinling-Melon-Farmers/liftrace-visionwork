# 走廊避障航点测试说明

对应启动文件：

```text
patrol_uav_ws-patrol_planner/src/uav_mission/launch/corridor_waypoint_test1.launch
```

本测试只验证“固定航点 + 实时点云建图 + Fast-Planner 航点间避障 + 末点降落（目标功能，见第六节当前限制）”。当前文件没有启动 YOLO/视觉识别、目标识别、投递释放或视觉降落对准流程。

## 一、启动前准备

```bash
source /opt/ros/noetic/setup.bash
source vision_ws/devel/setup.bash
source patrol_uav_ws-patrol_planner/devel/setup.bash --extend
```

如果工作空间尚未构建，先按项目原有流程构建；本测试说明不要求修改其他业务代码。

## 二、启动顺序

### 1. 启动 MAVROS/PX4

```bash
roslaunch mavros px4.launch
rostopic echo /mavros/state
rostopic hz /mavros/local_position/odom
```

确认飞控连接、位姿和里程计正常后再继续。

### 2. 启动 MID360

```bash
roslaunch livox_ros_driver2 msg_MID360.launch
rostopic type /livox/lidar
rostopic hz /livox/lidar
rostopic type /livox/imu
```

应确认激光消息类型与工程现有 FAST-LIO 配置一致。

### 3. 启动走廊避障测试

```bash
roslaunch uav_mission corridor_waypoint_test1.launch
```

该 launch 会启动 FAST-LIO、FreeDOM 点云地图、Fast-Planner、规划桥、航点任务管理器和控制节点。任务管理器使用 `post_delivery` 模式，跳过视觉搜索和投递阶段，但仍等待人工启动。位姿和地图 readiness 满足后，调用：

```bash
rosservice call /navigation/start_mission "{}"
```
急停：rosrun mavros mavsys mode -c AUTO.LAND
记录点云：rosbag record /sdf_map/occupancy_inflate /freedom/static_pointcloud  /planning/bspline /planning_vis/trajectory /fastplanner/goal /mavros/local_position/pose
该服务启动任务状态机，不代替实机解锁及飞行模式切换。

### 4. 启动后检查

```bash
rosnode list
rostopic hz /freedom/static_pointcloud
rostopic hz /mavros/local_position/odom
rostopic echo /navigation/mission_status
rostopic hz /fastplanner/goal
```

检查 TF：

```bash
rosrun tf tf_echo map camera_init
```

测试文件要求 `map -> camera_init` 平移为 `(0, 0, 0)`、旋转为单位四元数 `(0, 0, 0, 1)`。

## 三、如何修改航点

直接编辑远端文件中的这一行：

```xml
<rosparam param="/navigation/mission_manager/mission/post_delivery_route">[[0.0, 0.0, 0.5], [2.0, 0.37, 0.5], [4.0, -0.37, 0.5], [5.0, 0.0, 0.5]]</rosparam>
```

每个航点格式为：

```text
[x, y, z]
```

例如改成三个中间航点：

```xml
<rosparam param="/navigation/mission_manager/mission/post_delivery_route">[[0.0, 0.0, 0.5], [1.0, 0.0, 0.5], [2.0, 0.5, 0.5], [3.0, 0.0, 0.5], [5.0, 0.0, 0.5]]</rosparam>
```

修改规则：

1. 航点必须是 `camera_init` 坐标系下的米制坐标。
2. 第一项通常写成起飞后的第一个点，例如 `[0, 0, 0.5]`；无人机实际从地面起飞到 `z=0.5`。
3. 最后一项必须是降落点，且必须与 `landing_xy` 一致。例如末点为 `[5, 0, 0.5]` 时保持：

   ```xml
   <rosparam param="/navigation/mission_manager/mission/landing_xy">[5.0, 0.0]</rosparam>
   ```

4. 高度 `z` 是 `camera_init` 的局部估计高度，不一定等于离地高度。实机地面高度变化时，应先确认 LIO 原点和地面高度。
5. 修改后必须重新启动 roslaunch；运行中的任务不会自动读取文件变化。
6. 航点之间仍由 Fast-Planner 根据实时点云重规划，航点只是阶段目标，不是强制直线飞行轨迹。

### 修改高度时还要同步修改

- `/waypoints` 中 `Takeoff_point` 的 `z`：控制器起飞高度。
- `post_delivery_route` 中各点的 `z`：航线目标高度。
- `search_altitude`、`mission/approach_altitude` 和 `mission/return_altitude`：本测试目前均为 0.5。
- `external_planner_max_command_z`：目前为 0.65，航点高度不能超出控制器允许范围；文件中的同名设置要保持一致。
- 降落链高度副本（`corridor_waypoint_test.yaml`）：`land_height`（0.03）、`align_height`、`external_landing/capture_height`、`uav_vision/recovery_height`，以及 `corridor/flight_height` 信息性记录；后三者必须等于航线 z，且满足 `capture_height > auto_land_height >= land_height`、`drop_system/height_threshold < recovery_height <= align_height`。
- `corridor_waypoint_test1.launch` 中 `obstacle_test_auto_land` 节点的 `cruise_z` 参数和 `route_revision`（与 yaml 中 `post_delivery_route_revision` 一致）；`landing_xy` 与 yaml 中 `mission/landing_xy` 一致。

## 四、坐标方向注意事项

`camera_init` 是 FAST-LIO 的初始局部世界坐标系。当前测试文件将 `map -> camera_init` 固定为零变换，因此两个坐标系重合，但这不能自动保证 `+X` 是机头正前方、`+Y` 是机体左侧。

如果希望航点按“机头前方为 X、左侧为 Y”解释，启动 FAST-LIO 建图前应将无人机摆正，使机头朝期望的 `camera_init +X`。如果已知初始偏航误差 `psi`，可在人工编辑航点时先做二维旋转：

```text
x_new = cos(psi) * x - sin(psi) * y
y_new = sin(psi) * x + cos(psi) * y
```

不要为此修改 `map -> camera_init` 的单位 TF，除非同时放弃“该 TF 必须为零变换”的测试要求。。
