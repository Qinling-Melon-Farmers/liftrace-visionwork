# 实机导航与避障启动说明

## 启动前准备

```bash
source /opt/ros/noetic/setup.bash
source vision_ws/devel/setup.bash
source patrol_uav_ws-patrol_planner/devel/setup.bash --extend

```

尚未编译时先执行：

```bash
BUILD_JOBS=2 bash top_level_scripts/build_competition.sh
```

## 启动顺序

### 1. MAVROS

```bash
roslaunch mavros px4.launch
rostopic echo /mavros/state
rostopic hz /mavros/local_position/odom
rostopic hz /mavros/imu/data
```

### 2. MID360 驱动

在 Driver2 适配完成前，使用能发布 livox_ros_driver/CustomMsg 的驱动链。启动后检查：

```bash
roslaunch livox_ros_driver2 msg_MID360.launch
rostopic type /livox/lidar
rostopic hz /livox/lidar
rostopic type /livox/imu
```

若类型为 livox_ros_driver2/CustomMsg，当前 FAST-LIO 不能直接订阅，不要继续启动整机导航链。

### 3. 整机应用

competition_hardware.launch 已包含相机启动和 YOLO 实时显示，默认关闭。实机联调可执行：

```bash
roslaunch uav_mission competition_hardware.launch \
  model_path:=/home/orangepi/liftrace_r64_onboard_405bda42/runtime_models/merged_standard_fp32.rknn \
  start_camera:=true \
  video_devices:=/dev/video0 \
  start_yolo_live_view:=true \
  show_yolo_window:=true
```

附加：调试实时位置打印
 cd position_monitor/
 ./position_monitor


参数说明：

- start_camera:=true：由该入口启动相机并发布 /camera/image_raw、/camera/camera_info；不要再启动其他相机节点。
- start_yolo_live_view:=true：启动 YOLO 结果叠加节点，发布 /uav_vision/yolo_debug，不重复运行 RKNN 推理。
- show_yolo_window:=true：本机打开 image_view 窗口；无桌面板端设为 false。


该入口启动 FAST-LIO、FreeDOM、LIO 外部位姿、相机 TF、RKNN 视觉链、patrol_control、任务管理器、Planner Bridge 和释放许可代理；

### 4. 检查与任务启动

```bash
rosnode list
rostopic hz /freedom/static_pointcloud
rostopic hz /mavros/local_position/odom
rostopic hz /camera/image_raw
rostopic hz /uav_vision/detections
rostopic echo /navigation/mission_status
rosservice list | grep mission
```

启用显示时检查：

```bash
rostopic hz /uav_vision/yolo_debug
```

确认任务管理器 ready、定位和地图稳定后执行：

```bash
rosservice call /navigation/start_mission "{}"
```

该服务只启动任务状态机，不代替解锁、起飞和现场安全检查。实机解锁、起飞、舵机动作和带载投递必须按现场流程单独确认。


## 5. 当前实机坐标系、地图与命令行查看

### 5.1 坐标系

`camera_init` 是 FAST-LIO 建图的局部世界原点，`/Odometry`、FreeDOM 地图和规划器地图使用它。`map` 是 MAVROS/PX4 的局部位置坐标系，`/mavros/local_position/pose` 使用它。

### 5.2 任务与规划路径

`competition_hardware.launch` 会启动规划器和任务管理器，但任务管理器默认处于 `IDLE / waiting_for_manual_start`，规划器显示 `wait for goal`。位置和地图 readiness 满足后，按现场流程手动启动：

```bash
rosservice call /navigation/start_mission "{}"
```

该服务只启动任务状态机，不执行自动解锁、起飞或舵机动作。成功启动后任务管理器才会生成目标并通过 `/fastplanner/goal` 进入规划器；规划成功后才有 `/planning_vis/trajectory`。

### 5.3 地图范围与占据体素

当前硬件入口最终规划参数为：SDF 分辨率 `0.05 m`，地图大小 `12 x 22 x 3 m`，原点约 `(-6,-11,-0.2)`，局部更新范围 `(8.5,8.5,4.5) m`，可视化截断高度 `2.49 m`，障碍物膨胀 `0.30 m`，上/下方向分别 `0.10/0.30 m`。规划边界约为 `x[-6,6] y[-11,11] z[-0.2,2.8]`，但当前更新窗口和传感器范围会进一步限制实际有效区域。
