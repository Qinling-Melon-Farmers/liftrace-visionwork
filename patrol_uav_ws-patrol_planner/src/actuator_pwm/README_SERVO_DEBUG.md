# 舵机调试与正式服务互斥

初始化、正式pwm_node1、servo_debug_node.py共用/run/lock/liftrace-servo.lock。初始化脚本持锁至退出；两个服务各自持锁至进程退出。锁文件不得删除、替换或通过其他路径绕过。初始化负责创建锁文件，并设置SUDO_USER的0600权限。先使用原初始化入口，再单独选择正式服务或调试服务。

调试launch仅启动调试节点，不再同时启动正式服务。调试与正式服务必须配套升级；旧版本未使用锁，不能与新版混用。SetServoDuty字段不变，原GUI仍可发送；停止与退出由新版工作台提供。

- /SetServoDuty（patrol_control/SetServoDuty）：slot=1后/2右/3左，500000～2500000ns。普通输出约0.3秒；hold=true保持输出。
- /servo_debug/stop（std_srvs/Trigger）：取消当前及已排队旧请求，关闭三路并读回；保留duty_cycle，后端仍持锁。
- /servo_debug/shutdown（std_srvs/Trigger）：成功停止后异步退出。失败不退出，等待处理/重试。
- /servo_debug/status顺序不变：[后脉宽,后enable,右脉宽,右enable,左脉宽,左enable]。

停止失败会阻止继续发送，必须再次成功停止才能恢复。正常退出和ROS shutdown会尝试关闭三路；SIGKILL、断电等不保证清理。成功响应仅确认电气写入和读回，不能证明机械到位或投递完成。旧GUI的线性角度显示不作为实物标定。

顺序：结束试飞和旧舵机进程 → 原PWM初始化 → 启动调试 → 发送/停止 → 关闭输出并退出调试 → 确认后端退出 → 原正式服务/试飞入口。停止成功后必须退出调试，否则正式服务和初始化会被锁拒绝。
